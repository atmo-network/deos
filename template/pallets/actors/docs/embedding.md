# DEOS Actors Runtime Embedding Guide

> Package-owned contract for reusing `pallet-deos-actors` outside the current DEOS/TMCTOL reference runtime.

**Status**

- **Component**: `pallet-deos-actors` (Rust crate `pallet_deos_actors`)
- **Release line**: `0.7.27`
- **Audience**: external runtime implementers embedding Actors without inheriting DEOS/TMCTOL topology
- **Companions**: [`README.md`](../README.md), [DEOS Actors Specification](./specification.en.md), [DEOS Actors Architecture](./architecture.en.md)
- **Source navigation**: `src/types.rs` is the stable public facade; the architecture map routes Contract, Lifecycle, Scheduler, and Observation type owners; `src/contract.rs` owns semantic classification rather than public type definitions
- **Non-goals**: DEOS governance policy, TMCTOL bucket topology, System Actor catalog standardization, UI product flows

`pallet-deos-actors` is a bounded deterministic actor kernel. A downstream runtime can embed it without inheriting DEOS governance policy, TMCTOL bucket topology, native staking design, or the current System Actor catalog.

The package is fresh-genesis source only. The current baseline defines no migration from an earlier activation, detector, hold, resource, or index layout and must not be used to upgrade a deployed chain; a downstream live lineage owns its own explicit bounded migration before adopting this storage baseline.

Use this guide with the normative [DEOS Actors Specification](./specification.en.md) and shipped [DEOS Actors Architecture](./architecture.en.md). The specification defines portable semantics; this package document defines the host contract; the architecture document maps the reusable package implementation and source ownership.

## Executable Portability Evidence

The repository's [`embedding-runtime`](https://github.com/atmo-network/deos/tree/main/template/pallets/actors/embedding-runtime) package is a minimal external-consumer runtime fixture owned by this pallet boundary. It uses local account and asset types, local Weight bindings, zero genesis System Actors, smaller Service/Deadline bounds, native balance ingress through its own transaction extension, and no DEOS/TMCTOL primitives or topology.

The default profile proves deterministic unsupported optional adapters and all three error policies, including that Permanent adapter failures never create suspended run state. The opt-in `dex-fixture` profile adds User `SwapOut` with an absolute cap and an explicitly Temporary `SwapIn` fixture for Mutable User/System suspended run state. This package is executable portability evidence, not a second product or a normative actor topology.

| Portable capability | Independent evidence |
| --- | --- |
| Actor topology | Zero genesis System actors; local `u64` accounts and `u32` assets |
| Error policy | Abort, continue, and Temporary-only retry paths |
| Actor run state | Mutable User/System suspension persists the open nonce separately from finalized identity, the sole cursor, exact retry eligibility, bounded current-cycle authority, cumulative plus last-Step outcomes, typed suspension, cancel, and pure close |
| Busy ingress | Executive transfer during Running/Suspended changes ordinary custody but creates no latch, fee, deferred Cycle, or second residence |
| Permissions | Immutable rejects `RetryLater { max_attempts }`; User rejects `Mint`; User accepts `SwapOut` |
| Optional capability | Default DEX/staking/donation fail Permanent; DEX fixture supplies only local pairs |
| State and weights | Canonical Trigger runtime state, dedicated refundable Actor-state hold, coordinator cursor, fresh storage version, try-state reconciliation, and nonzero production-derived classes |
| Host-qualified geometry | Every local Step count, current-read amount and predicate surfaces, over-cap admission rejection, and coherent reevaluation at each execution attempt |

Both profiles use the pallet's canonical Service ring and Deadline carrier. The fixture defines no DEOS primitive, TMCTOL helper, System Actor catalog, custom scheduler, or product topology.

## 1. Minimal Host Runtime Obligations

An embedding runtime must provide only the bounded host surface that Actors cannot own itself:

- `AssetOps/current state`: Provide transfer, burn, mint, task-spendable balance, total-owned balance, minimum balance, and exact `preflight_transfer` consequences over local runtime types. `total_balance` includes held, frozen, or reserved ownership for Parked Balance activation; `balance` is the reducible Task amount surface.
- `AssetOps/dependencies`: A completed eligible Contract captures every authored balance anchor after effects and fees commit, registers one collision-free source per watch, then transfers Service authority to Park with a B+1 review deadline. Transfer, mint, and burn routes publish the matching causal revision in the same transaction. The deadline remains mandatory because generic host routes are not claimed event-complete.
- `AssetOps/transfers`: Preflight covers source withdrawal and recipient depositability, preserves retry classification, and must agree with the following transfer under unchanged state. Generic Actors does not promise that a provider-backed or reserved-only zero-free native recipient accepts sub-minimum ingress.
- `AdmissionCertificateAuthority`: Typed fail-closed owner for the current Actor semantics version, composed production Weight identity, body geometry version, configured-bounds commitment, and maximum lifecycle Weight. These runtime-owned facts remain separate from authored semantic Contract identity.
- `StepControlWeight`: Typed authority returning its production Weight identity, maximum Actor-control Weight for an exact Step/context, and valid actual Weight for committed phase/outcome/placement plus independent Task invocation and nonzero Action-fee collection facts. `StepControlExecution::task_effect` identifies invocation, not receipt emission, even for fee-exempt System Actors; `action_fee_collected` must not imply invocation when the Task was NotInvoked. The context distinguishes the inline head from its bounded tail fragment and bounds current predicate geometry. Missing or component-wise greater-than-reserved actual evidence rolls back the complete attempt; a host may conservatively report the admitted maximum until generated branch owners justify reclaim.
- `TaskEffectWeight`: Typed authority returning its production Weight identity, maximum admission Weight, and valid actual Weight for `TaskEffectExecution::{NotInvoked, Invoked}`. Non-invocation returns zero; invocation includes committed or typed-failure work from the canonical generated mechanism owner. Missing or component-wise greater-than-reserved actual evidence rolls back the complete attempt and halts the pass.
- `ObservationProvider`: Current typed scalar state classified as Unavailable, Uninitialized, Fresh, or Stale over the embedding's `ObservationFeedId`; Actors reads it only when an authored observation predicate is evaluated at the actual check or Attempt. Observation publication has no Actors ingress, subscription, or Trigger consequence; the boundary has no concrete Oracle, producer, history, or off-chain dependency.
- `DexOps`: Caller-aware exact-in quotes and capacity-bounded exact-out swaps with deterministic fees, slippage, rounding, and failure behavior. Swap methods receive only `ExecutionContext { actor, actor_type }`; the package derives immutable `ActorType` from stored actor state so an embedding never reconstructs authority from account catalogs or sovereign-address heuristics.
- `LiquidityOps`: Addition, removal, and pair-scoped donation; donation permits reserve strengthening without LP receipt minting when supported by runtime policy.
- `StakingOps`: Generic staking operations plus adapter-visible share balance and optional transferable share-asset mapping for Unstake amount resolution.
- `FundingAuthority`: Default-deny authorization for explicit actor/source pairs when an actor selects `RuntimePolicy`; pallet-owned policies do not delegate.
- `SovereignAccountDeriver`: Deterministic infallible mapping from tagged User/System custody inputs into the host `AccountId`; it must preserve domain separation, reject no admitted identity through panic, and remain stable for custody reattachment.
- `SystemActorContractValidator`: Read-only candidate validation called before an Active System Contract is installed or replaced. Bind `()` when the host defines no closed System activation topology; a host with an explicit catalog may reject undeclared or cyclic runtime-owned edges here. The validator must remain bounded and must not turn rank or edge metadata into Actor Contract identity or User policy.
- `Time`, `CadenceTickMillis`, and `MaxTemporalDelayTicks`: Deterministic consensus milliseconds, the host's nonzero tick quantum, and the shared ten-Julian-year AtTime/Cadenced horizon. The pallet floors readiness, ceils activation anchors, and never derives cadence or its admission bound from local block count. `TargetBlockTime` and `MaxExecutionDelayBlocks` independently bind the ten-Julian-year consensus-block horizon.
- `BlockResourceBudget`: Immutable checked two-dimensional input to Prepass. `from_settled_prefix(maximum_block, maximum_fixed, settled_prefix, remaining_fixed_reserve, control_numerator, control_denominator)` enforces the host's fixed-work ceiling while partitioning only the actual remainder. The host must bound and admit the contributing work before execution; construction-time rejection is not a substitute for service admission. Static construction treats the declared conservative fixed envelope as its ceiling. `begin_prepass(budget)` freezes it in the existing block state; external admission and Drain must use `state.budget()` rather than recomputing from a getter, and caller limits must match that snapshot. Finalization takes no replacement budget and publishes the frozen allocation. The host selects its own Actor Control and Shared Economic ratios, Actor/user base turns, and borrowing policy; generic Actors requires component-wise bounds, class-neutral cyclic Service, maximum reservation, valid-actual settlement, and fail-closed invalid composition. The DEOS equal-thirds policy is reference-runtime composition, not package law.
- `Prepass declaration`: The Mandatory call declares `BlockResourceBudget::maximum_block()` as a conservative upper bound independent of the fixed envelope; execution remains limited by its frozen Control and Actor base domains and reports actual Weight. Hosts must preserve SDK reclaim and exclude the provisional declaration from the settled prefix without discarding base/encoded overhead. Temporary FRAME bookkeeping above the block maximum is not an execution allowance or a settled-prefix observation.
- `Fresh-turn admission`: The configured `BlockResourceBudget` defines minimum Control and Actor/user base turns and belongs in the authority's configured-bounds commitment. A dynamic Prepass budget must preserve all three minima. Active creation, replacement, activation, genesis and try-state reject a Contract whose conservative Service Control exceeds the fresh remainder after mandatory Prepass, two-clock Deadline, bounded parked review and finalization, or whose Task effect exceeds its Actor base turn. The complete encounter includes common inspection, suffix, terminal cleanup and declared optional work; StopCycle uses Control. The combined idle envelope remains an additional check. Complete physical owners and successful funding/collector behavior require independent qualification.
- `Actor Prepass data`: The host supplies `ActorPrepassInherentData` through `provide_actor_prepass_inherent_data` before pallet inherent creation/checking. It may use a node provider or normalize missing data in both BlockBuilder APIs from the immutable version, preserving all explicitly supplied data for validation. The package requires a complete canonical marker at `ACTOR_PREPASS_INHERENT_VERSION`, derives one payload-free Mandatory call, and rejects missing, unsupported, malformed or trailing-byte data. The [reference integration](../../../../docs/actors.integration.en.md#omni-inherent-provider-compatibility) derives only absent markers for standard Omni providers. `PrepassContext` is the host's bounded read-only authority proving required Timestamp and consensus-context inherents already executed; false rejects before resource or scheduler mutation.
- `WeightInfo`: The single runtime-derived numeric authority covers worst-case Task classes, calls, Predicates, fees, ingress, scheduler work, orchestration, Actor run state, finalization, and cleanup in both Weight dimensions. Transfer includes ledger preflight and possible synchronous address-event ingress; Mint includes its own possible ingress. Burn remains independently priced without transfer-ingress proof; adapter-free `StopCycle` prices its explicit stop event.
- `Weight generation`: The `SubstrateWeight` and `()` implementations shipped in `src/weights.rs` are hand-written estimates, not benchmark output, and are not production authority. Run `frame-benchmarking` against the complete host runtime, bind the generated file, and regenerate after any adapter, bound, resource, storage, or hook change.
- `contract`: Exhaustive read-only classification of each Task, Predicate, amount resolution, and error policy. Its task weight owner delegates to `WeightInfo`; it does not replace runtime measurement, capability configuration, or canonical task parameters.
- `PipelineControlWeight`: Bind the prepared `PipelineControlWeightProvider<ActorContractOf<Self>>` declaration; `()` has a deterministic unavailable identity and returns `None`. This Rust host obligation has no live fee or authority consumer yet; §1A owns its staged contract.
- `WeightToFee`: Deterministic conversion from generated family-specific Trigger-occurrence maxima into per-occurrence charges, bounded Cycle-control maxima into later Pipeline Opening charges, and current Task-effect maximum/actual evidence into Action-fee settlement.
- `FeeCollector` + `FeeSink`: One atomic ledger-only runtime boundary that transfers every User fee in full into the mandatory deposit-capable collection destination without invoking Actors ingress, readiness, or process publication. Trigger collector rejection surfaces as `TriggerFeeCollectionFailed`, not underfunding. Certified ingress producers must propagate that failure to their declared atomicity owner rather than commit the movement without its required occurrence consequence.
- `StateHoldCurrency` + `RuntimeHoldReason`: One native fungible hold adapter with the pallet's dedicated `HoldReason::ActorState`, plus nonzero or explicitly policy-zero `ActorStateHoldBase` and `ActorStateHoldPerByte` prices. The host must preserve exact hold/release semantics and enough hold-reason capacity for this independently aggregated owner obligation. User owners back identity, Contract head/body, detector, and the type-derived maximum Run footprint for the complete Active installed lifetime; deactivation releases Active components. This reservation prevents autonomous Opening from requiring new owner hold capacity. System Actor state remains host-capacity-owned.
- `AddressEventIngress`: Typed certified-ingress boundary (`AddressEventIngress::preflight`/`notify`) over the package `AddressEvent` value. Preflight is read-only (lifecycle, source policy, Trigger, fee, and required destination); notify executes exactly once at the host's declared post-movement or transactional-precommit consequence point and rejects through `IngressFailure { error, retry }` with the same closed Temporary/Permanent classification as `TaskFailure`.
- Governance/system origins, a two-dimensional hook Weight meter, runtime-reserved `ActorOnIdleReserve`, owner-slot/Service/Deadline/active/total-identity/sweep bounds, `MaxIdleStarvationBlocks`, and fee constants.
- Creation admission: Explicitly select `GenesisConfig.user_creation_enabled`; its default and missing `UserCreationEnabled` storage deny every new User identity. Existing User control/service and System creation are independent. The public `set_user_creation_enabled` authenticates `GlobalBreakerOrigin` and remains available during freeze. Its scalar Weight declaration is shared with the breaker setter pending physical qualification; hosts must bind their own governance enablement rather than infer it from privileged dispatch. Trusted Rust hooks `apply_user_creation_enabled` and `apply_global_circuit_breaker` perform only their scalar write and typed event; the host caller must authenticate an explicit bounded delegation before invoking them. They do not authenticate an origin or dispatch arbitrary Actor calls. User creation benchmarks opt into admission during setup, and its extra scalar read requires requalified host creation Weights.
- Breaker control: Host origin for the global circuit breaker. A host read model may expose semantic Actor eligibility, but raw pages, generations, cursors, and unbounded history remain private topology or materialized data.
- Canonical Service configuration: bounded `MaxQueueLength`, `MaxQueueEntriesScannedPerBlock`, and `MaxExecutionsPerBlock`. One actor-keyed persistent ring, one authoritative head/cursor, one B+1 eligibility rule, one Deadline carrier, and one Run owner govern every Actor. Actor class, Actor id, execution share, and priority policy never change cyclic service order.
- Under `runtime-benchmarks`, `setup_predicate_assets` supplies distinct assets for general predicate fixtures. Production Current benchmarks require `setup_max_encoded_predicate_assets` and `setup_max_encoded_observation_feeds`: `predicate_set_evaluation` measures asset-heavy mixed totals, `predicate_asset_evaluation` measures pure non-native accounts, and `predicate_observation_heavy_evaluation` measures one fixed asset plus its parameter's number of fresh observations. Host records must have maximum encoded width. Default unsupported errors fail measurement explicitly. Repeated keys or short host records do not establish worst-case ProofSize. Additional host/refusal and cached-result diagnostics qualify the components beyond these mixtures.
- `BenchmarkHelper::liquidity_snapshot` optionally reports total input balances, native free/reserved balances and an existing pool's LP identity/owned balance/ordered reserves. An unsupported observer returns an error; a supported absent pool is `None`. Keep this bounded query outside measured execution and do not treat a mock receipt as host-ledger evidence. The observation itself supplies no price or maximum-width proof. Raw liquidity failure/recovery and late-Deadline/exhaustion profiles require this observer, explicitly Skip unsupported mocks, and verify that failed attempts leave pools/inputs unchanged except the separately collected Action fee.
- `BenchmarkHelper::asset_account_exists` optionally reports read-only ledger-record presence independently of balance. `None` means unsupported topology, not absence. Presence-sensitive fixtures require an explicit `Some(expected)` result and keep queries outside measured execution; this supplies no account-width or proof bound.
- Current-amount benchmarks retain the full configured Step count and verify exact typed ledger or adapter reads at each Attempt. Host fixtures must use maximum encoded non-native accounts and distinct maximum-width staking positions where applicable; unsupported hosts fail explicitly. These component fixtures do not certify whole-Actor resource admission.
- The extra shared-native-hold Close profiles optionally use `BenchmarkHelper::setup_close_currency_peer` to create an unrelated hold through a public host producer before Actor holds. A false result explicitly skips this host-specific domain; producer errors stop it. `assert_close_currency_peer` must verify preservation of the hold and producer authority before and after measured Close. Generic hosts without that producer cannot claim this coverage.

Service admits discovery before touching round authority, then admits Actor loading only for eligible heads. Hosts must price both stages and their settlement bookkeeping, including empty/closed probes; rollback retains performed inspection while restoring the round marker. A discovery budget refusal provides no frontier evidence and cannot alone update starvation telemetry. Successful bounded scan exits and independently known accounting halts retain their separate policies.

Storage rollback does not refund execution resources. A rejected admitted branch retains its Control maximum and any valid effect observation; absent or invalid effect evidence retains the admitted effect maximum. These conservative charges are not measured actuals or collected economic fees. Optional Actor service halts for that block, while ordinary external dispatch and mandatory finalization retain their own authority and remaining capacity.

Service reserves the host's pure-cleanup bound in addition to Step control before any effectful or zero-Step mutation that may close the Actor. Closed attempts and late rejection retain that allowance; successful nonterminal work releases it. Hosts must establish complete generated containment for this composition rather than treating persistent completion as destruction evidence. Cleanup reservation changes block-resource admission, not Action-fee ownership.

The host selects `MaxParkedBalanceWatches` independently of `MaxContractSteps` and `MaxWhitelistSize`. It bounds authored watch rules, episode snapshots, dependency plans and current source/registration storage counts. The reference and external-consumer fixture select one; reducing this bound does not limit sovereign custody or assets used by Steps. Certificates must bind the selected bound, and physical/metadata evidence must use the same configuration.

The host runtime owns those bindings. Actors core owns scheduling, admission, task orchestration, lifecycle, bounded state, fee reservation, amount resolution, task-scoped transactions, and observability events. Dormant identities retain address/ownership lineage and explicit mutability under the total-identity bound but own no contract or scheduler state; an Immutable dormant identity rejects activation and owner close. Runtime-specific custody-only addresses may remain outside generic actor storage when no Actor identity is intended.

Deterministic User and System custody derivation survives host account-provider removal. Reattachment recovers the same address but does not recreate balances removed by external reaping, dust handling, or other host policy.

Policy-bearing effectful Steps use `StepControlWeightProvider::{maximum_behavior_control_weight, actual_behavior_control_weight}` with `BehaviorControlWeightContext`. Both methods default to `None`; implementing the no-policy methods alone admits no policy control. The host production Weight identity must bind every implemented policy-control owner. The price includes ordinary current-Step control plus bounded policy decoding/authentication, reduction, candidate commit and transactional refusal work. Shape bytes are encoded values, not measured trie ProofSize. The same source shape governs stored maxima and actual settlement; complete lifecycle, public-call and production binding coverage remains required before public policy admission.

Zero-Step policies require `maximum_behavior_zero_step_control_weight` and `actual_behavior_zero_step_control_weight` on the same provider; both default to `None`. They price complete inner Opening/completion policy control, excluding the separately admitted residence suffix and lifecycle destructor. The maximum also owns the zero-Step Pipeline tariff; actual evidence must not exceed it. No Task or Action fee exists. Native mock prices are functional model coordinates, not production coefficients.

Prepared policy Close authenticates the stored certificate, full Contract geometry and current host identity instead of asking the public admission constructor to accept an unavailable policy. Terminal simulation without eligible Service, including an independent terminal during financial Deadline waiting, admits and executes that same Close under rollback and reports resource/hold/cleanup refusal rather than fabricated success. A retained Run supplies its prior nonce, cursor and accumulated result without a new Step. These native paths do not enable public policy creation or qualify lifecycle/call costs.

Current-Step service for prepared policy sources additionally authenticates the cold expression and current certificate, requires the selected maximum Step price to fit its stored envelope, and requires the independent Close price. Zero-Step uses its own maximum port. The transient service Contract carries the authenticated expression; absent-policy reconstruction retains the original ports. Native canonical rounds establish functional preparation, not public admission or physical certification.

Policy Service inspection separately requires `maximum_behavior_service_inspection_weight(BehaviorServiceInspectionWeightContext)` on `StepControlWeightProvider`. It defaults to unavailable. Configured encoded/clause/atom ceilings are available before cold reads; canonical Service books their complete additional inspection owner after reading the common head and retains its cost on refusal or rollback. Inner Step/zero-Step prices exclude this outer owner. Pipeline pricing composes it for each bounded Attempt or once for zero-Step; it grants no destruction payment or unbounded pre-Opening inspection credit. Native model and trie-key witnesses are not production calibration.

## 1A. Pipeline Tariff Owner Proposal

Interface preparation is implemented: the crate exports `PipelineControlWeightProvider<Contract>` and requires `Config::PipelineControlWeight`; `()` supplies an unavailable catalog. Live fee compilation, physical authority and public admission are unchanged. Test/benchmark-only candidates are also implemented; live consumer/authority/metadata-error stages below remain a proposal, not qualified pricing. Specification §§4.4/8.4 retain authority; the architecture fee boundary owns the shipped visit compiler and its remaining phase-price limitation.

The recommended boundary is one fee-only, complete-Contract Weight declaration, separate from `StepControlWeightProvider`. It returns no Balance, executes no Actor and chooses no successor. The generic pallet retains validation, the transition graph, error/terminal precedence, bounded reachability and one canonical conversion/collection path. A runtime binds generated numeric models against that kernel truth; it must not implement another Actor state machine. If numeric lowering needs a reusable graph helper, that helper belongs in the pallet before a host binds it.

```rust
pub trait PipelineControlWeightProvider<Contract> {
  fn production_weight_identity() -> [u8; 32];
  fn maximum_pipeline_control_weight(contract: &Contract) -> Option<Weight>;
}

// Current declaration-only Config surface:
type PipelineControlWeight: PipelineControlWeightProvider<ActorContractOf<Self>>;
```

The only query input is the complete validated authored Contract. The host can inspect real header/body/policy shape without another public branch-description ontology or extra generic parameter on the physical Step provider. For the proposed consumer, the query domain is User pricing; System bypasses it and retains zero Actors service fees with unchanged physical admission. Declaration/lowering work needs its own bounded caller Weight; a finite `u32` threshold or global cutoff is not permission to enumerate its values. Actor id, owner account, live balance, current nonce/streak, scheduler position, block remainder and off-chain state are not query inputs.

| Decision | Narrow phase/exit query on Step provider | Complete-Contract fee declaration |
| --- | --- | --- |
| Kernel semantics | Requires a new declared-case vocabulary and a generic path fold; actual execution evidence cannot substitute | Kernel graph remains normative; generated model must conform to it, not replace it |
| Required information | Existing context lacks full header, policy expression and uniform opening-state domain; extending it pressures the physical interface | Borrowed Contract carries authored information; coherence/authority validation stays in the pallet |
| Resource versus fee authority | Risks making conservative actual fallback an economic promise | Physical maxima/actual reclaim stay independent; tariff availability is separately fail-closed |
| Host burden | More branch declarations and invalid-tuple exclusions | One complete bound and identity; generic lowering cannot be duplicated in runtime |
| Selection | Not selected for this interface; remains a possible internal lowering detail if evidence later earns it | Recommended minimum public host contract; no numeric implementation selected |

`Some(weight)` promises a conservative maximum of ordinary chargeable Control for one complete Pipeline under that exact Contract and current tariff identity, over every coherent funded/admitted opening state represented by its bound authority. It covers both Weight dimensions, one Opening, shared/local retry limits, mutually exclusive exits, normal completion and all reachable policy/lifecycle shortening. It must not repeat Opening-only work, add mutually exclusive finalizers, invent Immutable retries or discard authored body/loading obligations. A physical Step maximum repeated over visits is not evidence for this promise. The current weighted visit compiler is a useful count-domain proof aid, not a qualified complete tariff model.

The uniform domain includes all relevant coherent policy episodes, carried global streaks and eligible nonces for the unchanged Contract, not a reset snapshot or whichever state makes the quote cheapest. Querying the same validated bytes with the same identity must be deterministic and storage-read/write-free. Asset/account/header geometry and runtime adapter cases within the admitted domain require explicit host coverage. No general predicate solver or unproved policy/window exclusion is supplied by this proposal; unsupported domains return `None`, rather than silently approximating them with an unqualified source.

The initial consumer domain is User `OnUnfunded::Close`, including zero-Step and nonempty Contracts when the host actually qualifies them. Availability may be a strict deterministic subset described by the catalog identity and its evidence. Policy-bearing availability does not remove any existing policy/Close/inspection gate. AwaitFunding stays outside this first switch: a future extension must separately qualify ordinary control and finite installation/producer/episode work; a price alone cannot admit it.

| Physical work | Proposed sole economic owner |
| --- | --- |
| Explicit installation/reconfiguration, tariff lookup and compilation | Ordinary caller transaction/call Weight; not an added later Pipeline charge |
| Useful readiness and its dedicated initial wait inspection | Trigger and separately qualified financial composition, never this ordinary Pipeline declaration |
| Admitted-turn discovery, common and policy inspection, inner preparation/control | Complete Pipeline declaration, exactly once per selected visit |
| Opening collection/rearm, reduction/monitor, semantic/hold reconciliation, selected residence/cursor transition, normal completion | Complete Pipeline declaration, respecting phase and exit exclusivity |
| Actual-price lookup/containment, Action collection and receipt control | Complete Pipeline declaration; the Action's monetary effect fee remains independent |
| Invoked Task effects | Action owner; no Task-inclusive join may be counted again as Pipeline Control |
| Final state destruction and lifetime resources | Creation-backed cleanup; physically admitted now, never added to Pipeline Weight |
| Optional wait entry/recovery/due/hints | Independently qualified financial owners; absent from the initial Close-only declaration |
| Pre-Opening work and arbitrary uncommitted collector/invariant refusals | Independently bounded caller/producer/refusal backing; never credit from an uncollected future Pipeline fee |

The returned Weight is complete for that ordinary owner: consumers must not add `service_turn_control_weight_upper`, policy inspection, placement or fee suffix again. Zero-Step still needs applicable physical maximum/actual/Close authorities, but its inner maximum is not automatically the new complete tariff. StopCycle stays Control-only and receives no Action fee. Selected terminal control/publication may cost work; final destruction remains excluded. Overlapping proof inputs require a qualified union, not addition of observed proof bytes or subtraction of Task/destruction timings.

This initial shape requires code-static, versioned tariff/converter inputs; a live stateful price schedule is unsupported, not silently read by the callback. A catalog identity must bind the generated tariff model, supported Contract domain, kernel tariff/compiler semantics, and exact `WeightToFee` conversion/rounding/denomination dependencies. The cached head stores Balance, so changing the converter without changing the pricing identity is unsafe even if physical Weight coefficients stay equal. Configured bounds, including the global cutoff, remain committed through admission authority. A type name, function pointer or manually repeated label without dependency evidence is not an identity proof.

The identity is deliberately non-optional. `()` has a deterministic unavailable-catalog identity and always returns `None`; unavailable price is not unknown global physical authority. At the final switch, the existing domain-separated production identity composition includes control, effect and tariff identities plus the tariff semantics tag; the certificate retains its existing fixed-size identity field. `AdmissionCertificateAuthority::current()` must remain obtainable for physically supported System Actors even when User tariffs are unavailable. System skips the price query rather than borrowing a User zero-price fallback.

`None` means unavailable qualification, not zero work, an unreachable branch, alternate admission permission or a request to reuse the physical maximum. Proposed failure is `PipelineTariffUnavailable`; it must remain distinct for no-policy User creation/activation/replacement and must never be erased into an apparently valid zero quote. Unavailability is not insolvency and cannot select apoptosis or an economic failure policy. A `Some` value cannot authorize an otherwise invalid Contract. New error/metadata/client artifacts belong to the consumer-switch cohort, not this proposal.

The final producer uses one Result-bearing admitted-geometry path so tariff failure survives to its caller; it must not duplicate an expensive full compile merely to recover an error dropped by the current Option path. The qualified ordinary Weight is converted once and stored in the existing `PipelineMachineEnvelope` Balance. Opening keeps its O(1) header read and existing atomic collection. Failure restores the owning creation/installation/reconfiguration transaction, including provisional fee/slot/hold/cancellation changes; ordinary outer transaction payment is separate. No remaining budget, per-Actor escrow, rent, new custody mutation or additional scheduler state is introduced.

| --- | --- | --- |

| Coordinated consumer switch | Replace rather than fall back to the old coarse fee path; thread typed errors and rebind certificates/heads, quotes, tests and artifacts | Qualified tariff required for every supported User no-policy/policy lane; optional policy/wait validators remain independently authoritative |

Candidate input reuses kernel canonical-precondition, Trigger/window, Step, retry, Parked Balance, nonce-horizon and expression-syntax checks. It intentionally does not invoke public policy availability, fee solvency, instance/custody/hold admission or account-specific host topology. Window/source validation can read the current block; the declaration itself remains storage-free. The source is neither installed nor authenticated as a live Actor by this diagnostic API.

The candidate converts the complete declared ordinary Weight once, without adding common discovery, policy/placement, Task or destruction costs. System skips catalog, price and conversion callbacks and returns economic zero, not physical zero. Its separate identity commits a candidate-compiler domain tag, class/mutability, full semantic Contract identity, complete current physical authority, applicable catalog identity and selected Weight/Balance. Explicit Provider/Converter injection is for native models; their dependency pairing must be evidenced, not inferred from a Rust type name. This identity never replaces a certificate or cached head.

`WeightToFee` returns Balance infallibly. This candidate performs no aggregate arithmetic and cannot detect an arbitrary converter's internal saturation, truncation or overflow; inventing an overflow branch or rejecting a legitimate maximum is unsound. Exact type-extrema models delimit this boundary only. Reference qualification must prove converter/rounding/denomination behavior over the declared domain independently; max-value acceptance is not physical admission or monetary capacity.

The current independently usable source baseline remains intact through preparation. That is not a claim that its coarse tariff is qualified. No transitional runtime mode, legacy storage alias or reference scalar fallback is proposed. After the switch, missing tariff refuses User installation and reconfiguration; System physical operation remains available. A deployed-lineage retariff or paid-Run migration is outside this fresh-genesis proposal; there is no permission to top up or recharge an already paid Pipeline.

The smallest falsifiers are an unavailable User tariff preserving the owning transaction; System skipping an unavailable User backend; equal bodies with changed converter/model identity invalidating cached authority; exact one-time conversion without adding common/placement costs twice; first Opening versus retry/finalization countermodels; shared cutoff/local-cap and conditional StopCycle cases; zero-Step and policy-terminal owner separation; and independent-consumer compilation without DEOS topology. Native models establish these contracts only. Full input/caller maxima and independent Creation/Trigger/Pipeline backing remain separate release gates.

## 2. Optional Fail-Closed Adapters

`AdmissionCertificateAuthorityProvider::behavior_close_additional_weight` declares complete additional optional-state Close work. Its default `None` forbids prepared policy execution and loaded finalization. Production identity, lifecycle maximum, complete caller containment and independent economic backing must qualify the composition before policy admission; native mocks do not supply those bounds.

Selected terminal cleanup runs from its cleanup-specific full-authority reload/rechecks, or supplied full authority, through complete retirement. The source's earlier construction remains caller work. The table assigns executed work within that span; a complete caller bound is its composition, not another additive component.

| Physical owner | Included occurrence | Excluded occurrence |
| --- | --- | --- |
| Caller preparation/inspection | Initial source authentication, context/hash/price lookup, origin/freeze checks and refusal work outside selected terminal cleanup | The subsequently admitted cleanup span; no borrowed uncollected Pipeline credit |

| Caller/producer composition | The qualified union of its own wrapper/control and every reachable cleanup branch, with transaction and nested consequences | Another additive component, a second charge for the same invocation or a sum of overlapping recorded joins |

Ownership follows each executed occurrence, not a helper name or storage key. `close_control_weight_for_contract` can execute in preparation, nonterminal control and cleanup; each occurrence needs its invoking owner's coverage. Repeated reads/writes remain work even if they add no unique trie key. A Step's terminal result publication remains Step control; `clear_behavior_cycle_for_cancellation(..., closing = true)` belongs to selected cleanup when a live Run is being destroyed. A runtime may bind unit implementations for capabilities it does not expose:

- `AssetOps = ()` rejects Transfer, Burn, and Mint mutation and reports no deposit viability; it never fabricates successful ledger effects.
- `AdmissionCertificateAuthority = ()` returns no current authority, so certificate construction fails closed.
- `StepControlWeight = ()` returns `None` for maximum and actual evidence, so no control envelope is admitted.
- `TaskEffectWeight = ()` returns `None` for maximum and actual evidence, so no Task effect envelope is admitted.
- `ObservationProvider = ()` returns Unavailable for every feed and makes every observation Predicate false without creating a Task failure.
- No DEX means swap tasks fail deterministically through `StepErrorPolicy`.
- No liquidity support means `AddLiquidity`, `RemoveLiquidity`, and `DonateLiquidity` fail through `LiquidityOps`.
- No staking means `Stake` and `Unstake` fail through the staking adapter.
- No runtime-authorized funding pairs means `FundingAuthority = ()`, which safely denies every `RuntimePolicy` provenance.

Unsupported adapters are valid only when user-facing plan builders and runtime docs make the unsupported task surface clear. They must fail deterministically without panic, mutation, loops, or off-chain nondeterminism. Unsupported capability is permanent and must never become retryable suspended run state.

## 3. Ownership Boundary

- `Actors owns`: Actor ids, tagged derivation inputs, owner slots, sovereign reverse ownership, Service/Deadline scheduling, lifecycle transitions, fee reservation, amount resolution, Task admission, Task-scoped atomicity, Step error policy, and bounded events.
- `Runtime owns`: Infallible stable mapping of tagged custody inputs into its concrete `AccountId`, asset ledgers, caller-aware DEX pricing, liquidity pool and donation policy, staking topology/share mapping, atomic fee-collection policy and sink depositability, ingress producers, governance origins, genesis System Actor definitions, any closed System activation manifest and validator, and task weight calibration.
- `UI owns`: Plan authoring affordances, dry-run/simulation UX, unsupported-task hiding, user recovery flows, per-cycle timeline rendering, and warnings around `ContinueNextStep` after mutating tasks.
- `Docs own`: The separation between portable task-language patterns and a concrete runtime's System Actor topology.

Business policy belongs in runtime adapters or genesis actor configuration, not in `pallet_deos_actors` core.

## 4. Actor Permission Model

User actors are signed-owner controlled, fee-bearing, slot-bounded, and cannot mint or individually pause/resume. System actors are governance-created, slotless, fee-exempt, and may be Mutable or Immutable; individual pause/resume requires Mutable System authority. No runtime extrinsic may mutate, pause, trigger, or close a System Immutable actor, but that control guard must not block mandatory internal terminal transitions such as consecutive-failure closure. A later attachment to its vacant custody locator creates a fresh identity rather than reopening the former actor.

`ensure_control_origin` accepts either the signed `owner` or `SystemOrigin` for a System actor, so the `owner` account passed at creation holds the same pause, resume, trigger, contract-update, and close authority as governance over that actor. A host that supplies a signable `owner` therefore delegates governance-equivalent control to that account. Pass an account with no known private key when System control must stay governance-only; the reference runtime uses the `ActorsPalletId` account for exactly this reason.

A downstream runtime decides whether to ship any genesis System actors. Genesis System Actor topology is runtime-owned configuration, not a pallet requirement. `GenesisSystemActors::integrity_test` lets a host bind cross-pallet account, contract, and policy assumptions into the pallet's ordinary runtime-upgrade integrity gate; the default implementation is empty.

## 5. Portable Patterns vs Reference Topology

Reusable Actor Contract patterns include:

- Fee collection and redistribution.
- Scheduled burn or treasury transfer.
- Balance-ingress triggered routing.
- Liquidity provisioning or donation through runtime adapters.
- Ordinary final Actor Contracts whose Steps move actor-owned balances before a later pure close.

The DEOS/TMCTOL catalog of burn actors, fee sink, liquidity actors, buckets, treasuries, BLDR lanes, and native staking LP provisioning is one reference topology. External runtimes should copy only the task-language patterns that match their own economic standard.

## 6. Boundary Contracts

- `Fee admission`: Creation charges process establishment and backs eventual complete state destruction once. Only a useful User Trigger transition from `pending_signal = false` to `true` performs Actor-specific Trigger work and charges its generated family owner; redundant latched activity does neither, including while busy. Later Idle readiness consumption charges complete Pipeline Machine control, excluding final Actor destruction, before Opening and refunds no prior Trigger fee on insufficient admission. Each Action-bearing Task reserves only its current maximum effect and settles valid actual effect Weight on success or typed failure. Non-invoked `FundingUnavailable` charges zero Action fee. Ledger-only collection must not invoke Actors ingress; failure rolls back only its owning transition.
- `Fee conversion`: Actors asks `WeightToFee` for deterministic maximum and actual pricing. Step-control pricing must separate Cycle completion from creation-backed final Actor destruction; physical admission still covers every reachable close branch. Every runtime control/effect provider must return trustworthy component-wise bounded actual evidence; task bounds include adapter and routing work in both Weight dimensions. The host must qualify its fixed Creation Fee against its admitted lifetime-cleanup domain, independently of refundable state holds.
- `Task amount safety`: Transfer, Burn, exact-input swap, liquidity, staking, and donation spend through `PreserveSpend`, leaving the adapter-reported asset minimum and current-attempt Action-fee reservation intact; no future Action fee is held. Transfer cycle-balance forms retain their captured volume and check this live capacity on every Attempt.
- `DEX amount safety`: Exact-in quotes must match caller fees and executable route selection; exact-out receives a policy-derived maximum input that preserves minimum balance and future fee reserve. A host runtime that resolves `RemoveLiquidity` from an LP token must own an O(1) reverse pair index or an equivalently bounded generated lookup outside generic Actors and update it on every supported pool-creation path.
- `Staking amount safety`: Unstake `Fixed` and current-percentage amounts resolve through current adapter share balance; 100% consumes the current available shares without a lifecycle privilege.
- `Ingress triggers`: Every supported producer must route through the typed `AddressEventIngress::preflight`/`notify` boundary and declare one atomic ordering protocol. Prefer read-only preflight, movement, then exactly one notification in one producer transaction. A host may precommit the Actors consequence only when a non-cloneable holding or equivalent ownership constraint prevents post-movement recovery, and then must prove deposit failure restores the exact holding, ledger, events, and Actors state. Recoverable Service/Deadline capacity is Temporary; monotonic exhaustion, corruption, and invariant failure are Permanent. Runtime event scanning, balance-diff discovery, silent failure, and protocol-order misdescription are unsupported.
- `Mandatory phase and hook admission`: The host Executive must order required context inherents before exactly one Actor Prepass and every signed extrinsic after it. Prepass services due Deadlines and the bounded dependency scan, then enters `ExternalPhase`; `on_idle` serves one canonical Service round through `FreshDrain`, and `on_finalize` requires `Finalizable` with zero outstanding reservations. `on_idle` must reserve its generated fixed base before storage access. `ActorOnIdleReserve` must equal genuinely reserved gross headroom and Actors meters against the component-wise minimum of that reserve and actual remaining Weight. Opening plans and bounded `RetryLater` suffixes plus measured pure cleanup must fit after `scheduler_admission_overhead` in both Weight dimensions. Temporal and explicit repair units consume only available headroom and may defer actor execution, so exact actor-local markers and cross-block convergence form part of the embedding contract.
- `Starvation observability`: `IdleStarvationState` is `Healthy`, `Starving { consecutive_blocks }`, or `Alerted { consecutive_blocks }`. Each starved actor-service pass increments the stored count, threshold detection and alerted recovery emit once, and breaker periods freeze the state because no actor-service pass occurs.
- `Actor run state`: Mutation adapters return explicit `TaskFailure { error, retry }`; unknown failures and unsupported unit adapters are Permanent. Only Mutable actors admit `RetryLater { max_attempts: 2..=MaxRetryAttempts }`; the protocol-fixed host constant is 10. A suspended run stores its open `cycle_nonce` while identity retains the latest terminated nonce, the sole current cursor, exact `eligible_at`, bounded current-cycle authority, cumulative outcomes, exact last-Step outcome, and typed suspension. Retry rereads current predicates and amounts. Runtimes bind generated suspension, retry, completion, cancellation, and suffix-admission classes without adding another scheduler or off-chain keeper dependency.
- `Task weight class`: The runtime must classify every task with a deterministic upper bound. Admission may be conservative; it must not underprice execution.
- `Core task admission`: Extend the portable `Task` enum only for a reusable economic primitive that existing composition plus an adapter cannot express without violating atomicity or custody. The change must ship bounded typed parameters, amount/funding/donation semantics, adapter ownership, events/errors/rollback behavior, generated two-dimensional weights, production-budget evidence, semantic tests, and an explicit SCALE/schema-version decision together; runtime topology and product policy stay in adapters and actor graphs.
- `Compatibility/versioning`: `0.7.x` is a fresh-genesis pre-launch line. The first launched downstream compatibility epoch, not an unrelated package-major declaration, begins append-only public enum discriminants and dispatch indices for that chain. Later encoded argument or storage-layout changes require the owning compatibility/migration contract, while additive host adapters and weight recalibration follow package/runtime version policy. A Cargo version never substitutes for pallet `StorageVersion`, runtime `spec_version`, or a bounded live-chain migration.
- `Read model`: Known actor state, owner-slot recovery, scheduler state, current `IdleStarvationState`, and bounded events are canonical on-chain surfaces. Historical starvation duration, fleet dashboards, long timelines, rankings, and analytics are indexed/materialized views reconstructed from detection/recovery events.

## 7. Task-Scoped Atomicity Contract

Actors guarantees Task-scoped atomicity, not whole-contract atomicity. A failed executable Task rolls back all Task-local storage effects and its success event. Earlier successful Steps in the same Actor Contract remain committed. After rollback, `StepErrorPolicy` decides whether the cycle aborts or continues.

| Surface | Actors guarantee | Adapter/runtime obligation |
| --- | --- | --- |
| `Transfer` | Transfer task runs in the task transaction; failed transfer emits failure/summary only | Asset adapter must not preserve partial debit/credit on failure |
| `Swap` | Swap task rolls back if adapter returns error after intermediate mutation | DEX adapter must keep quote, debit, credit, fee, and pool mutation atomic or rely on the Actors transaction |
| `AddLiquidity` | LP success event persists only when the whole task succeeds | DEX adapter must not leave one reserve, LP mint, or debit committed after a late error |
| `Stake` | Stake success event persists only when adapter succeeds | Staking adapter must not leave partial receipt mint, pool share update, or source debit after failure |
| `Unstake` | Unstake success event persists only when adapter succeeds | Staking adapter must not burn shares without returning underlying value on failure |
| `DonateLiquidity` | Donation success event records returned amounts only on success | Donation adapter owns pair balancing and must roll back partial donation/burn/reserve mutation on failure |
| Pure close | No task executes; sovereign balances remain untouched | Runtime must bind generated cleanup weight and preserve actor-owned accounts |
| `ContinueNextStep` | Failed task rolls back, emits `StepFailed`, then later steps may execute | Plan authors should add balance guards after mutating tasks |
| `AbortCycle` | Failed task rolls back, emits `StepFailed`, aborts cycle, and may increment failure count | Adapter rollback must complete before abort handling |
| Earlier successful step | Remains committed after a later task fails | Whole-plan compensation is outside Actors core |
| Task-local rollback | Reverts task storage effects and success event | Multi-step adapter mutations must be transaction-safe |
| Event visibility | Success event is not emitted or is rolled back with failed task; failure/summary events remain observable | Adapters should not emit misleading durable success events outside the transaction boundary |

Pure close has no task-scoped atomicity case: it prechecks fallible invariants, then deletes only actor-owned state and indexes without fees or balance movement.

## 8. Package Portability and External Runtime Tests

An independent consumer should run native `cargo check --no-default-features` and direct `cargo check --target wasm32v1-none --no-default-features` against the packaged crate. The direct target build traverses the upstream `secp256k1-sys` C build and therefore requires a WebAssembly-capable C compiler such as `clang` or Zig configured for `wasm32-freestanding`; ordinary host GCC is not equivalent because it rejects WebAssembly target options including `-mmutable-globals`. A missing target compiler is an environment failure, not successful no-std evidence, and native checking must be reported separately rather than substituted for it.

A runtime embedding Actors should add local tests for any adapter that mutates more than one storage item:

- Late failure after a partial transfer, burn, pool update, receipt mint, share burn, or donation mutation rolls back task-local state.
- `ContinueNextStep` after a failed mutating task preserves earlier successful steps and executes later eligible steps.
- `AbortCycle` after a failed mutating task rolls back the failed task and aborts without whole-plan rollback.
- Explicit, automatic, dormant, and sweep close preserve sovereign balances, execute no task, and emit `ActorClosed` exactly once.
- Unsupported no-op adapters fail deterministically without panics or hidden state mutation.
- Adapter-level success events do not survive a failed task unless they are explicitly outside the Actors transaction boundary and documented as such.
- Fee collection failure rolls back the payer debit and leaves Fee Sink unchanged.
- Certified ingress destination or collector failure rolls back signed, internal-protocol, and XCM value movement according to the producer's declared atomicity protocol; expired Actors may receive ordinary balance without readiness.
- Exact-out never debits above the Actors-provided capacity, and Unstake dynamic modes resolve against shares rather than the base asset.
- Healthy empty `on_idle` leaves no starvation-state key or recovery event; first starvation, one-time alert, prolonged alert, breaker clearing, and one-time recovery match the transition contract.
- Mutable User and System plans suspend only on explicitly Temporary failures or `FundingUnavailable` under `RetryLater { max_attempts }`; retry starts at the same cursor without prefix replay and uses one nonce across attempts.
- Permanent and unsupported-adapter failures create no run state; Immutable admission rejects bounded `RetryLater`; User `SwapOut` requires explicit `InputLimit::LiveQuote` or `InputLimit::Absolute(nonzero)` intent, always enforced with current preservable capacity; liquidity addition/removal require fixed non-zero output minima at every adapter boundary; System-only `Mint` remains unchanged.
- Direct ingress during Running or Suspended changes sovereign custody normally but creates no readiness latch, fee, causal history, or deferred Cycle. A later retry observes current Available balance.
- Saturated mixed-class load preserves cyclic Service encounter order under one head, blocks followers behind an unadmitted head, retains one generation-bound residence per process, and never executes one Actor twice in a block.
- Explicit cancellation, Contract replacement, deactivation, terminal transition, and pure close delete Run state without compensation, prefix rollback, or sovereign-balance movement. A retained Active Actor's cancellation releases its exact Service or Deadline residence before any later useful readiness can publish a new Cycle.

## 9. Non-Goals

Embedding Actors does not require and must not imply:

- Arbitrary user code execution.
- Unbounded task graphs or dynamic smart-contract-like behavior.
- DEOS/TMCTOL System Actor topology.
- DEOS governance or native staking policy.
- Indexer-backed UX as a consensus dependency.
- Off-chain keepers as a correctness requirement.
