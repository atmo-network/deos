# AA-Актор

## Кратко

`DEOS Actors` — ограниченная система акторов среды исполнения. `AA-Актор` — один ограниченный исполнитель внутри этой системы.

Системный уровень описан на странице [Система Actors](actor-system.ru.md). Здесь рассматривается отдельный актор.

## Контракт актора

Удобная модель:

```text
один самостоятельный аккаунт + один способ запуска + один ограниченный `Actor Contract`
```

У актора есть собственный аккаунт, расписание или условие запуска, `Actor Contract`, правила жизненного цикла и порядок обработки сбоев. Вместо распределения повторяющейся экономической логики по специализированным модулям DEOS выражает ограниченное поведение типизированными шагами с явными пределами среды исполнения.

Устойчивый контракт закрепляет:

- Детерминированное поведение при одинаковых состоянии и контексте блока;
- Ограниченный объём работы;
- Статические упорядоченные шаги без памяти процесса, которую могли бы изменять задачи;
- Разреженное состояние прогресса во владении планировщика только на время приостановки изменяемого актора;
- Предсказуемые последствия сбоев;
- Удаление на месте без автоматического распределения возвратов.

Акторы — инфраструктура среды исполнения, а не произвольные сценарии.

Изменяемый актор может назначить `RetryLater` шагу, адаптер которого способен сообщить о временном сбое. Тогда Actors хранит только указатель нерешённого шага и ограниченное состояние попыток. Успешные предыдущие шаги сохраняются, но `Actor Contract` не превращается в изменяемый код. Постоянный сбой завершает цикл; отмена удаляет прогресс без компенсации уже зафиксированных эффектов. Неизменяемым акторам это правило недоступно.

## Классы и применение

Спецификация различает два основных класса:

- `User Actors` — пользовательские акторы с пользовательской моделью комиссий и правилами ячеек владельца;
- `System Actors` — создаваемые управлением системные акторы для автоматизации протокола.

В текущей эталонной линии акторы обеспечивают ликвидность, выполняют сжигание и обратный выкуп, распределяют казначейские потоки, удерживают или разворачивают корзины и исполняют пользовательские ограниченные цепочки задач. Большая часть исполнения во владении протокола реализована как System Actor.

## Условия запуска и формы `Actor Contract`

Акторы запускаются по расписанию, вручную или по событию поступления средств на адрес. Последний вариант составляет основу координации через токены: актив, поступивший на аккаунт актора, одновременно может служить сигналом пробуждения.

Типичные формы `Actor Contract`:

- Сжигание по таймеру: обменять собранные комиссии на Native, затем сжечь его;
- Ликвидность по поступлению баланса: принять внешний залог, обменять его часть и добавить ликвидность;
- Узел графа: получить LP-токен от другого актора, вывести ликвидность и распределить активы по казначейским аккаунтам.

Во всех случаях действуют общие правила Actors: детерминированное планирование, периоды ожидания, допуск по комиссии, жизненный цикл и ограниченное исполнение.

## Зачем нужны акторы

Акторы превращают экономическую координацию в явное поведение среды исполнения. Они связывают эмиссию, маршрутизацию, корзины, казначейские операции и действия под управлением протокола, не превращая каждый повторяющийся процесс в отдельный модуль.

Они также позволяют строить графы: исходящий баланс одного актора может стать сигналом запуска другого. Поэтому крупный протокольный процесс складывается из малых ограниченных частей и остаётся доступным для проверки как типизированная автоматизация.
