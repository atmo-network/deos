# Слой скриптов

## Кратко

Каталог `/scripts` содержит автоматизацию для операторов и разработчиков эталонного стека DEOS. Атомарные Bash-скрипты, составные процессы и административные утилиты упрощают сборку, проверку, развёртывание, наблюдение и обслуживание парачейна DEOS.

## Классы скриптов

Автоматизация намеренно разделена на два класса с предсказуемыми обязанностями.

### Атомарные скрипты

Пронумерованные скрипты выполняют одну конечную операцию и не вызывают друг друга. Их непрерывная нумерация соответствует последовательности получения подтверждений для локальной сети:

- `01-download-binaries.sh` — загружает закреплённый комплект Polkadot, Omni Node и рабочих процессов и проверяет его контрольные суммы;
- `02-install-tools.sh` — устанавливает необходимые операторские инструменты из Cargo;
- `03-build-runtime.sh` — собирает артефакт Wasm;
- `04-generate-chain-spec.sh` — создаёт проверенную спецификацию цепи непосредственно из полного набора исходных параметров среды исполнения;
- `05-spawn-zombienet.sh` — запускает локальную сеть;
- `06-network-smoke.sh` — наблюдает ограниченное финализированное продвижение ретрансляционной цепи и парачейна;
- `07-network-e2e.sh` — подтверждает одну подписанную финализированную передачу по событиям и хранилищу действующей сети;
- `08-session-transition.sh` — наблюдает одну финализированную смену сессии через RPC обоих коллаторов;
- `09-composed-economic-path.sh` — сверяет финализированный путь DEOS Router, DEOS Oracle и Burn Actor по событиям и хранилищу.

### Составные процессы

Именованные скрипты объединяют атомарные шаги:

- `bootstrap-local-network.sh` — собирает среду исполнения, создаёт спецификацию и запускает локальную сеть с веб-клиентом;
- `validate-local.sh` — выполняет выбранный профиль `fast`, `heavy` или `full`; для запросов на слияние и проверенных отправок в `main` система `GitHub Actions` запускает тяжёлую проверку, а для тегов версий — полную проверку со сверенными исполняемыми файлами и повторным созданием рабочей среды исполнения и клиентских артефактов;
- `actors-assurance.sh` — проводит тяжёлые проверки нагрузки и вместимости планировщика Actors;
- `network-assurance-local.sh` — объединяет свидетельства о топологии, финализации, переключении при сбое, перезапуске и подписанном переводе; `SESSION_TRANSITION=1` добавляет многочасовую проверку смены сессии, а `COMPOSED_PATH=1` — финализированные свидетельства DEOS Router, DEOS Oracle и Burn Actor;
- `benchmarks.sh` — собирает измерения производительности среды исполнения и формирует веса.

## Административные утилиты

Административные скрипты помогают оценивать готовность локальной или действующей сети, не скрывая границы полномочий:

- `seed-web-client-state.sh` — готовит кошелёк, обмен и нативный стейкинг для проверки веб-клиента в действующей сети;
- `export-papi-metadata.sh` — экспортирует метаданные Rust и пересобирает дескрипторы PAPI для веб-клиента;
- `bootstrap-native-staking-local.sh check` — проверяет готовность начальной настройки нативного стейкинга без отправки транзакций;
- `bootstrap-native-staking-local.sh prepare-calls` — выдаёт данные следующего вызова Root, администратора стейкинга в управлении или подписанного оператора для регистрации и инициализации стейкинга, создания канонического пула `NTVE/stNTVE` либо внесения начальной ликвидности;
- `authorized-upgrade-local.sh check` — закрепляет финализированную идентичность среды исполнения, сравнивает сетевой и локальный код, проверяет полномочия на стратегическое предложение, выпуск `$VETO` и ожидающий авторизованный хеш без отправки транзакций;
- `authorized-upgrade-local.sh prepare-authorization` — выдаёт привязанные к кандидату данные вызовов для доли, предварительного образа и стратегического предложения без подписи; защитный вариант `Pass` недоступен до готовности жизненного цикла;
- `authorized-upgrade-local.sh apply` — передаёт уже авторизованный код только при явном `--submit`;
- `authorized-upgrade-local.sh snapshot|verify` — сохраняет финализированное непустое исходное состояние и проверяет точное сохранение DEOS Router, DEOS Oracle, Actors, версии среды и кода кандидата после обновления;
- `teardown-local-network.sh` — безопасно останавливает фоновые процессы и удаляет временное состояние сети.

## Подготовка нативного стейкинга

Этот процесс разделён между двумя безопасными для оператора командами:

1. `bootstrap-native-staking-local.sh prepare-calls` читает состояние сети и готовит данные следующего вызова для рабочего операторского пути;
2. `bootstrap-native-staking-local.sh check` проверяет готовность канонического пула `NTVE/stNTVE`, обменного курса нативного стейкинга и неактивного Liquidity Actor нативного стейкинга.

Обе команды по умолчанию только читают состояние или готовят план. Первая никогда не подписывает и не отправляет транзакции: она лишь выводит данные вызова и ожидаемые полномочия для каждого шага.

## Общие соглашения

Все именованные и административные скрипты следуют одному каркасу:

1. `usage`;
2. `parse_args`;
3. `check_prerequisites/plan`;
4. `main`.

Общий файл `_common.sh` отвечает за сообщения, учёт шагов и фоновые процессы. Каждый такой скрипт поддерживает `--help` с точным описанием применения.
