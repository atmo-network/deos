# С чего начать

## Кратко

DEOS включает глубокие слои среды исполнения, экономики, клиента, документации и средств работы агентов. Чтобы начать, не нужно изучать их все.

Выберите путь по своей цели. Для каждого пути ниже указан короткий маршрут, ясное условие завершения и минимальная проверка, подтверждающая, что вы работаете на нужном уровне.

Для оценки DEOS или создания производного проекта читать `AGENTS.md` не требуется. Этот файл предназначен для сопровождающих проект и агентов. Человеку следует начинать с этой страницы, вики и README соответствующей рабочей области.

## Путь А — понять DEOS за 10 минут

Этот путь предназначен для представителей экосистем, партнёров, инвесторов и разработчиков, которые хотят понять, стоит ли изучать DEOS глубже.

Если вы оцениваете партнёрство или собственный проект на базе DEOS, начните с [Предложения для партнёров](partner-pitch.ru.md). Оно сначала объясняет практический смысл DEOS, а затем направляет к архитектуре.

Прочитайте:

1. [Предложение для партнёров](partner-pitch.ru.md), если вы оцениваете применение DEOS во внешнем проекте;
2. [DEOS за 60 секунд](deos-in-60-seconds.ru.md);
3. [Экономическая физика прежде политики](../comparisons/physics-vs-politics.ru.md);
4. [Стандарт TMCTOL](../concepts/tmctol-standard.ru.md), начав с краткого описания и основных механизмов;
5. [Уровни экономических утверждений](../concepts/economic-claim-levels.ru.md), чтобы отличить свойства механизма от обещаний о рынке.

Путь завершён, если вы можете ответить:

- Что DEOS предлагает вместо ситуативного управления казной DAO?
- Почему TMCTOL — стандарт на базе DEOS, а не весь фреймворк?
- Какие утверждения описывают детерминированное поведение протокола, а какие зависят от рынка и работоспособности исполнителей?

Если интерес сохранился, продолжите по маршруту из [Предложения для партнёров](partner-pitch.ru.md).

## Путь Б — запустить DEOS локально за 30 минут

Этот путь предназначен для разработчика, который проверяет, запускается ли репозиторий на его компьютере.

Предварительные условия:

- Установлен Rust;
- Установлен Node.js;
- На диске достаточно места, а на сборку рабочей области Polkadot SDK отведено достаточно времени.

В первом терминале из корня репозитория:

```sh
./scripts/bootstrap-local-network.sh
```

Ожидаемый результат:

- Локальные исполняемые файлы Polkadot SDK доступны;
- Эталонная среда исполнения собрана;
- Создана спецификация локальной цепи;
- Zombienet запускает локальную сеть на основе Omni Node;
- Парачейн начинает создавать блоки.

Во втором терминале из корня репозитория:

```sh
npm --prefix web-client install
npm --prefix web-client run dev
```

Ожидаемый результат:

- Vite выводит локальный адрес;
- Открывается эталонный клиент;
- Загружается раздел вики;
- После готовности локальной сети можно подключить кошелёк, состояние цепи и ограниченные оперативные данные.

При желании добавьте демонстрационное состояние:

```sh
./scripts/seed-web-client-state.sh
```

Если возникли трудности:

- [Слой скриптов](../usage/scripts-layer.ru.md) объясняет назначение каждого сценария;
- [Трёхуровневая проверка](../development/three-layer-validation.ru.md) помогает выбрать объём проверок и понять, когда его расширять;
- `./scripts/teardown-local-network.sh` останавливает локальные службы;
- `./scripts/clean-local-artifacts.sh` удаляет созданные локальные артефакты.

Путь завершён, когда локальная сеть создаёт блоки, а веб-клиент работает с ней.

## Путь В — безопасно изменить экономику в производном проекте

Этот путь предназначен для партнёрской команды или разработчика протокола, который хочет создать на основе DEOS собственную экосистему.

Сначала прочитайте:

1. [Создание форка DEOS](../usage/forking-deos.ru.md);
2. [Формулы TMCTOL](../math/tmctol-formulas.ru.md);
3. [Трёхуровневая проверка](../development/three-layer-validation.ru.md).

Первый экономический эксперимент проведите в симуляторе до изменения кода среды исполнения:

```sh
node simulator/tests.js
```

С чего безопасно начинать изменения:

| Изменение | Начальная точка | Что менять затем | Минимальная проверка |
| --- | --- | --- | --- |
| Цена или наклон TMC | Симулятор и формулы | Настройки среды исполнения после подтверждения математики | Симулятор, затем тесты TMC |
| Распределение или резервы TOL | Спецификация TMCTOL и симулятор | Схема Actors, настройки среды исполнения, документация | Симулятор и тесты среды исполнения |
| Правила комиссий DEOS Router | DEOS Router | Настройки маршрутизатора, границы управления | Тесты маршрутизатора и проверка утверждений |
| Домены управления или типы предложений | Обзор управления | Пакет и настройки управления, клиент | Проверки управления и клиента |
| Тексты интерфейса и введение | `web-client/` и `wiki/` | Среда исполнения, только если меняется контракт данных | Проверка клиента и доверенного содержимого вики |

Не меняйте без тщательной проверки:

- Начальные параметры кривой после её создания;
- Формулировки о нижней границе, сжатии или гарантиях без пересмотра условий соответствующих утверждений;
- Инварианты учёта по корзинам;
- Разделение ограниченных проекций в блокчейне и материализованных либо индексированных представлений;
- Границы полномочий защитного контура управления.

Путь завершён, когда вы понимаете, какие решения относятся к идее продукта, параметрам симулятора, константам среды исполнения, правилам управления, представлению в клиенте или данным, материализованным вне блокчейна.

## Минимальная проверка для каждого пути

Начинайте с наименьшей осмысленной проверки. Не каждое изменение требует всех проверок.

| Путь или изменение | Минимальная проверка |
| --- | --- |
| Только знакомство | Команды не требуются |
| Текст вики или введения | `npm --prefix web-client run validate:wiki` |
| Поведение веб-клиента | `npm --prefix web-client run validate` |
| Границы веб-клиента | `npm --prefix web-client run validate:dag` |
| Токеномика или формулы | `node simulator/tests.js` |
| TMC в среде исполнения | `cargo test --manifest-path template/Cargo.toml -p pallet-deos-tmc --locked` |
| Широкие изменения среды исполнения | `cargo test --manifest-path template/Cargo.toml --workspace --locked` |
| Изменение нескольких доменов | Симулятор, тесты Cargo, проверка клиента и итоговая проверка репозитория |
