## Decision Question

Does the retained production ObservationChange fanout page owner bound one fully admitted subscriber page whose Actors carry maximum-Step heads, encoded first Tasks, and admissible maximum funding/watch fields?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` ObservationChange subscription, deferred fanout, Trigger latching, and canonical Service placement; `docs/actors-resource-policy.specification.en.md` family reservation.
- `Invariant`: One on-chain observation change dirties the feed; one bounded fanout page calls canonical Trigger admission for each unlatched subscriber, charges useful readiness only once, and publishes pending Service without executing an Actor Step.
- `Reopen trigger`: The measured full page cannot be admitted through ordinary User creation or the fanout page does not perform the reported Trigger/Service transition.

## Context and Hypothesis

- `Current architecture`: `reactions.rs::do_fanout_dirty_observation_page` iterates one bounded subscriber page and calls `signal_observation_subscriber_ordinary`, which loads the current Actor state and commits canonical readiness. `lib.rs::observation_fanout_ordinary_weight_upper` selects the maximum generated fanout page branch; `materialization_family_minimum(1)` adds base, branch probe and fault owner.
- `Reason`: Existing `observation_fanout_page` constructs one full page of short inert User Contracts. It does not qualify the head/proof size or Actor-load work of an equally admitted maximum-Step page.
- `Hypothesis`: Maximum heads on every subscriber make the complete page exceed the retained owner in RefTime or ProofSize.
- `Materiality`: A selected live page above the charged family minimum blocks component-wise owner sufficiency regardless of whether the independently configured ceiling contains the page.

## Controls

- `Controlled variables`: One benchmark Wasm, 50 steps × 20 repeats, full `ObservationPageSize` User subscribers, three-feed dirty-list topology with measured feed in the middle, ordinary User creation and funding, one measured `do_fanout_dirty_observation_page`.
- `Changed variables`: W1 heads/tails use maximum Step count and encoded first Task rather than inert one-Step Contracts. W2 adds maximum signed funding/watch header. W3 adds one subscriber on a second page and measures the naturally rotated one-subscriber tail. W4 keeps W2's full page and installs a bounded synthetic reusable-tombstone Ready span before the measured turn. None executes a Task effect.
- `Confounders`: W1 uses OwnerOnly funding and no balance watches; W2's maximum signed allowlist need not include each Actor owner, since the policy governs future funding ingress rather than creation ownership. Both use short ObservationChange Triggers, not maximum AddressEvent Trigger headers. The first Step is never executed; selected RefTime W1/W2 differences cannot establish ordering without a noise envelope.

## Statistical / Variance Notes

The positive RefTime gaps versus retained production include 192 additional reads at nonnegative DB cost; ProofSize is a separate deterministic excess. W1's selected page is 961,802, W2's 1,010,826, both above retained 325,342. W2/W1 RefTime ranking is inconclusive without a local noise envelope. EXP-0144 identifies a startup minimum violation and rejects a separate live family-ceiling inference; this Leaf does not approve a changed config or ordinary-block capacity.

### Benchmark Evidence Disposition

- `Benchmark Evidence Status`: Qualified.
- `Reassessment Trigger`: Contract head encoding, subscriber page size, canonical Trigger/Service placement, benchmark fixture, Weight generator or Wasm identity changes.
- `Compared Observation IDs`: Both 50×20 output SHA-256 values under Environment.
- `Noise / Stability Evidence`: Same-Wasm matched generated outputs; positive RefTime base and read delta plus large deterministic ProofSize difference. No universal host variance claim.
- `Current Authority`: W1 and W2 reachable full-page counterexamples to retained fanout unit. Neither is an adopted coefficient or universal maximum; EXP-0144 owns the distinction between startup integrity and live shared-budget interpretation.

## Result

W1 measures `20,610,426,000 / 961,802 + 1,352 reads/326 writes`, and W2 `22,125,448,000 / 1,010,826 + 1,352/326`, versus retained `12,688,411,000 / 325,342 + 1,160/326`. The retained ordinary page and its maximum-selector alternatives underbound both selected headers in complete RefTime with DB costs and ProofSize.

## Interpretation

The existing short-head fixture omits ordinary Actor head/proof loading, even though full pages of maximum-Step User Contracts, including funded/watch headers, enter pending Service under real collection. Fixing the fanout page owner must include its complete physical work and preserve fee/source/fault attribution. EXP-0144 replaces the earlier live-refusal inference with a startup integrity violation.

## Decision

Research result: reject the retained ordinary fanout page coefficient as a complete physical bound for W1 and W2. No production Weight, cost vector, Wasm or family minimum is rebound until detector/placement owner closure and coordinated generation.

## Validity

- `Establishes`: Ordinary funded maximum-Step User subscriber page is reachable and exceeds the retained fanout page in both resource dimensions.
- `Does not establish`: Maximum ObservationChange family over all header/funding/cycle states, partial-page retry/terminal behavior, whole-block composition, production fee sufficiency, or released Weight.
- `Known limitations`: W1 OwnerOnly, W2–W4 maximum signed funding/watch headers; all use short ObservationChange Trigger. W3 is one naturally rotated one-Actor second page. W4 injects a bounded synthetic full-capacity tombstone Ready span, yet produces no blocked/refusal outcome. No mid-page retry, terminal branch or Step effect is measured.
- `Invalidation triggers`: Changes to fanout selector, admitted header encoding, page capacity, runtime DB model or benchmark Wasm/source identity.
- `Residual qualitative insight`: Increasing head width raises per-page ProofSize without additional reads or writes; EXP-0144 owns the distinction between startup minimum bound and live shared-family grant.
