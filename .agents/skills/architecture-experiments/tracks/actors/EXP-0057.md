## Decision Question

Does each of the six useful Trigger families have one complete reference-Wasm occurrence owner, while direct, indexed and temporal source paths reserve their physical work once and exclude already-latched Actor-specific evaluation and Trigger collection?

## Governing Specification

- `Owners`: `template/pallets/actors/docs/specification.en.md` (sole ownership, useful Trigger occurrence, lifecycle, placement and scheduler); `docs/actors-resource-policy.specification.en.md` (component-wise admission/actual settlement and equal-thirds policy); `docs/actors-performance-assurance.specification.en.md` (evidence contract and target).
- `Frozen physical input`: [EXP-0025](./EXP-0025.md) C1 Architecture Freeze. No change to FIFO, ticket chronology, Q1, causal floor, primary/reference ontology, source/successor atomicity or sole execution owner.
- `Accepted semantic input`: [EXP-0020](./EXP-0020.md) selects early direct rejection, eager Cadenced detach, consumed AtTime and detector-local indexed disablement. This experiment requalifies Weight ownership; it does not reopen that topology.
- `Semantic oracle`: A0 SHA-256 `8746e423168309975e509be91e4eb06fdf0eb0b43369d75f1ee62202a4341678` remains frozen; use only for relevant semantic equivalence, never as a Weight oracle.

## Context and Hypothesis

The six family-specific `WeightInfo` methods are both the User Trigger-fee basis and the bounded useful-occurrence witnesses. Physical source publication and deferred traversal remain caller/worker-owned: an occurrence coefficient is not added a second time to an inclusive host, fanout or Crossing branch. Already-latched Manual and AddressEvent calls retain ordinary source/transaction ownership but no second Actor Trigger fee; ObservationChange and Crossing skip through `IndexedTriggerDetectionDisabled` before loading Actor state; Cadenced has no live Trigger deadline while latched; AtTime is consumed.

The retained 0.7.24 evidence established these semantics, but the 0.7.25 control-cell source and installed generated file no longer share exact storage identity. The smallest deciding refresh is therefore the six existing useful-occurrence profiles on one current reference benchmark Wasm, combined with source inspection and focused redundancy regressions. Complete file regeneration remains G5 rather than a reason to patch coefficients manually.

Each fixed profile has no independent count component, so generated output selects the fixed conservative point from 50 steps × 20 repeats. ## Result

Every admitted Trigger family reaches a measured current-source useful occurrence owner. Runtime quote/fee selection is exhaustive over `TriggerFamily`; physical Observation, Crossing and temporal workers reserve their inclusive branch separately; direct and indexed regressions establish that an existing latch cannot produce a second Actor-specific fee, event or activation.

## Interpretation

Useful economic ownership and physical block ownership are related but not additive. Observation/Crossing host or worker methods own traversal and publication; temporal cursor admission explicitly reserves the maximum family occurrence; Manual retains ordinary dispatch Weight. The family coefficient prices one successful User occurrence and public cost quote. Redundant source work that remains necessary for source truth or cursor progress is not mislabeled as a useful Actor occurrence.

## Decision

Accepted for the six-family reference binding. Select exactly one family-specific occurrence Weight and Trigger fee only when that family commits `pending_signal: false -> true`. Do not select it for an already-latched occurrence, and do not add it to an inclusive host/fanout/Crossing physical owner. Stage the six generated values above for EXP-0064 composition and EXP-0065 complete regeneration; the installed coefficients remain stale and must not be patched from temporary fragments.

## Rejected Alternatives and Tradeoffs

| Candidate | Decision | Reason |

| One family-independent Trigger coefficient | Rejected | ObservationCrossing proof/database work and Cadenced topology differ materially from direct families |

| Add occurrence Weight to every deferred worker branch | Rejected | Useful page/Crossing branches already include physical occurrence work; addition double counts |
| Remove indexed membership on latch | Retains EXP-0020 rejection | Mutates authoritative fanout/range traversal; detector-local disablement preserves source topology |

## Validity

- `Establishes`: Current reference-Wasm generated useful-occurrence values for all six Trigger families; exhaustive fee selector; physical source/worker ownership partition; focused useful and redundant-latch behavior.
- `Does not establish`: Exact installed production Weight, final production Wasm, generic host implementation bounds, complete Waiting/source/cleanup composition, admission closure or integrated throughput.
- `Known limitations`: Fragments are intentionally uninstalled. Inclusive fanout/Crossing/source files remain stale until complete regeneration; external hosts must preserve their declared synchronous consequence owner.
- `Invalidation triggers`: A changed measured body, Trigger family, detector topology, physical worker composition, fee selector, source/runtime/Wasm identity or acceptance rule requires scoped requalification.
- `Residual qualitative insight`: Price the useful readiness mutation by family, but meter unavoidable source traversal at its physical owner even when the candidate is already latched.
