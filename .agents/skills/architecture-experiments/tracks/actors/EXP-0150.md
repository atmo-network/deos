## Decision Question

Does the retained generated `task_split_transfer(4)` bound cover four active maximum-header User recipients, rather than only the existing four System-recipient benchmark profile?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` §6.1 and `docs/actors.integration.en.md` certified ingress.
- `Invariant`: One invoking Task effect owns all leg preflights, actual transfers, certified ingress and balance-dependency publication; recipient useful Trigger fees remain independent economic charges, not a second physical Task addition.
- `Reopen trigger`: A valid four-leg Task cannot admit or atomically process all four funded User recipient heads under the declared contract.

## Context and Hypothesis

- `Current architecture`: The reference runtime now caps legs at four. The generated effect benchmark already reaches four distinct active System Actors with saturated source filters and tombstone queue; the User diagnostic combines four distinct maximum-header User Actors with real funded Trigger collection.
- `Reason`: The older eight-leg diagnostic User Opening used ordinary recipients and cannot decide ingress cost. Bounding leg count alone does not bound recipient header/class work.
- `Hypothesis`: The retained four-leg coefficient suffices even when every recipient is a funded maximum-header User Actor.
- `Materiality`: A selected ordinary valid witness exceeding retained RefTime or ProofSize rejects coefficient sufficiency without claiming a universal maximum or comparing unmatched runtime artifacts.

## Result

All four User recipients admit, trigger, and retain canonical Pending Service after the complete transfer loop. U exceeds the retained four-leg projection in RefTime including DB and ProofSize. Native mock test and benchmark Wasm both execute the same diagnostic shape.

## Interpretation

The cap from eight to four does not remove the live User-recipient ingress owner. The System-recipient slope covers active Actor notifications but not User maximum header/funding/fee work. The recipient Trigger fee remains its own economic charge; its execution is already inside the invoking Task effect and must not be physically added twice.

## Decision

Status Rejected: the retained-coefficient sufficiency hypothesis fails on the selected four-User witness. No production Weight acceptance follows; complete four-leg Task-effect bounding and coordinated Weight/Wasm/ABI generation remain release work. Outcome class: research result. Stop this diagnostic after the one matched contrast; do not expand a Task × class × Trigger product.
