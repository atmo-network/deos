## Decision Question

What is the smallest atomic movement protocol that preserves exactly one current-generation obligation across every Live, Sleep, Park, and Pending transfer, arbitrary owner/protocol control, full destination, stale reference, callback rollback, and lazy-detach interruption without requiring a second service queue?

## Governing Specification

- `Exact section`: `BACKLOG.md` one-obligation/saturation invariants and N3.8; `template/pallets/actors/docs/specification.en.md` §2.3 current-state residence.
- `Invariant`: A committed current Actor generation has exactly one canonical residence or one terminal/disabled process-local cleanup authority; source authority is released only in the same transaction that secures its successor or proves terminal revocation.
- `Reopen trigger`: A supported transition can commit with zero or multiple current obligations, ordinary saturation can poison global service, or mandatory revocation requires an unbounded scan or an unreserved destination slot.

## Context and Hypothesis

- `Current architecture`: EXP-0125 selects one stable process, a Live/Pending ring, deadline pages for Sleep/review, and process-owned Park evidence. EXP-0126 selects direct mutation-safe round progress. EXP-0127 requires durable destination authority before acknowledgment, but exact full-capacity and arbitrary-control outcomes remain open.
- `Reason`: Remove-first movement loses work on destination refusal; insert-first movement can temporarily duplicate authority; reserving ordinary queue slots for every control path wastes bounded capacity and still does not solve stale reverse-index cleanup.
- `Hypothesis`: Preflight destination capacity and exact source/generation, stage all destination writes, source unlink, process residence swap, and cursor/revision acknowledgment in one storage transaction. On ordinary refusal retain the source unchanged. Terminal/disabled control first revokes execution and directly unlinks the exact residence, then retains only a generation-bound process-local cleanup cursor serviced from mandatory Control reserve.
- `Materiality`: Freeze one exact commit/refusal/rollback protocol and finite saturation matrix. Concrete encoded capacities, Weight values, cleanup implementation, and runtime tests remain N4.2/N5.2/N5.3.

## Measurements

### Canonical Authority and Linearization

`Process.residence` is the sole semantic discriminator and contains the exact generation plus one generation-bound handle or Park Certificate. Carrier entries are physical references validated against it; they never independently authorize execution. A movement transaction performs:

1. Resolve the current generation, accepted plan, exact source residence/handle, and all affected header/page/cursor state. A mismatched old reference is stale cleanup, never movement authority.
2. Preflight the complete effect and resource envelope, including destination occupancy, new key/page/heap bounds, callback writes, source unlink, round cursor repair, reverse-handle replacement, and acknowledgment writes.
3. Stage the destination representation while `Process.residence` still names the source. Staged entries cannot execute because carrier validation requires the process discriminator.
4. Update `Process.residence` exactly once to the destination, remove the exact source representation, repair its header/page/cursor, and apply acknowledgment only when destination authority is durable.
5. Commit all writes together. Any error restores source, process discriminator, destination, frontier, revisions, and cursors exactly.

When source and destination share the service ring, Live↔Pending is a process-role update on the retained node rather than unlink/reinsert. It preserves position, round markers, and occupancy. A reentry that semantically requires a new B + 1 position follows EXP-0126 and performs the bounded transactional unlink/splice.

### Movement and Refusal Matrix

| Source → outcome | Successful commit | Destination full or preflight refusal |
| --- | --- | --- |
| Live/Pending → Live/Pending | Retain or splice one exact node; set role/round state once | Retain source node, role, marker, cursor, and acknowledgment unchanged |
| Live/Pending → Sleep | Secure exact deadline slot/key/heap path, swap discriminator, unlink node | Retain service node and retry/review authority; no deadline claim |
| Live/Pending → Park | Secure complete certificate, registrations, and timed-review slot when required, swap, unlink | Retain Pending/Live source; acknowledge no negative snapshot |
| Sleep → Live/Pending | Secure service node marked considered B and eligible B + 1, swap, remove exact deadline slot | Retain deadline slot as due and leave wake cursor fixed |
| Park → Live/Pending | Secure service node and funded/bounded check authority, swap, then acknowledge traversal | Retain Park plus revision inequality/dirty cursor; source traversal does not advance |
| Sleep ↔ Park | Secure complete destination deadline/certificate authority, swap, then release source | Retain source and all due/revision evidence |
| Any → completion | Prove semantic terminal result, directly unlink exact residence, then delete process if no cleanup remains | Transaction rollback retains source; completion never needs another residence slot |

Typed normal refusal is local backpressure (`DestinationFull`, `ControlUnavailable`, or exact bounded structural cause), not an invariant fault. A service drain encountering a valid refused head obeys EXP-0126 and stops without advancing. A shared wake traversal obeys EXP-0127 and retains its exact target/member. Other unrelated service, deadlines, sources, and owner calls remain usable; no global poison flag is written.

### Arbitrary Control and Mandatory Cleanup

Owner pause/update/cancel and protocol disable/retire first validate authority and generation, then transactionally set a non-executable process status and directly unlink the exact current node/slot/certificate handles. Revocation itself requires no Live, Sleep, Park, or Pending destination slot. If all reverse registrations and auxiliary pages fit the bounded call, they are removed in the same transaction. Otherwise the same stable process becomes the sole `DisabledCleanup` or `RetiredCleanup` authority with an exact old generation, phase, page/slot cursor, and remaining-count bound. It is not executable residence and cannot wake, hold custody policy, or target a replacement.

Mandatory progress uses an explicit component-wise `MandatoryControlReserve` that ordinary activation, checks, and Actions cannot consume. Signed owner control prepays its complete immediate path; runtime-required retirement/detach work is admitted only from the reserved per-block control envelope and retains its process-local cursor when the next unit does not fit. N5.2 must size and generate every immediate and incremental owner. Capacity reserve is therefore semantic capacity to revoke and retain a bounded cursor, not permanently empty ordinary ring/page slots.

A new generation may be created only after its own admission succeeds and uses a distinct generation namespace. Old cleanup can coexist only as the old generation's process-local tombstone/cleanup record; exact reverse handles compare generation before deletion. Cleanup completion deletes only old-generation metadata. It cannot remove, wake, acknowledge, or mutate the replacement.

### Saturation and Recovery Matrix

| Hazard | Preserved state | Recovery |
| --- | --- | --- |
| Full service ring | Sleep/Park/source traversal remains exact; no cursor/ack advance | Direct completion/control or ordinary service frees a node, then the retained source retries |
| Full deadline pages/directory | Live/Pending/Park source remains canonical | Due removal/control frees a slot/key; source retries without reconstructed history |
| Full Park registration/source pages | Pending remains canonical; old registrations stay until replacement commits | Dirty traversal/stale detach/control frees exact handles; negative check retries |
| Mandatory reserve exhausted in block B | Revoked cleanup cursor remains exact and non-executable | Next block replenishes reserve; ordinary queues cannot steal it |
| Callback/late validation failure | Entire movement and acknowledgment roll back | Same source is retried under current state/revisions |
| Repeated hint while source blocked | Coalesces into existing current obligation/revision | One later successful transfer covers newest current state |
| Last-member unlink | Ring cursor becomes None/count zero transactionally | Same-block admission is B-considered/B + 1 eligible |
| Stale old-generation member | Current generation untouched; stale handle yields no authority | Bounded direct detach or old-generation cleanup cursor removes only stale physical state |

No transition waits for capacity while holding an externally visible half-reservation. Transaction-local staged writes disappear on refusal/rollback. Across transactions, authority always remains with the source or process-local cleanup owner.

## Result

Candidate A has one commit point for every residence exchange. Before that point the exact source remains authoritative; after it, the exact destination is authoritative; staged physical entries cannot execute independently. Transaction rollback restores every source, destination, cursor, and acknowledgment write. Ordinary full conditions retain local source authority, while terminal/disabled control bypasses ordinary destination capacity through direct unlink and one bounded process-local cleanup owner.

## Interpretation

Atomicity does not require a permanently reserved queue slot or universal overflow queue. The stable process already supplies the discriminator needed to make destination-first physical staging non-authoritative until commit and to retain interrupted mandatory cleanup without executable membership. Separating normal source-retained backpressure from mandatory revocation prevents saturation from becoming corruption while preserving strict blocked-head and fixed-traversal rules.

## Decision

Accept Candidate A as a research result and sole N3.8 movement protocol: complete preflight; transaction-local destination staging; one process-discriminator linearization; exact source release and cursor/ack update in the same commit; unchanged source on ordinary refusal; direct non-executable revocation with generation-bound process-local lazy cleanup; and a component-wise mandatory Control reserve rather than reserved ordinary membership slots. Stop after the finite W1–W3 matrices. Runtime realization and numeric resource sufficiency remain open.

## Rejected Alternatives and Tradeoffs

| Candidate | Decision | Evidence-backed reason |
| --- | --- | --- |
| Remove source before destination admission | Rejected | Refusal or callback rollback can leave no current obligation |
| Commit destination before releasing source without a discriminator | Rejected | Both carrier entries can independently authorize execution |
| Universal overflow/Pending queue | Rejected | Creates a second service owner, another saturation point, and duplicate-order semantics |
| Permanently reserve ordinary ring/page slots for control | Rejected | Wastes normal capacity and does not own reverse-index cleanup or every destination type |
| Treat full as invariant fault/global quarantine | Rejected | Legal bounded occupancy would poison unrelated service permanently |
| Let ordinary work borrow mandatory reserve | Rejected | Hot admissible work can starve revocation and stale cleanup indefinitely |
| Scan for predecessor/member during control | Rejected | Violates bounded direct-removal authority and makes full-state cost population-dependent |
| Cleanup cursor without generation binding | Rejected | Old cleanup can delete or wake a replacement generation |
| Advance source cursor and reconstruct later | Rejected | Reconstruction is a second acknowledgment channel and can lose exact order/revision authority |

The accepted tradeoff is larger transactional preflight/write geometry and a separately generated mandatory Control envelope. It buys one linearizable obligation and deterministic recovery without sacrificing ordinary carrier capacity.

## Validity

- `Establishes`: One movement linearization point, destination-first staging semantics, source-retained typed refusal, direct arbitrary revocation, last-member behavior, generation-isolated lazy cleanup authority, mandatory reserve separation, and full-state recovery rules.
- `Does not establish`: Runtime correctness, exact capacities/encoding, cleanup throughput, numeric mandatory reserve, generated Weight/ProofSize, adversarial composition, or release viability.
- `Known limitations`: N4.2 must choose the exact cleanup phase/cursor fields; N5.2 must prove every complete preflight and reserved incremental unit fits block budgets.
- `Invalidation triggers`: Any implementation commits duplicate/absent authority, needs an ordinary destination to revoke, lets ordinary work consume mandatory reserve, scans population, advances on refusal, or lets old cleanup affect a new generation.
- `Residual qualitative insight`: Saturation is safe when refusal preserves the exact source and mandatory control reduces to direct revocation plus resumable generation-bound cleanup.
