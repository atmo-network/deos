## Decision Question

Can an ordinary fresh-genesis ObservationChange fanout turn produce the stored `Terminal` branch, a `retry_after` deferral, or the `Some(false)`/`None` result paths that would justify separately charging a complete terminal/refusal page owner?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` §4.2 and §4.4 bounded ObservationChange readiness and temporary-retry semantics; `template/pallets/actors/docs/architecture.en.md` Observation fanout progress.
- `Invariant`: Classify only reachable complete physical work as a live Weight owner; source/probe/fault and ordinary page remain independently bounded. Do not erase contractual retry semantics without a specification and implementation decision.
- `Reopen trigger`: A new activation outcome, real temporary destination refusal, storage lineage obligation, or code path explicitly producing a terminal branch.

## Context and Hypothesis

- `Current architecture`: `DirtyObservationState` still carries `Ordinary | Terminal` and `retry_after`; `materialization_family_minimum(1)` takes the maximum of ordinary page and generated `observation_fanout_terminal()`. EXP-0143 W4's synthetic saturated Ready span still signals all 64 Actors instead of causing refusal.
- `Reason`: The retained terminal, blocked and retry profiles look like distinct charged branches, but benchmark labels do not prove current production reachability.
- `Hypothesis`: No ordinary fresh-genesis path can enter `Terminal` or set `retry_after` with the current single-variant observation activation result.
- `Materiality`: Avoid a Cartesian benchmark expansion and incorrect double reservation; retain separate contractual question for any later genuine temporary outcome.

## Measurements

`ObservationActivationOutcome` has only `Ordinary(ActivationOutcome)` (`scheduler.rs:155`). `process_observation_change_occurrence` returns either `Ordinary(IgnoredStale | Latched)` or `ActivationFailure::Permanent`; insufficient fee maps to `Ordinary(IgnoredStale)` and other failures roll back. `signal_observation_subscriber_ordinary` therefore returns only `Ok(Some(true))` or an error, never `Ok(Some(false))` or `Ok(None)` (`reactions.rs:569–587`). The regular signal wrapper returns only `Ok(true)` or an error (`reactions.rs:549–566`). `do_fanout_dirty_observation_page` sets `Terminal` only after `None` and sets `retry_after=Some(now+1)` only after `Some(false)` or `false` in the terminal branch (`reactions.rs:692–737`). Fresh dirty-feed construction initializes `Ordinary`/`None` (`reactions.rs:230–248`), and all ordinary producer writes in that file preserve or reset those fields. The generated `observation_fanout_terminal` benchmark instead calls ordinary `do_fanout_dirty_observation_page()` for one expiring System Actor and asserts pending Service; it does not force the stored `Terminal` selector (`benchmarking.rs:20770–20790` at this lineage). The named `observation_fanout_blocked_page` fixture fills reusable tombstones yet likewise asserts all subscribers pending Service. EXP-0143 W4 confirms that limit of the synthetic saturation shape.

## Result

No live ordinary transition can write `Terminal` or set `retry_after`. The named terminal benchmark exercises an ordinary expiring System Actor, and the named blocked benchmark exercises an ordinary successful saturated-tombstone page. Neither proves a distinct terminal or refusal unit.

## Interpretation

The ordinary page and independently charged source/branch probe/fault work still need physical bounds. Do not eliminate retry from the *contract* merely because this implementation cannot produce it today; classify the unused stored branch/retry machinery separately from concrete required refusal semantics. Do not remove production Weight or change SCALE/storage fields until a coordinated pre-launch contract and artifact review.

## Decision

Classify the separate `Terminal` and retry fanout selectors as non-live for current ordinary fresh-genesis operation; keep the retained comparison explicitly conservative and defer removal/simplification to coordinated source/Weight/Wasm/ABI generation. No code, Weight or configuration is changed in this Leaf.
