## Decision Question

Can ordinary Q1 continuation become materially cheaper when the current Step obligation, rather than a reconstructed Actor-centric view, is the physical hot-path entry while the Actor remains the semantic and control-plane entity?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` → `§3.3`, `§3.5`, `§5.1`, `§5.3`, `§6.1`, `§8.2-§8.3`, and `§13.1`.
- `Invariant`: Preserve strict FIFO, Q1, N+1 causal eligibility, one live Pipeline plus one deferred latch, C6 Contract geometry, Pipeline Machine prepayment, Action pay-as-executed, atomic Task effects, no mid-Pipeline apoptosis, persistent sovereign custody, and exact-slot recovery.
- `Reopen trigger`: Any candidate that changes semantic order, batches execution, duplicates authored Contract semantics, weakens stale-authority rejection, introduces a second scheduler, or commits more than one Step per Actor per block is not a physical optimization candidate.

## Context and Hypothesis

- `Current architecture`: FIFO resolves ActorId and loads Actor identity/hot/Contract/funding/run partitions before current-Step execution and successor placement.
- `Reason`: EXP-0005 showed isolated key co-location does not materially improve complete production throughput; the larger remaining gradient may be the breadth of the Actor-centric hot path and repeated physical I/O.
- `Hypothesis`: A compact current-Step service handle plus stable run authority, direct current Contract-fragment access, situational snapshot loading, and optional page-level I/O amortization can reduce Actor-machine cost without changing Actor semantics.
- `Materiality`: At least 20% improvement in one primary Pareto metric without unacceptable regression in another, lifecycle/state hold, service-gap fairness, exact Task equivalence, or bounded worst-case ProofSize.

## Statistical / Variance Notes

The first decision surface is one ordinary middle Step with successor, not create/Opening or full first traversal. The legacy run-progress benchmark removed the prior payload and hid its read proof behind a write overlay; candidate comparisons use the corrected persisted-payload setup. Prefix scaling is accepted only as storage-I/O amortization evidence and never as permission to batch execution.

## Result

A1 clears the focused gate on a matched User middle-Step setup: the candidate physical owner set lowers RefTime and estimated proof by 52.8%, measured proof by 65.5%, reads from 15 to 5, and writes from 4 to 3. This is a lower-bound owner probe rather than a complete semantic branch, so it authorizes only the smallest integrated Running in-chunk-successor implementation.

Prepared A0 ledger and corrected the focused persistence setup so the maximum RunPayload exists before the measured Q1 transition. The correction exposes a larger binding gradient: progress ProofSize rises from the legacy `5,775` overlay model to an honest `8,567` because state-hold reconciliation reloads the existing broad payload.

The minimal A1 adds no persistent cache or authored fields. The existing `ActorStepTicket` remains the compact handle. For a Running cursor inside a loaded tail chunk with an in-chunk successor, run authority validates the chunk directly; Contract head, admission certificate, and unrelated funding/snapshot partitions remain cold. Head-only progress reconciles the exact User hold by applying the checked encoded-length delta between old/new RunHead to the retained run-hold component; Opening, payload mutation, terminal, replacement, cancel, close, and any uncertain branch use the generic full reconciliation path. H0 Cycle-local hold policy therefore remains unchanged.

## Interpretation

The corrected production candidate changed both `persist_loaded_run_state` and final Queue-placement reconciliation. It removed ActivationAuthority, ObservationFeeds, ObservationSubscriptionSlot, and CrossingMembership reads from the complete middle-Step branch, but the remaining queue, Contract, RunPayload, action, and hold owners dominate proof. End-to-end RefTime improved only 7.7%, while measured and estimated proof were unchanged. Exact run-component reconciliation is therefore sub-material even on the correct route.

The owner-necessity ledger leaves one plausible A1 survivor: situational RunPayload elision. A Step with no Opening predicate and no amount resolution that depends on frozen Opening/funding state can execute from RunHead plus the authored Step, preserve the untouched payload, and persist only the new RunHead. ContractHead cannot be removed without duplicating authored schedule/completion/funding authority.

A matched actor+queue storage-owner A/B now isolates only the RunPayload read. Elision reduces estimated proof by 29.1%, measured proof by 48.1%, and RefTime by 9.3%. Trie overlap lowers the earlier arithmetic maximum, but focused ProofSize still clears the 20% gate. This authorizes the complete semantic branch implementation.

The first retained implementation slice adds an exhaustive semantic dependency classifier owned by `AmountResolution`, `Task`, and `Step`. `Fixed`, `PercentageOfCurrent`, and `AllAvailable` remain snapshot-independent; `PercentageAtOpening`, `PercentageOfLastFunding`, and any Opening predicate require frozen cycle payload. Exhaustive Task matching makes future variants fail compilation until classified.

The second retained slice makes current-Step execution consume the already validated `CurrentStepPlan.run` for Running cursor and state inputs instead of reloading `ActorRunStateStore`; Suspended still uses authoritative `begin_run_attempt`, and plan-less simulation falls back to storage. This does not yet eliminate the scheduler's initial payload read, but establishes one validated run input for the compact projection.

The complete payload-elision candidate included explicit commitment provenance, compact Running projection, head-only persistence, checked hold delta, RunHead-based successor placement, and safe pre-cutoff projection. It passed the complete pallet suite before measurement and was then fully reverted after missing the materiality gate. The resulting A1 improved RefTime by 14.9% and estimated proof by 17.2%; measured proof improved 40.1%. No candidate-specific storage, plan field, loader, persistence branch, hold path, or scheduler path remains.

## Decision

Reject A1 and fully revert compact projection, payload-elision provenance, head-only persistence, hold-delta, and projection-specific scheduler changes. Retain only independently useful semantic dependency classification and validated-plan reuse if they remain behavior-neutral after cleanup. Do not advance A2: vectorization would add physical complexity atop a Step-centric layout that failed the complete-path materiality gate.

## Rejected Alternatives and Tradeoffs

| Candidate | Decision | Evidence-backed reason |
| --- | --- | --- |

| Multi-Step execution batch | Excluded | Violates Q1 and per-Step transaction ownership |

| Generic replacement scheduler | Excluded | Creates a second order owner |
| External block-bound successor pages | Excluded | A successor committed before later Manual, Trigger, or wakeup readiness must reserve its canonical FIFO position at source; delayed page materialization either permits overtaking, inserts ahead of FIFO, or becomes a second order owner |
| Grouped transient successor flush | Excluded | Independent committed-Step durability requires each successor's canonical position to survive immediately; delayed cross-Step flush creates a shared failure domain, while per-Step flush restores scalar mutation |

## Validity

- `Establishes`: When complete, comparative physical cost of Actor-centric versus Step-centric ordinary Q1 for declared workloads.
- `Does not establish`: Permission to alter Actor semantics, priority, fee ownership, lifecycle, custody, or the one-third Control ceiling.
- `Known limitations`: The retained classifier and validated-plan reuse are behavior-neutral and do not claim the rejected A1 cost reduction; corrected benchmark setup awaits the next ordinary Weight generation.
- `Invalidation triggers`: Contract/run/FIFO geometry, generated Weight, resource ratio, page bounds, or host transaction model changes.
- `Residual qualitative insight`: Step-centricity is useful only if it removes complete hot-path owners rather than renaming Actor-centric reconstruction. Ordinary exact-`N+1` placement already bypasses generic wakeup materialization and appends directly to FIFO after cutoff. Future page-I/O research must remain inside canonical FIFO ownership; a separate due-block successor page cannot encode interleaved global admission order.
