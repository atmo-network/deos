## Decision Question

Does retained generated `manual_trigger()` bound a signed Mutable User maximum-Step Contract with maximum signed-funding and balance-watch header in both complete RefTime and ProofSize?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` §4.2 Manual readiness and §7.7 useful-readiness fee; `AGENTS.md` Actor Fee Boundaries and Transactional Mutation.
- `Invariant`: The signed call and one useful Trigger fee own the complete bounded detection/collection/placement work, excluding later Pipeline/Action effects. Redundant latched occurrences create no second activation.
- `Reopen trigger`: Contract header bound, Manual dispatch body, generated owner or fee attribution changes.

## Context and Hypothesis

- `Current architecture`: Original `benchmarking.rs::manual_trigger` creates a one-Step short User Actor. `manual_trigger()` is both the signed dispatch Weight and the `trigger_weight_for_family(Manual)` useful-readiness fee basis; full headers admitted by the same `create_user_actor` route can be much larger.
- `Reason`: EXP-0147/0148 separately falsified short-header useful-readiness owners for other families; Manual remains a direct signed dispatch rather than a deferred fanout page.
- `Hypothesis`: One legal maximum-Step signed-funding/watch header exceeds the retained Manual coefficient independently in complete RefTime and ProofSize.
- `Materiality`: This underbound affects signed dispatch admission and a User Trigger fee, not merely an internal diagnostic fee or a pending release note.

## Statistical / Variance Notes

The positive RefTime base and 11 added reads make complete RefTime underbound robust for these outputs. Proof result does not rely on comparing two estimators with different PoV settings: W1's measured PoV alone exceeds the production charged estimate. Neither metric proves maximality over all Manual outcomes.

### Benchmark Evidence Disposition

- `Benchmark Evidence Status`: Qualified selected signed-dispatch and useful-fee underbound; no adopted coefficient.
- `Reassessment Trigger`: Manual Contract header, signed call, Weight/fee owner or Wasm changes.
- `Compared Observation IDs`: Selected and matched output hashes under Environment.
- `Noise / Stability Evidence`: Matched Wasm positive base/DB delta; measured PoV exceeds retained estimate despite different proof modes.
- `Current Authority`: Retained Manual dispatch/fee Weight fails one legal maximum-header positive User call in both resource dimensions.

## Result

One admitted Manual positive latch costs `416,750,000 / 21,922 + 31 reads/6 writes` generated (11,032 measured PoV) versus retained `198,003,000 / 6,196 + 20 reads/6 writes`. Direct signed dispatch is physically underpriced; User Trigger fee uses this same owner.

## Interpretation

Manual has no deferred outer fanout page to absorb this gap. Do not add a later Pipeline/Action effect to this signed Trigger owner or assume the short profile bounds other Manual terminal/negative branches. Honest rebinding must coordinate complete selector, fee vector, production Wasm and block-resource capacity.

## Decision

Reject retained `manual_trigger()` as a complete physical positive User maximum-header bound. No production Weight, fee vector or Wasm is changed in this Leaf.

## Validity

- `Establishes`: A paid, ordinarily signed maximum-header User Manual Trigger exceeds retained complete RefTime and ProofSize.
- `Does not establish`: Manual maximum over all classes, mutability, negative Park, zero-Step or later Pipeline/Action effects.
- `Known limitations`: Single Mutable User/Idle positive latch; funding allowlist contains accounts distinct from the extrinsic signer but creation and trigger are ordinarily admitted.
- `Invalidation triggers`: Changed header bounds, signed dispatch or retained production identity.
- `Residual qualitative insight`: Direct signed source underpricing cannot be hidden behind a deferred page budget; economic and dispatch owner are the same generated unit.
