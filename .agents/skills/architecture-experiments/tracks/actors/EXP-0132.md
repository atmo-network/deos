## Decision Question

Which shipped Actors surfaces must be deleted, replaced, or explicitly preserved so the current-state persistent-ring implementation has exactly one execution authority, one wake path and no unpriced legacy scheduler while custody, provider anchors and effect adapters remain unchanged?

## Governing Specification

- `Exact section`: `BACKLOG.md` N5.1; `template/pallets/actors/docs/specification.en.md` §2.3; EXP-0120–EXP-0131 current lineage.
- `Invariant`: Fresh genesis rejects removed encodings and exposes only current-state semantics. One generation-bound process owns residence and execution; ingress creates a coalesced Pending check, never a historical cause or hidden Cycle. Lifecycle removal is custody-neutral.
- `Reopen trigger`: One supported genesis, hook, ingress, API, client or independent-host path can reach legacy scheduling authority, or removing a legacy surface changes sovereign balances, provider anchors or effect semantics.

## Context and Hypothesis

- `Current architecture`: Shipped code still stores `pending_signal`, `RunOpeningSnapshotOf`, Ready tickets/pages, waiting pages/heaps and `ActorControlLocators`; scheduler transitions repeatedly detach and republish successor cells. Runtime Weight/config and client ABI expose Opening and queue-shaped fields. The current specification already supersedes those semantics but implementation remains legacy.
- `Reason`: Adding the selected persistent ring beside these paths would create two service owners and preserve obsolete snapshot/publication costs, invalidating resource comparison and boundedness claims.
- `Hypothesis`: Delete legacy semantic authority and physical scheduler storage in one fresh-genesis cut; replace every supported ingress with generation-bound Pending admission and every service transition with in-place process/residence mutation. Preserve only independent identity, custody/provider, fee collection and effect-adapter boundaries. No compatibility reader, migration, queue bridge or fallback hook survives.
- `Materiality`: Freeze a complete path-class elimination/isolation map with code anchors and supported embedding coverage. Runtime edits, generated ABI/metadata/Weight and tests remain implementation work.

## Result

Every legacy scheduling class has a unique disposition. Snapshot, latch, Ready queue, waiting-primary, successor-publication and unmetered fallback authority must be deleted, not bridged. Temporal references and run tiers survive only in replacement form under one stable generation process. Custody/provider/effect boundaries remain independent and cannot schedule work by themselves.

## Interpretation

A fresh-genesis redesign is safest as a hard cut, not a migration. Keeping an old queue for rare sources would make that queue the real liveness owner and leave its storage and Weight payable. Conversely, deleting account or effect membranes because they mention Actors would conflate scheduler authority with independent economic truth. The boundary is capability-based: anything that can publish/execute service is replaced; anything that only owns custody or performs an admitted effect is preserved.

## Decision

Accept Candidate A as the N5.1 map: remove all legacy snapshot, latch, Ready/waiting-primary, successor and fallback scheduling authority in one fresh-genesis implementation; route every supported source and return through one generation-bound process/residence machine; atomically regenerate runtime/client consumers; preserve custody, provider anchors, fee collection and effect semantics as non-scheduling boundaries. Outcome class: research result. Finite stopping basis: every inventoried path class has one disposition and no fallback is admitted.

## Rejected Alternatives and Tradeoffs

| Candidate | Decision | Evidence-backed reason |
| --- | --- | --- |
| Dual-write old and new schedulers | Rejected | Creates two authorities and doubles cleanup/resource obligations |
| Keep old queue for rare ingress or retry | Rejected | Hidden fallback owns real liveness and remains unpriced |
| Reinterpret removed SCALE variants | Rejected | Violates fresh-genesis semantic coherence |
| Preserve `pending_signal` as API-only truth | Rejected | Duplicates Pending residence and invites stale authority |
| Delete custody/effect adapters with scheduler | Rejected | Changes independent economic semantics outside N5.1 |
| Migrate old storage | Rejected | Pre-1.0 fresh genesis has no production lineage obligation |

The accepted tradeoff is a coordinated ABI/storage break and full generated-evidence refresh. It buys one inspectable authority and removes compatibility complexity.
