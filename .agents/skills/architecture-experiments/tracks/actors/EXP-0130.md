## Decision Question

What is the smallest resumable cleanup protocol that can reclaim every physical object of an authorized retired generation under saturation and interruption, while never mutating replacement semantics or custody and never depending on an unbounded scan or idle-only progress?

## Governing Specification

- `Exact section`: `BACKLOG.md` N4.2; `template/pallets/actors/docs/specification.en.md` §2.3 and §9; EXP-0125 carrier handles, EXP-0128 direct revocation, and EXP-0129 status authority.
- `Invariant`: Revocation removes execution authority immediately. Later cleanup may delete only objects named by the retired generation's sealed cleanup manifest; a replacement generation has disjoint authority and storage identity. Custody is never a cleanup object.
- `Reopen trigger`: Cleanup requires population search, can lose its cursor, can be starved by ordinary work, releases admission/holds before their last protected object is gone, or can delete/wake/acknowledge current-generation state.

## Context and Hypothesis

- `Current architecture`: EXP-0128 and EXP-0129 leave an exact generation-bound cleanup cursor after transactional revoke-before-detach, but do not freeze its phases, eligibility, interruption semantics, or replacement overlap.
- `Reason`: A generation tag prevents semantic aliasing but does not pay traversal or prove that all reverse registrations, deadline keys, carrier cells, certificates, and metadata are eventually removed. A generic sweep can cross generations; immediate all-object cleanup can exceed a block; idle-only cleanup can starve forever.
- `Hypothesis`: Seal one immutable `CleanupManifest` at retirement from already-owned bounded reverse handles/counts. Advance one typed phase and scalar/page cursor monotonically through exact object classes. Each unit validates retired generation and object tag, directly detaches at most its generated bound, and commits cursor advancement with deletion. Finalization separately proves every class empty before releasing process tombstone, storage hold, and generation slot.
- `Materiality`: Freeze semantic cleanup ownership, ordering, full-capacity behavior, and replacement isolation. Exact encoding, numeric limits, prices, generated Weight, and runtime implementation remain N4.3/N5.2.

## Measurements

### Sealed Manifest and Eligibility

Retirement preflight derives the manifest only from process-owned bounded reverse handles and counters already required by the live carrier contract. It does not enumerate a population or allocate a discovered-work vector:

```text
Cleanup {
  generation,
  reason,
  eligible_from,
  phase,
  cursor,
  remaining_by_class,
  manifest_commitment
}
```

`eligible_from` may enforce an epoch/era or dispute window, but eligibility merely gates deletion; it never supplies traversal authority. Required immediate revocation, direct executable-residence detach, and durable cursor installation occur before that window. The manifest is sealed when `Retired` commits. Later source notifications may create stale physical references only if they already carry the old generation; they cannot enlarge the manifest or grant execution.

A replacement may be admitted after old revocation and cleanup-cursor capacity are secured. It receives a fresh nonwrapping generation and distinct carrier/reverse keys. Reusing an exhausted generation space fails closed. The old tombstone remains independently charged until finalization.

### Canonical Phase Order

| Phase | Owned objects | Unit and advancement rule |
| --- | --- | --- |
| 0 Direct residence detach | Exact ring node or deadline/Park residence named at revocation | Transactionally delete/repair direct neighbors or prove already stale, then clear residence handle |
| 1 Executable auxiliaries | Retry/review deadline key, Pending role, round/frontier marker, callbacks | Delete exact generation-tagged handles; never classify or execute |
| 2 Detector/source reverse registrations | Park dependency keys, source subscriber entries, direct account mapping | Walk only process-owned bounded pages/slots; delete matching old generation or consume stale slot |
| 3 Process semantic state | Park Certificate, run/retry/failure basis, plan/Contract generation payload, local hot state | Delete only after phases 0–2 counters are zero; preserve committed external effects and custody |
| 4 Admission resources | Generation-owned storage hold, retained-byte accounting, slot/provider reservation | Release only after all protected bytes and references prove absent |
| 5 Final tombstone | Cleanup manifest/cursor and old process-generation record | Delete atomically after zero counters and no current-generation alias; stable Actor identity/custody remain |

The phase order is semantic: remove all paths that could be mistaken for service before semantic payload, then release economic/admission resources, then erase cleanup authority. Within a phase the cursor is one scalar page/slot or exact-handle position. A unit touches at most the generated maximum for that phase; no phase change occurs until its remaining count is zero and bounded owner-owned headers prove exhaustion.

### Atomic Unit, Interruption, and Stale Work

Each cleanup unit validates Actor id, retired generation, status, phase, cursor, manifest commitment, and complete phase-specific resource envelope. It loads the exact object, checks its generation, deletes and repairs bounded local structure if matched, or classifies it stale/already absent. The same transaction decrements the class counter and advances the cursor. Failure rolls back object and cursor together.

A stale callback, wake, detector member, or deadline extraction validates `Process.status == Serving` and exact current generation before semantic work. Against Retired it may invoke only the same bounded detach primitive; it cannot advance the canonical cleanup cursor unless it proves that cursor names the same object. Duplicate helpers therefore converge idempotently rather than creating a second sweep owner.

If mandatory Control is exhausted in block B, the cursor remains durable and resumes in a later block. Ordinary service cannot borrow the reserved maintenance owner. Signed cleanup may accelerate the same canonical cursor only by paying the complete unit and cannot select an arbitrary phase/object or bypass eligibility.

### Replacement and Capacity Matrix

| Hazard | Old-generation outcome | Replacement/custody outcome |
| --- | --- | --- |
| Ordinary carriers/pages full | Revocation stores non-executable cleanup in reserved process/tombstone capacity | Admission is independent; no ordinary slot is reserved for cleanup |
| Replacement uses same dependency key | Old reverse entry deletes only exact `(Actor, old_generation, slot)` | New entry survives and keeps its own revision/acknowledgment |
| Old deadline becomes due | Due worker proves Retired/stale and bounded-detaches | No wake, retry reset, or new-generation cursor movement |
| Interruption after physical delete | Transaction rollback retains object/cursor, or committed delete advances cursor | Replacement remains unchanged |
| Old object already removed | Unit proves exact absence and consumes its manifest count once | No broad key deletion |
| Final hold/slot release | Occurs only after prove-empty phases | Stable sovereign account and balances are never released/transferred |
| Mandatory budget exhausted | Cursor waits without executable authority | Current generation continues under ordinary owners |

### Progress Contract

Cleanup liveness is not an `on_idle` promise. N5.2 must generate one complete maximum unit for every phase and reserve a non-borrowable per-block maintenance envelope. Admission bounds the creation rate of cleanup debt so, under the declared sustainable-load assumption, reserved service rate is strictly greater than admitted long-run cleanup work. If outstanding debt reaches its generated high-water mark, replacement/update/creation admission returns typed backpressure before revocation capacity is endangered. Mandatory terminal revocation itself remains admitted through its separately reserved cursor/tombstone capacity.

This experiment establishes the owner and inequality shape, not numeric rates. N4.3 owns byte/hold debt and release prices; N5.2 owns phase maxima and capacity constants.

## Result

Candidate A gives every retired generation one sealed finite cleanup owner. Revocation remains immediate and capacity-safe; later work advances monotonically through exact generation-tagged object classes. Replacement generations coexist in disjoint namespaces, stale work is bounded and non-semantic, custody survives, and resource release occurs only after prove-empty finalization.

## Interpretation

Generation tags are safety predicates, not a reclamation algorithm. Safety requires exact reverse authority and disjoint namespaces; liveness additionally requires a durable canonical cursor, non-borrowable funded service, and admission that bounds debt creation. Separating final resource release from physical detach prevents an interrupted sweep from turning retained bytes into unowned debt.

## Decision

Accept Candidate A as the sole N4.2 cleanup protocol: retirement seals a bounded generation-owned manifest; cleanup follows fixed direct-detach, auxiliary, reverse-registration, semantic-state, resource-release, and tombstone phases; each unit atomically deletes/proves stale and advances one canonical cursor; replacement generations are namespace-isolated; custody is excluded; mandatory progress is funded independently of idle work; debt admission must remain below sustainable service. Runtime realization remains open.

## Rejected Alternatives and Tradeoffs

| Candidate | Decision | Evidence-backed reason |
| --- | --- | --- |
| Scan global carriers/indexes by Actor id | Rejected | Cost scales with unrelated population and interruption has no exact authority |
| Build a mutable discovered-work queue | Rejected | Adds another boundedness/saturation owner and can miss concurrent old references |
| Delete by Actor id without generation | Rejected | Old cleanup can remove replacement objects |
| Let stale wakes perform semantic cleanup/revival | Rejected | Source timing authority would become lifecycle authority |
| Advance cursor before deletion | Rejected | Failure can permanently skip retained state |
| Release hold/slot at revocation | Rejected | Remaining bytes and traversal cost become uncollateralized debt |
| Run only in idle block remainder | Rejected | Admissible sustained load can starve mandatory reclamation forever |
| Let ordinary work borrow maintenance reserve | Rejected | Full ordinary demand destroys the promised progress bound |
| Forbid replacement until full cleanup | Rejected | Unnecessarily couples mutation latency to reclamation despite generation isolation |

The accepted tradeoff is retained tombstone/manifest state, reverse handles, and a dedicated maintenance budget. It buys bounded restartability and replacement safety without delaying cessation or changing custody.

## Validity

- `Establishes`: Complete object-class ownership, fixed cleanup phases, exact-handle cursor semantics, atomic interruption recovery, stale-work behavior, replacement namespace isolation, final release ordering, and funded sustainable-load progress shape.
- `Does not establish`: Runtime implementation, exact encoding/capacity/rate, retained-state prices, generated Weight/ProofSize, or release readiness.
- `Known limitations`: N4.3 must price manifest/tombstone/disabled bytes and debt high-water marks; N5.2 must generate each phase and reserve; N5.3 must compose adversarial races.
- `Invalidation triggers`: Population scan, mutable unowned worklist, idle-only service, early release, generation alias, custody mutation, lost cursor, or old cleanup changing current semantics.
- `Residual qualitative insight`: Bounded reclamation needs both an ownership proof and a queueing inequality; generation labels alone provide neither progress nor payment.
