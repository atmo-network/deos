## Decision Question

Which conforming activation-authority geometry lets broad observation fanout latch and request canonical future placement without loading or statically charging maximum Contract Step resources, funding payload, or run payload, while preserving exact terminal classification, FIFO/wakeup placement, fault isolation, and production Weight soundness for coalesced, placed, and terminal branches?

## Governing Specification

- `Exact sections`: [`template/pallets/actors/docs/specification.en.md` §1.5 Causal Readiness, §2 Trigger Matrix and Unified Placement, §5.2 Observation Topology, and §5.4 Mandatory Prepass](../../../../../template/pallets/actors/docs/specification.en.md); [`docs/actors-resource-policy.specification.en.md` §1 Resource Domain and §4 Admission and Actual Weight](../../../../../docs/actors-resource-policy.specification.en.md); [`docs/actors-performance-assurance.specification.en.md` §1 Evidence Contract and §4 Contract Complexity Matrix](../../../../../docs/actors-performance-assurance.specification.en.md).
- `Invariant — one activation contract`: Fanout sets the sole `pending_signal` latch and requests the same canonical placement semantics as every external readiness source; it may not create a second ready queue, scheduler, priority, or off-chain authority.
- `Invariant — exact terminal behavior`: Window expiry, cycle-nonce exhaustion, pause, cooldown, Running/Suspended placement, stale membership, and capacity failure remain fail-closed and transactionally equivalent to generic activation.
- `Invariant — No Ceiling Tax`: Raising B8 to P32 may not increase fixed fanout ProofSize, reads, writes, or retained short-Actor bytes solely because unused maximum admission/funding/run capacity exists.
- `Reopen trigger`: Reopen Specification only if every bounded single-placement geometry requires maximum execution payload to classify readiness correctly; a losing physical projection does not justify semantic relaxation.

## Context and Hypothesis

- `Current architecture`: Broad fanout visits one occupied subscriber page and invokes generic `request_activation`. Generic activation reconstructs admitted Contract state and loads `ActorFunding` plus `ActorRunState` before classification. A one-Step Idle subscriber does not read tail chunks, but generated fixed Weight still inherits maximum encoded admission, funding, and run bounds.
- `Measured gap`: EXP-0002 final P32 handoff raised dense-page ProofSize from B8 `300,510` to P32 `331,998`, reducing service under the unchanged 20% block envelope from three pages to two even though the subscriber Contract remained one Step.
- `Reason`: The normative 32-Step ceiling cannot bind while fanout service capacity is coupled to unused execution payload maxima.
- `Hypothesis`: A compact authority containing only the immutable Contract identity and readiness/terminal fields needed before placement can make B8/P32 fanout Weight structurally identical; extended admission resources, funding maps, run snapshots, and Step payload remain execution-owned and load only after placement reaches service.
- `Materiality`: Any B8/P32 difference in fixed fanout ProofSize/read/write topology is material. A candidate also fails if it adds one short FIFO storage key/read, weakens authority validation, delays terminal substitution beyond the canonical activation contract, or exceeds ±5% B8 RefTime without a strictly lower binding ProofSize dimension.

Candidate A's fixed projection contains semantic Contract ID, body commitment, admission identity, observation feed, cooldown, schedule window, and optional terminal cycle nonce. The three C6 authority IDs bind projection identity without widening `ActorIdentity` or `ActorHot`; lifecycle transactions derive/write/delete the projection with Contract geometry, and TryRuntime proves exact field and authority equality.

Preparation dependency review found that projection-only activation is insufficient: exact generic classification also owns current-Step User fee viability, dynamic native balance, Running/Suspended cursor and retry coherence, retry-attempt terminal substitution, and current eligibility. Candidate A therefore tiers existing authority rather than caching a lossy summary. C6 head/tail fragments co-locate each Step's admitted resource envelope; the admission certificate retains compact runtime/body identity only. `ActorRunHead` owns mutable scalar authority, cursor, eligibility, retry, outcomes, and suspension; immutable Opening/funding snapshots move to `ActorRunPayload`, written once at Opening and removed at termination. Ordinary fanout loads identity/hot, activation projection, one current fragment, compact run head when non-Idle, and the dynamic native account only for User viability. It does not load funding state, admission-resource vectors, unreached Steps, or run payload.

Fanout requires projection presence and later execution revalidates its C6 IDs before semantic mutation, classifies window/cycle terminal state from the projection plus `ActorIdentity`/`ActorHot`, and never reads Step resources, funding, or run payload for ordinary activation. Running/Suspended actors must already carry canonical queue/wakeup placement and only latch/coalesce. Idle actors receive the same computed ready-FIFO or temporal-wakeup placement as generic activation. A durable subscriber-page position permits a compactly preflighted contiguous ordinary prefix to commit without charging a following terminal actor; a terminal actor executes under a separate scalar cleanup owner, and progress advances only after that branch commits. No second readiness queue or scheduler is introduced.

A candidate is conforming only if every duplicated field remains an explicitly derived projection with C6 as semantic source, one generation owner, transactional drift prevention, and fail-closed stale-generation tests.

## Controls

- `Controlled variables`: C6 tail chunks; Step and Task representation; Actor IDs and page size 64; subscriber page occupancy; trigger/feed; one-Step short Contract; lifecycle state; queue/wakeup capacities; 20% fanout envelope; block Weight; database backend; benchmark tool; 50 steps/20 repeats; B8/P32 tuple relation; production Weight template; Rust/SDK line.
- `Changed variables`: Candidate A adds one fixed activation-projection key, co-locates Step resources with existing C6 fragments, splits mutable `ActorRunHead` from immutable `ActorRunPayload`, adds one bounded dirty-page position, and introduces compact ordinary cohort plus disjoint scalar terminal owners; `ActorIdentity`, `ActorHot`, authored Contract semantics, and funding state remain unchanged.
- `Confounders`: Generated models remain branch-specific rather than one monolithic fanout call. Queue, wakeup, coalesced, branch probe, terminal, exact fault record, and fault clear have disjoint owners; deterministic tests hold branch selection, rollback, retry pacing, and terminal precedence constant.

## Result

Required raw measurement and production handoff are complete for B8 and P32: renewed five-sample W-S1 and W-FP, all eight fanout/control owners, maximum lifecycle and Opening, compact certificate geometry, semantic parity, dispatchability, production Weight, metadata, ABI, generated control-plane evidence, and matching Wasm. ## Interpretation

The binding dimension is P32 ordinary fanout ProofSize because it determines discrete service under the fixed component-wise 20% envelope. Including the separately measured enlarged-fault base, branch probe, ordinary maximum, and reserved fault Weight admits three pages (`3 × 310,233 + 1,629 = 932,328` ProofSize) and rejects a fourth; candidate A therefore restores P32 service `2 → 3` without changing the envelope. Exact B8/P32 proof/read/write identity across every ordinary branch shows this is structural rather than host-latency noise.

Candidate A is not globally Pareto-dominant: B8 W-FP proof rises `0.68%`, short C6 state gains 11 bytes, and historical B8 close RefTime rises `8.15%` because lifecycle owns one derived projection. These costs are non-binding: B8 service remains three pages, W-S1 has no new key/read and remains within ±5%, and maximum P32 lifecycle Weight is only `857,805,000 / 81,886` against the component-wise dispatch envelope. In exchange, P32 W-FP proof falls `8.87%`, RefTime falls about `93%` against generic activation, and fixed service returns to three pages.

Semantic validity is supported by exact generic/compact classification parity, canonical queue/wakeup post-state equality, durable retry pacing, rollback-bound fault identity, stale-topology closure, and profile semantics. Production compaction removed admission-resource duplication; renewed P32 Weight, metadata, ABI, control-plane evidence, tests, and matching Wasm converge. Under the predeclared binding-dimension criterion, candidate A is accepted and shipped as the P32 runtime geometry.

## Decision

Accepted and integrated. Candidate A is the physical compact Observation activation baseline because it wins the binding P32 ProofSize/service dimension while preserving semantic parity, short-FIFO topology, three-page B8/P32 service, and maximum fit. Its B8 lifecycle/byte overhead remains an explicit non-binding tradeoff. Candidates B and C remain rejected. Complete renewed handoff evidence authorizes and now backs the production P32 binding.

## Validity

- `Establishes`: Candidate A restores three-page P32 service with ceiling-invariant ordinary branch structure, preserves short-FIFO topology and semantic parity in the measured matrix, and fits maximum P32 lifecycle dispatch component-wise.
- `Does not establish`: Release readiness, live-chain throughput, or fanout throughput beyond the fixed reference envelope.
- `Known limitations`: The complete generated handoff establishes the P32 physical/runtime contract only; actual-current branch fee settlement and broader atomic control ownership remain separately tracked work.
- `Invalidation triggers`: Changes to activation semantics, ActorHot/Contract/admission/funding/run layout, page size, fanout envelope, queue/wakeup topology, Weight template, toolchain, or benchmark fixtures require baseline review.
- `Residual qualitative insight`: A fixed page Weight can remain ceiling-invariant only when every reachable activation branch either uses compact bounded authority or has a separately admitted owner before mutation.
