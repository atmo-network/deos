## Decision Question

Can caller-local authoritative values remove an immediate duplicate read without weakening freshness or error order? O1–O3 decide the closed canonical head-advance candidate. The independent O4–O6 comparison asks whether Pipeline collection can reuse the fee just derived from its own current Contract Head instead of loading that Head again before any callback; it does not reopen O3 sampling.

## Context and Candidates

- `Current architecture`: `consider_service_head` Gets Header, Node and Process and validates them. `advance_service_head` immediately repeats all three Gets without an intervening callback, write or host effect; Idle and defensive advancement repeat Header and Node. This is not the earlier discovery before Task execution: each advancement must still start a new fresh inspection after any fee/adapter/callback.
- `Hypothesis`: A private bounded return value can carry these same freshly validated records directly to the writes within that call, removing three retained-advance Gets and two Idle/defensive Gets with no new reads, clone, allocation, key or authority cache.
- `Materiality`: At least the predicted repeated Gets disappear in the retained H1 Step and negative controls, with all other observable workflow truth unchanged. Physical selection additionally needs matched whole-owner timing or a complete-turn resource improvement; logical deletion alone does not prove CPU, PoV, fees or capacity.
- `Controlled / changed variables`: Only same-call loaded-value plumbing changes. Keep semantic writer, storage layout, ring, Q1/FIFO/B+1, prices, workloads, compiler and host fixed. This does not reopen EXP-001's frozen architecture or admit its marker-placement proposal. The closed O1–O3 candidate set is exactly A and B; no header-Put elision, cross-call context reuse or class-pricing change is bundled.

## Interpretation

The mechanism really removes repeated logical reads and speeds its direct advance helper in this finite fixture. The complete Service point estimate is favourable but not accepted under the frozen uncertainty rule; this is neither proof of no benefit nor evidence of a release speedup. The slightly higher probe medians also forbid calling the loaded-return abstraction free. All distinct keys remain, and the scaffold dominates H1 omissions. None of these dimensions may be collapsed into a global multiplier. The Pipeline candidate removes one read per nonzero User collection invocation, not per Step, retry or Actor consideration. O6 confirms the single omitted SDK repeat but not a whole-Service gain. Unchanged controls also shift unfavourably, so a causal CPU regression is unproven; the predeclared selection failure still suffices to keep A4.
