## Decision Question

Does the production nonzero-Step User Opening path select a qualified inclusive Control owner for its Pipeline collection and settlement work, rather than relying on a System-derived minimal owner without demonstrated coverage?

## Governing Specification

- `Owners`: `template/pallets/actors/docs/specification.en.md` and `docs/actors-resource-policy.specification.en.md` retain independent fee owners, complete Weight accounting, admission/actual containment and transactional settlement.
- `Accepted input`: [EXP-0031](./EXP-0031.md) qualifies inclusive User Opening collection ownership; [EXP-0062](./EXP-0062.md) independently qualifies Action collection. Their scoped measurements are not invalidated by this binding question.
- `Frozen invariants`: Preserve C1, class-neutral FIFO, immutable cutoff, Q1, causality, fee semantics, custody neutrality and independent committed-Step durability.
- `Boundary`: Correcting a coverage/selector defect is not a G8 optimization or permission to change economic semantics. A semantic conflict must return to its specification owner.

## Context and Hypothesis

G6 funded-User inspection found that a real one-Step Manual `StopCycle` User pays a nonzero Pipeline fee, while its full-block and Prepass Control equal the System counterpart. The baseline classification witness was produced during EXP-0066's permitted smallest independence check; detailed evidence is transferred here, not duplicated in the integration Leaf.

`RuntimeStepControlWeight::actual_control_weight` selects `scheduler_inner_opening_complete_min(0)` for this context. That minimal benchmark is System-derived. Its arguments do not carry Actor type, and `StopCycle` has neither an Action collection allowance nor an invocation receipt, so those independent owners cannot distinguish this User execution. `scheduler_paged_execute_opening_max` appears in the control-model metadata and a maximal admission branch, but not in this minimal actual-settlement branch. Its presence in the model is not proof that this User execution settles through it.

The hypothesis is that a class-qualified inclusive settlement can restore the accepted ownership contract without counting overlapping source/collection work twice. Identical charged Weight is a coverage warning, not by itself a numerical underweight proof: existing envelopes may overprice other work. The release-relevant issue is the missing demonstrated User-domain binding, not a claimed measured RefTime or ProofSize shortfall.

### Admitted Funding-Policy Header Counterexample

`full_executive_user_completion_header_domain_witness` constructs two independent reference-genesis native states. Both use public Mutable User creation at block 0, a prefunded prospective slot-0 sovereign, ordinary signed Manual readiness at block 1 and a full Executive block 2. The fixture never rewrites Actor authority or ages a control cell. The only Contract difference is `OwnerOnly` versus a full 16-address `SignedAllowlist` containing the owner; both retain one unpredicated StopCycle, no window/auto-close, no tail, no tracked funding and Persistent completion.

The reconstructed context follows `execution_step_control_weight_context` and is independently checked against the stored first-Step maximum through the production provider. It is source-derived evidence, not instrumentation of live call arguments. Context order is cursor, steps-in-fragment, tail chunks, predicate evaluation units, Opening snapshots, Opening predicate results and funding snapshot upper bound.

## Interpretation

Do not confuse fee collection correctness, actual Weight remaining below its reservation, and coverage of the work performed. They are separate claims. Earlier primitive/inclusive reference measurements remain valid within their original scopes; an internally consistent generated artifact bundle does not by itself prove that a live selector uses the qualified User owner.

## Decision

Accepted. Select the inclusive scalar binding: EXP-0069 H16 at zero tails and EXP-0094 T16 at positive tails, conservatively shared by System/User because Actor class is absent from the stable context. Admission and actual settlement use the same generated owners; no overlapping charge or new context field is added. EXP-0095 supplies exact binding convergence. C1 remains frozen.
