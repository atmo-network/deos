## Decision Question

Do EXP-0120–EXP-0134 compose into one bounded production-capable physical architecture with exact state owners, carrier encodings, transition protocols, wake fallback, cleanup and resource boundaries, and which empirical and executable gates remain before N5.4 can close?

## Governing Specification

- `Exact section`: `BACKLOG.md` N5.4 and N6.5; `template/pallets/actors/docs/specification.en.md` §2.3; EXP-0120–EXP-0134.
- `Invariant`: One current Actor generation owns one canonical process and exactly one residence or terminal cleanup authority. Every selector, transition, callback, refusal and retained byte has bounded authority; custody and effects remain independent; no legacy scheduler can publish service.
- `Reopen trigger`: A selected child decision conflicts in composition, one legal transition needs a second service authority or unbounded search, an unsupported host path silently loses wake completeness, or implementation proves a selected encoding/bound impossible.

## Context and Hypothesis

- `Current architecture`: Fifteen accepted current-lineage Leaves select initial process geometry, discovery, return policy, Park evidence, negative-work admission, carriers, round protocol, lost-wakeup protocol, residence transfer, lifecycle, cleanup, collateral, old-path removal, resource ownership and supported-domain soundness. The shipped runtime remains legacy.
- `Reason`: A collection of compatible local decisions is not yet a compact physical architecture. N5.4 needs one owner map and composition contract without pretending that design records supply runtime tests, generated Weight or N6.5 residency/churn measurements.
- `Hypothesis`: The selected Leaves compose around a stable generation-bound process discriminator, one actor-keyed intrusive Live/Pending ring, retained C32 deadline pages and paged min-heaps, exact dependency registrations, immutable block rounds, transactional residence exchange and sealed cleanup manifests.
- `Materiality`: Freeze one complete physical design and its exact remaining gates. Do not claim residency benefit, break-even, production cost or release closure before N6.5 and implementation-generated evidence exist.

## Result

The fifteen selected current-lineage Leaves compose into one bounded physical model without an identified ownership or protocol contradiction. Canonical process state remains separate from occupancy-scaled ring, deadline, Park and cleanup indexes.

| Physical owner | Selected content and bound |
| --- | --- |
| `Process[ActorId]` | One current generation, accepted plan, typed status, sparse run/current basis, residence discriminator, Q1 and reverse handles; carriers contain no authoritative process copy |
| `ServiceHeader` | One global Live/Pending count, persistent next-encounter cursor and immutable block-round identity |
| `ServiceNode[ActorId]` | One per Live/Pending process: generation, previous/next `ActorRef`, kind, eligibility and considered markers; fixed reference payload is 41 bytes plus concrete round widths |
| Deadline substrate | `Option<ActorRef>` is 17 bytes; one C32 slot vector is 544 bytes plus prefix/page metadata; paged min-heaps index every nonempty Block/Tick/review key without deadline-range scan |
| Park ownership | One process-owned generation/plan certificate plus bounded exact-source pages/reverse handles; incomplete host domains also own deterministic timed review |
| Cleanup/resource ownership | One sealed manifest and atomic phase cursor per retired generation; retained-byte hold and terminal bond/classed debt remain separate from dispatch Control and effects |

`ActorRef = (actor_id: u64, generation: u64)` is 16 fixed SCALE bytes. These are child structural maxima, not trie or production-cost measurements; concrete round/revision widths and encoded `Process` maxima remain generated implementation evidence.

The composed plan is notification/deadline/manual → bounded source and generation check → coalesced Pending → complete check admission → current typed reads → Park/Sleep on false or staged Live at B+1 on true → round/generation/Q1/current revalidation → complete transition/effect reservation → callback → callback-visible revalidation → actual effect settlement and one process/residence commit. Acknowledgment covers only the evaluated revision.

| Structural operation | Bounded plan and visible replacement cost |
| --- | --- |
| Retained Live Step | Update process/run/Q1 and advance to stored next; still pay header/guard/current selection/effect work, but allocate/delete no node or successor ticket |
| Admission/unlink | Insert before cursor with neighbor patches; arbitrary removal reads exact reverse handle, patches at most two neighbors and repairs cursor, including singleton/head/interior/tail suffixes |
| Residence movement | Stage exact destination before one discriminator linearization and source release; full destination preserves source; deadline movement touches one C32 page plus bounded heap path |
| Wake | Traverse a fixed revision/page target, hand off durable Pending and acknowledge only covered revision; duplicate, stale, refused and interrupted suffixes remain paid |
| Retirement/cleanup | Revoke first, exact-unlink, seal manifest and consume presecured debt class; each cleanup turn deletes/proves one generation-tagged quantum and advances one fixed cursor |

Per-Step Ready dequeue/removal, successor ticket allocation/publication, Ready-page/ticket-locator growth, waiting-primary process copies and old latch rearm are structurally eliminated. This is not a net-benefit claim: N6.5 must establish their frequency, all replacement costs and the whole-service break-even. Runtime/model/property and generated evidence remain absent, so N5.4 is narrowed but not closed.

## Interpretation

The architecture removes the old ordinary successor-publication topology by keeping eligible continuations resident, but it does not make execution a one-header-write operation. Ring neighbors, immutable-round guards, current reads, callback revalidation, deadline/index movement, negative checks and cleanup remain real costs. Event-only parking is a host capability, not a generic promise. Production capability follows only after implementation and generated extrema prove the selected design and N6.5 establishes its whole-service residency tradeoff.

## Decision

Accept the composed subject as the N5.4 physical design baseline: one stable current-generation process; one actor-keyed intrusive doubly linked Live/Pending ring; retained C32 deadline pages and paged min-heaps for Sleep/Park review; exact revisioned dependency registrations; immutable block rounds; destination-first transactional residence; typed generation-safe lifecycle; sealed cleanup manifests; and separate generated Control, effect, settlement, collateral and debt owners. Outcome class: research result. Finite stopping basis: every selected child obligation has one composition owner and no design contradiction remains. N5.4 exit remains open on N6.5 residency evidence and runtime/model/property/generated proof.

## Rejected Alternatives and Tradeoffs

| Candidate | Decision | Evidence-backed reason |
| --- | --- | --- |
| Treat selected Leaves as implicit architecture | Rejected | Hides cross-boundary ownership and open empirical/executable gates |
| Claim residency win from removed operations | Rejected | Frequency and replacement costs are unmeasured until N6.5 |
| Keep old Ready/waiting fallback | Rejected | Creates a second service/liveness and resource owner |
| Copy process state into ring/deadline/Park entries | Rejected | Duplicates canonical authority and generation freshness |
| Universal event-only Park | Rejected | Independent hosts may not control every mutation domain |
| Defer concrete carrier or cleanup encoding | Rejected | 0.7.27 requires one bounded physical model, not abstract tuning debt |

The selected design trades extra direct neighbor writes, round markers, reverse handles, revision bookkeeping and mandatory cleanup capacity for bounded arbitrary control, stable encounter order, honest wake completeness and removal of ordinary successor publication. Whether that trade is an empirical improvement remains open.

- `Does not establish`: Runtime realization, executable soundness, generated coefficients/ProofSize, final SCALE maxima, production Wasm, N6.5 benefit/break-even, whole-service materiality or release readiness.
