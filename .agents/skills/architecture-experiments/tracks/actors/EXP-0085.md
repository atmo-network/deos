## Decision Question

Can the native signed-demand charged-owner ledger be bound to the retained signed production-Wasm states rather than only matching resource distributions?

## Governing Specification

- `Owners`: `docs/actors-performance-assurance.specification.en.md` (production evidence and target); `docs/actors-resource-policy.specification.en.md` (component-wise accounting); `template/pallets/actors/docs/specification.en.md` (fee and execution ownership).
- `Invariant`: Real valid signed dispatch, exact artifact identity, separate User transactions and User Actor fee authority; frozen C1 FIFO/Q1 and causal floor remain unchanged.
- `Reopen trigger`: Demonstrated semantic conflict, not signature randomness or an identity-linkage gap.

## Context and Hypothesis

- `Current architecture`: Native Executive replay reconstructs the System workload ledger while signing fresh user remarks.
- `Hypothesis`: Equal aggregate resource observations can be accompanied by exact signed-state linkage. Header mismatch is the smallest falsifier of reuse by header identity.
- `Materiality`: Evidence sufficiency for parent O16, not an additional throughput profile or optimization.

## Statistical / Variance Notes

Fresh signatures confound equality across independently authored runs, which is why the accepted campaign compares no cross-run headers. Each signed body is instead retained in its authored block and replayed against the same pre-state through exact Wasm. No host-timing conclusion is drawn.

## Result

The historical 0/100 cross-run header mismatch remains a valid warning against aggregate substitution. The current campaign removes that confounder by replaying each freshly signed native-authored block itself through the exact accepted Wasm and matching state/proof identity for all 100 blocks.

## Interpretation

Resource coincidence supports scoped native accounting, not identical signed-Wasm states or instrumented phase counts. No physical candidate comparison/Pareto winner is established.

## Decision

Accepted for EXP-0066 O16. Select the current 100-block signed native-authoring plus exact-Wasm replay cohort as sufficient state linkage. Preserve the historical mismatch as a rejected aggregate-equality shortcut; do not infer User Actor fee coverage because workload Actors remain System Actors.

## Rejected Alternatives and Tradeoffs

- `Aggregate-equality shortcut`: Rejected as state-identity proof by the explicit header mismatch.
- `Unsigned substitute`: Not admitted; the retained evidence uses real signed calls.
- `User Actor inference`: Rejected; the workload Actors are System Actors.

## Validity

- `Establishes`: Current-production signed-demand accounting linked block-by-block to exact Wasm execution, authored headers, post-state roots and proof-only verification.
- `Does not establish`: An on-chain rejection/fee for the withheld candidate, User Actor fees, the 10,000-Cycle target or release acceptance.
- `Known limitations`: Workload Actors are System Actors; the next candidate remains preflight-withheld after User ProofSize exhaustion.
- `Invalidation triggers`: Changed signer/body identity, source, Weight, runtime, workload or accounting method.
- `Residual qualitative insight`: Identity and aggregate equality are distinct proof surfaces.
