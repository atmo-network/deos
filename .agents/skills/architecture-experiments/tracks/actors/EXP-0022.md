## Decision Question

Does exact one-third Actor Control with the Shared remainder split equally between Actor effects and user dispatch materially improve the accepted 30/35/35 baseline without unacceptable economic-capacity loss?

## Governing Specification

- `Exact section`: `docs/actors-resource-policy.specification.en.md` → `2. Resource Algebra` and `3. Economic Zipper`.
- `Invariant`: Preserve component-wise accounting, strict FIFO, Q1, class neutrality, work conservation, deterministic remainder ownership, and at least approximately one third each for Control, Actor effects, and user dispatch.
- `Reopen trigger`: Actor Control above one third is excluded; all further throughput gains must optimize execution inside the one-third envelope.

## Context and Hypothesis

- `Current architecture`: EXP-0006 selected fixed 30% Control and equal 35%/35% Shared base turns.
- `Reason`: One third is the declared maximum Control share and provides a symmetric DEOS resource boundary.
- `Hypothesis`: Raising Control from 30% to floor one third yields a smaller but measurable traversal gain while retained one-third effect/user turns remain sufficient.
- `Materiality`: Require at least 5% more traversal throughput than 30/35/35 with zero semantic failures and exact base-turn preservation.

## Result

A1 completes W1/W2 at block 679 versus A0 block 746 and W3 at block 679 versus A0 block 765. Every continuous user dispatch remains admitted and W3 has zero failed Steps. W4 exact partition and borrowing tests pass.

## Interpretation

A1 clears the 5% materiality threshold in every throughput workload. The gain is 9.9% for Transfer and 12.7% for mixed effects while each guaranteed effect/user base turn falls only 4.76%. Equal thirds also establishes the declared hard Control ceiling; remaining throughput pressure transfers to execution-authority geometry.

## Decision

Accept A1 as the production resource partition. Actor Control is floor one third of schedulable Weight; Shared Economic owns the remainder; Actor and user base turns split that remainder floor/remainder. No later optimization may increase Actor Control above one third.

## Validity

- `Invalidation finding`: The 0.7.25 W1/W2 per-block collector reproduced first-population coverage at block `679` but found `optional_actor_work_halted = true` and no current-block `FinalizedBlockResourceTelemetry` in every measured saturated block; the runtime `on_finalize` contract would therefore reject these blocks. The historical completion counters are not valid production-block throughput evidence.
- `Retained observation`: Blocks `2..=679` contain 10,004 committed one-Step dispositions over 678 measured blocks, mean `14.7552`, because four Actors recur before complete population coverage; the old `10,000 / 679 = 14.73` quotient was neither exact committed-Step throughput nor an eligible-block mean.
- `Residual qualitative insight`: W4 still proves the equal-thirds arithmetic, and the normative resource policy independently fixes one third as the maximum Actor Control share. The A0/A1 completion comparison may guide diagnosis but no longer supports a production-performance acceptance claim.
- `Successor evidence`: The 0.7.25 repair adds a dedicated component-wise control meter, withholds generated Drain/finalization control before Prepass service, and proves current-block telemetry plus successful `on_finalize`. Repaired W1/W2 cover 10,000 Actors at block `1099` over 1,098 measured blocks with exactly 10,000 committed Steps/Openings/completions, mean `9.1075`, p50 `7`, p95/p99 `21`, range `0..=21`, zero failed Steps/closures/Drain Steps/halts, and Actor Control as the exact stop reason in all 1,098 measured blocks. The stable report includes the complete Step histogram and finalized domain counters. A 10,000-Actor control-only `StopCycle` run has the exact Transfer histogram with zero effect Weight and Actor Control as all 1,098 stop reasons, directly falsifying effect capacity as the baseline binding owner. Proof-saturated Transfer, zero-effect `StopCycle`, and Router-backed `SwapOut` W2 legs each submit 77 successful signed remarks per block, consume `673,442 / 676,150` User ProofSize with 2,708 remaining, and leave every Actor counter and histogram bin unchanged; RefTime saturation remains pending. This valid successor baseline does not retroactively restore the invalidated comparison. Regenerated Weight is `ac0ff2ca56fef3177b8aa73f914d021559afa059e3edc3026fcee19550671c71`, production Wasm is `5bd3271940df297201a40ce5d25db25c827d4fb1d3c1841bce050c220ee7042d`, and metadata is `78e21e8ed661ffac621115214786b416d9bc030e443456531956ef1f27120b0e`; exact commit/tree binding remains pending.
