### Deciding Observation Cleanup Envelope

The retained reference-Wasm profiles attain the declared physical alternatives through ordinary admission, publication, fanout and close. The dense-page profile clears one entry from a surviving full subscriber page and fills an existing free page. The middle-page profile deletes the target subscriber page between two full neighbours and repairs the live dirty-fanout page cursor. The last-subscriber profile directly attains the smallest falsifier: it removes the current middle dirty feed from a three-feed list, repairs the list cursor to the successor and allocates a new free page while preserving the preceding full page.

No one retained profile dominates every resource coordinate. The complete reference Observation authored-close owner therefore selects the component-wise envelope `442,102,000` pre-database RefTime, `18,474` estimated ProofSize, 28 reads and 29 writes. RefTime and writes come from `scheduler_inner_zero_step_user_observation_feed_close`; estimated ProofSize comes from `scheduler_inner_zero_step_user_observation_unlink`; both require 28 reads. Under the pinned reference RocksDB charge, the resulting RefTime is `4,042,102,000`. This is a conservative branch envelope over complete inclusive atoms, not an additive sum or a claim that the coordinates were jointly attained by one profile.

The envelope already includes canonical primary consumption, one Pipeline collection, applicable User hold reconciliation, authored terminal cleanup, subscription/feed unlink and free-slot publication. Maximum and actual select this one Observation authored-close owner; none of those operations may be charged again. The retained nonterminal Observation profile stays a separate persistence owner. Outer Ready/Waiting source and heap work, unrelated terminal paths, complete admission composition and generated-file regeneration remain with EXP-0058, EXP-0063, EXP-0064 and EXP-0065 respectively.
