## Decision Question

Does retained `close_actor` component-wise bound an ordinarily admitted signed User Suspended in a Block retry Deadline while its independent Tick Trigger owns the minimum key of a full Tick index?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` RetryLater, canonical Deadline residence, Actor close and custody; `docs/actors-resource-policy.specification.en.md` terminal admission.
- `Invariant`: One signed close atomically removes the exact Block retry, independent Tick Trigger, retained Run and hold, leaving sovereign custody unchanged and no successor publication.
- `Reopen trigger`: Ordinary funded retry cannot retain the measured two-clock authority or close has a non-neutral custody side effect.

## Context and Hypothesis

- `Current architecture`: `detach_actor_publication_inner` chooses one Block Deadline residence; independent `TriggerDeadlineHandles` removal repairs the Tick index, then `cancel_run_internal_loaded` deletes the suspended Run without re-publication.
- `Reason`: EXP-0140 measures Service-resident close and EXP-0139 measures Parked release. Neither prices this separate live residence selector.
- `Hypothesis`: A complete suspended Block Deadline + deep Tick close exceeds the retained `close_actor` in either RefTime or ProofSize.
- `Materiality`: A reachable single-component excess blocks production terminal dispatch, cleanup reserve and Pipeline fee acceptance.

## Result

W1's `83,820` ProofSize exceeds same-Wasm/retained `81,886` by 1,934 bytes but its complete RocksDB RefTime narrowly fits. W2's deep Block retry plus deep Tick close measures `2,927,514,000 / 128,352 + 90 reads/70 writes`, above retained `969,972,000 / 81,886 + 69/60` in both dimensions. On W2's Wasm, the selected EXP-0139 Parked both-deep close is still larger in each dimension.

## Interpretation

Block retry Deadline and independent Tick Trigger may coexist on one Suspended User with both indices deep, and removing both plus cancelling the Run uses one terminal finalizer. W2 is selected component-wise below matched Parked W5 but is a distinct canonical residence, not an extra Weight charge. Complete terminal containment must cover both without summing full closes.

## Decision

Measured W1 ProofSize and W2 RefTime/ProofSize rejections of retained `close_actor`; no production Weight or fee is rebound until all terminal selectors and adjacent owner groups close. Outcome class: research result; remain open for full component-wise domination.

## Validity

- `Establishes`: Real signed Suspended Users with local Block/deep Tick W1 and concurrent deep Block/deep Tick W2; retained ProofSize fails both, RefTime fails W2, custody survives both.
- `Does not establish`: Every deep Block tail/page geometry, all Run/cause or indexed detector cleanup branches, complete RefTime/ProofSize terminal envelope.
- `Known limitations`: W1 Block retry index is local and its same-Wasm RefTime margin nearly zero; W2 splits the guard population without forcing either clock's tail to one entry. Matched Parked W5 domination is selected, not universal.
- `Invalidation triggers`: Changes to retry admission, temporal topology, benchmark fixture, runtime DB model or source identity.
- `Residual qualitative insight`: DB I/O differences can offset a larger measured RefTime base; proof remains independently binding.
