## Context and Hypothesis

This required question was already uncovered by the pre-fission phase/domain map. It is allocated because its physical owner can be decided independently; no speculative optimization or new semantic requirement is introduced.

The existing source already exposes collection as a distinct ledger primitive and a distinct selector input. This experiment measures that primitive on the current reference benchmark Wasm and tests the selector and complete ledger trace without changing runtime semantics or installing a partial generated Weight file.

## Baseline and Candidates

The candidate is the existing isolated `fee_collection` benchmark and the existing `RuntimeStepControlWeight::action_collection_allowance`: reserve one generated collection owner for every non-`StopCycle` Step, settle it exactly when an invoked User Action has a nonzero total fee, and keep it independent of Pipeline collection and the invocation receipt. The zero owner remains selected for `StopCycle`, System execution and noninvocation.

## Result

The reference-Wasm primitive produces a generated `47,703,000 / 6,196` owner plus two native-account reads and writes. Fresh package ledger/receipt coverage and runtime selector regressions pass over Opening, Running and Suspended. The selected allowance is distinct from Pipeline collection and the invocation receipt, and the actual path can collect it only once for an invoked, nonzero-fee User Action.

## Interpretation

The isolated native-ledger transfer is the complete physical Action collection owner for the reference runtime. Phase does not alter that primitive; phase-specific base Control work remains outside it. `action_fee_collected` and `task_effect` are separate selector facts, while Pipeline collection has a separate call site and receipt. This accepts ownership and the measured primitive without claiming that the stale complete Weight file is a release artifact.

## Decision

Accepted for the reference native-ledger domain. Select exactly one generated `fee_collection` owner for invoked User Actions with nonzero total fee; select zero for System, noninvocation and `StopCycle`. Preserve Pipeline collection and invocation receipt as independent owners. EXP-0065 must regenerate the complete production Weight identity.

## Rejected Alternatives and Tradeoffs

Reject folding Action collection into the invocation receipt: System can emit a zero-fee invocation receipt without a ledger transfer. Reject folding it into Pipeline collection: Running and Suspended Action attempts collect without Opening, while Opening can charge both independently. Reject treating the old installed 47,004,000 ps coefficient as current evidence: the fresh generated primitive is 47,703,000 ps. Do not patch that coefficient manually; complete regeneration belongs to EXP-0065.
