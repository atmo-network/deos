## Decision Question

Which unique-owner Step-tail representation reduces nonterminal current-Step ProofSize below the EXP-0025 allowance without making maximum Contract lifecycle, reconstruction, or projection non-dispatchable?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` → `Hot/Cold Physical Contract`, `Complete Projection`, and `Active Execution State Geometry`.
- `Invariant`: One semantic ordered Contract has one immutable physical body owner per Step, reconstructs exactly, loads only the current execution representation, fails closed on stale or missing fragments, and preserves atomic create/update/close.
- `Reopen trigger`: A semantic defect or impossibility shared by all bounded unique-owner representations reopens the Specification; a performance loss rejects only the candidate.

## Context and Hypothesis

- `Current architecture`: Step 0 is uniquely inline in `ActorContractHead`; Steps 1..31 and their resource envelopes are stored in four-Step `ActorContractTailChunk` values.
- `Reason`: EXP-0025's semantically exact 100-Actor middle Transfer projection is `6,876.52` estimated proof/Actor against the `6,361` allowance. Its generated slope is `6,553`; the initial tail maximum annotation is `6,545`, while C1/C2 controls now identify complete current-plus-successor authority as the actual owner.
- `Hypothesis`: Capacity-only and one-Step fragmentation were falsified first. C3 then tested whether one current payload owner plus shifted Contract-bound successor resources could remove at least `515.52` proof/Actor; exact state-hold reconciliation falsified that residual hypothesis.
- `Materiality`: The primary gate is exact: grouped `3×32 + 4` middle Transfer must be at most `636,100` estimated proof. Every semantic divergence, added hot mutable owner, or non-dispatchable maximum lifecycle branch rejects a candidate. Among passing candidates, compare component-wise RefTime, ProofSize, reads/writes, retained bytes, and Wasm size without an arbitrary percentage floor.

## Benchmark Class, Workloads, and Criteria

- `Benchmark class`: Production-Wasm FRAME benchmark, exact retained-state profile, and deterministic differential/fault tests.

| Workload | State/population geometry | Hot/cold assumptions | Purpose |
| --- | --- | --- | --- |
| W1 | EXP-0025 three-Step Running cohort, Step 1 Transfer, `n=1..32`, grouped `3×32 + 4` | Current tail cold; Ready source and successor chunks distinct | Primary `6,361` proof gate |
| W2 | 32-Step create/update/close and state-hold reconciliation | Maximum bounded body cold | Lifecycle dispatchability and write amplification |
| W3 | Current-Step loads at first and last slot of every tail unit | Selected tail cold | Boundary-independent proof/read set |
| W4 | Exact 0/1/2/3/32-Step reconstruction and projection | All owned fragments cold | Semantic completeness and reconstruction cost |
| W5 | Missing, swapped, stale-hash, and duplicate-fragment fixtures | Adversarial bounded state | Fail-closed ownership evidence |

- `Metrics`: Generated RefTime and estimated/measured ProofSize; reads/writes; grouped 100-Actor cost; retained encoded bytes at 1/3/32 Steps; lifecycle dispatch fit; benchmark and production Wasm size; exact differential state/events/fees.
- `Statistical method`: Sequential compiled-Wasm RocksDB runs with 1,024 MiB cache, 50 steps, 20 repeats, and no sample removal. Retain generated coefficient standard errors. Deterministic encoded size and semantic postconditions have no noise band.
- `Acceptance criteria`: Exact A0/C1 semantics; grouped W1 estimated proof `<=636,100`; every maximum W2 call fits its production component-wise envelope; W3 has no unreachable-tail reads; W4 reconstructs exact bytes; W5 fails closed; and no duplicate mutable or semantic owner exists. Select from the conforming nondominated set by W1 proof, then lifecycle RefTime, retained bytes, Wasm size, and simplicity.
- `Rejection criteria`: W1 above allowance, semantic/event/fee drift, unbounded scan, stale or duplicated authority, current execution reading unreachable tails, or any maximum lifecycle/projection branch exceeding its dispatch envelope.

## Statistical / Variance Notes

B0, C1, C2, and C3 each use a separately rebuilt matching benchmark Wasm with sequential 50-step/20-repeat runs and no sample removal. C1 keeps the exact B0 proof model `8,088 + 6,553n` because a three-Step Contract encodes Steps 1 and 2 into one actual two-Step tail value under both capacities. C2 changes the model to `8,088 + 6,694n` and adds one read per Actor because full Running reconstruction loads two one-Step values. C3 changes it to `8,106 + 6,779n`: it reads one compact payload, but `exp0025_reconcile_single_step_state_hold` independently reads the canonical tail to reproduce exact immutable contract-body hold bytes. Generated coefficient standard errors remain below the 2% materiality floor; all ProofSize failures are exact model outputs, not timing noise.

## Result

C1, C2, and C3 preserve the focused three-Step A0 differential but all fail the primary W1 gate. C1 is proof-identical to B0 and slightly slower; C2 raises grouped estimated proof to `7,017.52`; C3 raises it to `7,103.24` because exact state-hold reconciliation retains the canonical tail read alongside the compact payload. No candidate is selected.

## Interpretation

The initial maximum-value attribution was incomplete. The three-Step workload stores only two tail Steps, so B0 and C1 encode the same actual value and proof despite different `MaxEncodedLen`; C2 splits that value but full reconstruction reads both keys. C3 removes tail loading from Running control-context reconstruction, yet the exact User state-hold owner still reads canonical tail bytes and makes the composed path worse. Therefore Step representation alone cannot clear the gate under the retained hold algorithm. This does not implicate FIFO, Q1, or frame ownership, and combining a separately controlled state-hold optimization would violate EXP-0004's changed-variable boundary.

## Decision

Reject C1, C2, and C3 at W1 before lifecycle measurement. Retain B0 and mark EXP-0004 Rejected: no Step representation candidate clears `6,361` without changing the separately owned exact state-hold reconciliation mechanism. Candidate code is deleted and EXP-0025 B0 source/Wasm are restored.

| Change C32 FIFO frames first | Rejected as current gradient | W1 slope is owned by `ActorContractTailChunk`, not frame proof |

## Validity

- `Establishes`: Exact B0 proof miss; C1 proof equivalence; C2 regression; C3 regression under exact state-hold reconciliation; and rejection of all admitted Step representation candidates for W1.
- `Does not establish`: A separately controlled state-hold reconciliation optimization, longer-Contract current-Step behavior, production schema selection, or EXP-0025 acceptance.
- `Known limitations`: C1/C2/C3 stop at the W1 three-Step Transfer Contract because each failed the primary rejection gate; W2–W5 were correctly not run.
- `Invalidation triggers`: Contract/Step/resource encoding, 32-Step ceiling, tail chunk size, storage proof model, runtime limits, benchmark method, C32 scheduler geometry, or task/effect profile changes.
- `Later evidence`: The governing assurance audit established that `6,361` is a W1 one-Step allowance rather than an independent middle-Step rejection ceiling, and the DEOS runtime subsequently changed the ceiling-dependent profile from `32/64/128` to `12/24/48`. These changes invalidate the selection claim while preserving the P32 representation measurements as historical constraint evidence.
- `Residual qualitative insight`: Current-Step locality is bounded by the maximum proven storage value, not only by the number of logical Steps consumed.

## Follow-Up / Next Gradient

```text
6,361 target → 6,876.52 middle-Step proof → 515.52 miss
→ two-Step capacity keeps the same actual value and proof
→ one-Step cells add one key/read and regress to 7,017.52
→ complete current-plus-successor payload/resource authority
→ C3 compact payload removes control-context tail load
→ exact state hold independently retains canonical tail proof
→ C3 regresses to 7,103.24 and fails W1
→ reject EXP-0004; retain B0 and named state-hold boundary
```

- `Eliminated hypotheses`: Frame chunk size is the current W1 slope owner; measured proof may replace estimated production proof; partial decode of one trie value reduces proof; two-Step capacity clears W1; one-Step fragmentation clears W1; compact current payload clears W1 while exact state-hold reconciliation is retained.
- `Remaining hypotheses`: None inside Step representation. A cached immutable contract-body hold component is a separate mechanism and requires its own controlled reopening before it can be composed.
- `Stop condition`: Met. All C1–C3 candidates fail grouped proof `<=636,100`; retain B0 and record `6,876.52` as the exact EXP-0025 blocker under current state-hold semantics.
