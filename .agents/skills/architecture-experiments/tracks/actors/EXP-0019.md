## Decision Question

Which Pipeline Machine pricing strategy best preserves one paid whole-pipeline control quantum over Q1 while each processed Trigger occurrence is charged independently before readiness coalescence, Actions remain pay-as-attempted, and insufficient paid-readiness consumption reclaims only process state—including a zero-Step immutable temporal case?

## Governing Specification

- `Exact sections`: `template/pallets/actors/docs/specification.en.md` → `1.4 Block-Paced Actor Cycles`, `2.2 Class and Mutability`, `2.3 Sovereign Accounts and Identifiers`, `2.4 Lifecycle, Execution Funding, and Terminal Order`, `4.3 State Holds and Fees`, and `6.4 Weight and Fee Derivation`; `docs/actors-resource-policy.specification.en.md` → `4. Admission and Actual Weight`; `docs/actors-performance-assurance.specification.en.md` → `3.5 Minimal User Apoptosis`.
- `Invariant`: Creation, each processed Trigger occurrence, each admitted Pipeline, and each invoked Action attempt are four separate fee owners. Trigger charging precedes setting/coalescing `pending_signal` and remains active while Running/Suspended; Pipeline charging occurs only when Idle service consumes readiness. Production favors one upfront bounded machine charge; future Action fees are never prepaid. Running/Suspended control cannot die economically, Action `FundingUnavailable` follows authored policy, and `CycleAdmissionInsufficient` exists only at Idle Pipeline admission. Apoptosis deletes process state/memberships only; sovereign custody and exact-slot derivation survive. Zero Steps is valid; User Immutable rejects owner destruction.
- `Reopen trigger`: Reopen Specification only if one upfront bounded machine charge cannot represent generated control geometry, current-attempt Action fees cannot remain transaction-local, zero-Step service cannot retain strict FIFO/terminal authority, or minimal cleanup cannot remain custody-neutral. System lifecycle evidence does not reopen User semantics by analogy.

## Context and Hypothesis

- `Current architecture`: A0 classifies User fee-native shortfall at each current Step as `BalanceExhausted` or `FeeBudgetExhausted`, admitting autonomous close cleanup. Close itself is already balance-neutral and deterministic sovereign custody already survives process deletion.
- `Reason`: Current-Step death can destroy a process after earlier pipeline effects commit, while a persistent funding wait retains unbounded-lifetime state. Prepaying future Action effects instead over-couples machine liveness to uncertain economic execution and creates a run balance ledger. Generated bounded control geometry permits one machine charge while each Action remains transaction-like.
- `Hypothesis`: P0 one upfront Pipeline Machine charge removes Running accounting touches and state versus P1 hold/refund and P2 per-Step charging, while preserving paid retry/continuation control. Trigger-family pricing can remain fixed-size and independently charge every processed occurrence, including already-pending busy Actors, without opening duplicate Pipelines; zero-Step temporal service can complete with no Action fee.
- `Materiality`: A1 must contain no economic close inside Running/Suspended, funding-wait state, or future Action-fee reserve. Acceptance requires exact Action fee/failure behavior, custody-root identity, exact-slot recovery, zero-Step immutable temporal completion, and either material P0 hot-path/state/Wasm simplification or evidence strong enough to select another candidate through Specification reopening.

## Result

The exact A0 changed boundary remains captured. A1-P0 has complete generated P32 production Weight, runtime-bound vectors, metadata, benchmark Wasm, and pre-format production Wasm.
