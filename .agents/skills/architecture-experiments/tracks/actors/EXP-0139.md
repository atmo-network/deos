## Decision Question

Does retained `close_actor` component-wise bound one reachable signed User Parked close with maximum balance watches, a Block review Deadline and independent Tick Trigger?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` Actor close/custody and Parked dependency contracts; `docs/actors-resource-policy.specification.en.md` terminal admission.
- `Invariant`: One atomic close removes exactly the Actor's independent Trigger authority, one canonical residence, all registered dependencies, Contract/Run state and hold; custody remains unchanged.
- `Reopen trigger`: An ordinary admitted actor cannot hold the measured two-clock authority or close cannot reclaim it atomically without custody transfer.

## Context and Hypothesis

- `Current architecture`: `detach_actor_publication_inner` selects Parked release, which iterates bounded `DependencyPlans`, removes optional Block review and registration pages, then the common finalizer closes the Actor. Temporal Trigger removal is independent.
- `Reason`: The base `close_actor` benchmark does not establish a maximum for Parked dependency release; the deep Service/Tick close evidence now owned by EXP-0140 exposes a separate ProofSize underbound.
- `Hypothesis`: The retained base coefficient also underbounds a reachable Parked two-clock terminal branch in either RefTime or ProofSize.
- `Materiality`: Any single component-wise underbound blocks dispatch, scheduler cleanup and fee adoption until the complete owner is generated.

## Result

Native benchmark tests and matched benchmark-Wasm close measurements passed for W1 local, W2 near-capacity deep Tick, W3 deep Block review, W4 one-entry-tail Block and W5 concurrent deep-clock geometry. All reclaim Parked plan, episode, review, Trigger and hold without custody transfer; W2 repairs the one-entry Tick tail page, W3 repairs a populated Block index, W4 its one-entry last page and W5 both deep last pages together. W1 exceeds retained RefTime but fits ProofSize; W2/W3/W4/W5 exceed both dimensions.

## Interpretation

Parked bounded registration teardown, optional review and independent temporal cleanup compose in one close. W2 and W3/W4 prove isolated near-capacity Tick and deep Block repairs, respectively; W5 proves one simultaneous deep-clock split without a universal maximum. Neither Parked complete close nor EXP-0140's Service/Tick close may be added to the other: they each include shared finalization. A component-wise final maximum must dominate both and qualify remaining independent terminal selectors.

## Decision

Measured W1 RefTime and W2/W3/W4/W5 RefTime/ProofSize counterexamples reject the retained `close_actor` coefficient for these selected Parked branches. The terminal selector is not closed; no production Weight, cleanup reserve or Pipeline fee is reissued from these diagnostics. Outcome class: research result. Continue only with a reachable missing selector or conservative complete-owner dominator.

## Validity

- `Establishes`: Ordinary signed maximum-watch Parked two-clock close exceeds retained RefTime on W1 and both dimensions on deep-Tick W2, deep-Block W3/W4 and simultaneous W5, independently under nonnegative DB costs.
- `Does not establish`: Universal Tick/Block index maximum, all concurrent population splits, every dependency-source variant, full terminal maximum, or generic package release pricing.
- `Known limitations`: Only balance watches; W2 nearly saturates Tick keys and leaves Block local; W3 fills the Block index while W4 forces its last page to one entry; both leave Tick local.
- `Invalidation triggers`: Changes to benchmark fixture, maximum watchers, admission, Parked release, terminal cleanup or Weight identity.
- `Residual qualitative insight`: A low ProofSize branch can still be the binding RefTime owner due to registration I/O.

## Follow-Up / Next Gradient

```text
terminal close → selected RefTime/ProofSize deficits → Parked registration and deep Tick repair
→ shared close envelope → qualify remaining residence/detector selectors or bounded dominator
```
