## Decision Question

What is the smallest stable hot/cold ownership geometry that supports the current-state vertical slice across resident execution, retry, idle checks, admission, parking, owner update, sweep, and later generation-safe reclamation without copying whole Contracts into membership indexes or making live cardinality scale with the largest historical `ActorId`?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` §2.3 current-state execution, residence, parking, and generation rules; `BACKLOG.md` N2.6 physical exit.
- `Invariant`: One Actor generation owns one mutable process authority. Memberships identify that authority but never copy the Contract or become a second process owner.
- `Reopen trigger`: A focused N3 falsifier proves the partition cannot preserve atomic movement, bounded arbitrary removal, or admission within host bounds; semantics reopen only if no bounded generation-safe representation can implement the specified one-obligation model.

## Context and Hypothesis

- `Current architecture`: The shipped vertical slice moves one whole `ActorControlCell` among Unsignaled, C32 Ready, and C32 Waiting stores, while certified Contract C6 and sparse Run tiers are separate actor-keyed owners.
- `Reason`: N3 needs one initial geometry before carrier implementation. Moving the process with placement couples high-frequency residence churn to identity/lifecycle/admission bytes and rewrites paged neighbors, while Contract and Run partitioning already matches current-Step co-access.
- `Hypothesis`: One stable actor-generation process record plus compact generation-bound carrier references preserves current semantics with less update amplification and no cold Contract decoding on membership traversal.
- `Materiality`: Select exactly one initial family and exclude broad alternatives. Exact carrier bytes and generated resources remain N3.5/N5.2 evidence, not an invented numeric threshold.

### Value and Decoder Geometry

| Owner | Keys per Actor generation | Bounded value evidence | Decoder rule |
| --- | ---: | --- | --- |
| Stable process | 1 | Compact identity, lifecycle, generation, cursor/eligibility, retry/latch, admission/resource, and direct residence handles; exact selected encoding measured after realization | Decode on service/control touch; never embed in membership |
| Contract head | 1 | Current P32 `MaxEncodedLen` ceiling 2,237 bytes | Decode for Step 0, policy mutation, close, or public reconstruction |

| Membership | Bounded references | Actor/physical slot plus non-aliasing generation and carrier-local coordinates; no Contract, process, or Step | Decode compact pages, then resolve one process key |

## Result

The hot co-access unit is mutable process authority, not the Contract. Execution needs one process record, the Contract head, and at most one exact four-Step tail; retries additionally need sparse Run state. Parking, wake, owner update, and sweep churn memberships independently of authored body bytes. The baseline moving whole-cell frames therefore couple unrelated lifetimes. Candidate A satisfies every structural criterion while preserving C6 and sparse Run geometry.

## Interpretation

The stable partition is process / current Step / optional Run. Live/Sleep/Park/Pending are indexes over that process, not state owners. Physical slots must follow configured occupancy, not monotonic Actor IDs, and every reusable slot and cleanup cursor must carry a non-aliasing generation. The result chooses no ring/page encoding and claims no numeric gain.

## Decision

Accepted as a research result and initial design selection: use one stable actor-generation process record, compact generation-bound membership references, sparse Run tiers, and the retained C6 Contract body. Stop after this one family. N3.5 realizes and measures one concrete carrier; N6.2 admits one alternative only if a stated falsifier occurs.

## Rejected Alternatives and Tradeoffs

| Candidate | Decision | Evidence-backed reason |
| --- | --- | --- |
| Moving whole control cell in frames | Rejected as target layout | Couples process writes to page/placement churn and rewrites unrelated frame bytes |
| Whole Contract/current Step in memberships | Rejected | Copies cold authority and amplifies update/close/generation hazards |
| Monolithic Actor value | Rejected | Decodes and rewrites unreachable body/run data on common service |
| Dense historical-ActorId array | Rejected | Physical cardinality diverges from supported occupancy |
| Stable process + compact generation references + C6 | Accepted | Matches co-access and supplies direct generation-safe ownership |

## Validity

- `Establishes`: The sole initial ownership family and the logical key/value/decoder/update map required by N2.6.
- `Does not establish`: Exact carrier, encoded process/reference bytes, generated Weight, throughput, fairness, or Geometry Freeze.
- `Known limitations`: Candidate A remains unimplemented; exact page fragmentation and proof are downstream.
- `Invalidation triggers`: New semantics, an N3 carrier falsifier, changed C6/Run ownership, or inability to encode non-aliasing generations within bounded state.
- `Residual qualitative insight`: Process lifetime exceeds residence lifetime; keeping them physically separate avoids making placement the semantic owner.
