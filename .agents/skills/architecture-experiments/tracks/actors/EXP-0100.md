## Decision Question

Do existing DEX/Router, XCM/message, observation, funding/resource, bounded-queue and adapter-capacity failures preserve atomic external commitment and route retry through one Actor-owned Continuation without independent pending/retry state?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` §§6–9 owns Task atomicity, Temporary retry, scheduler and lifecycle; root integration documents own adapter composition; `docs/actors-resource-policy.specification.en.md` owns fail-closed admission.
- `Invariant`: No duplicate external commitment, one Actor-owned Continuation, one capped typed retry/wakeup path and explicit live/pending/fanout/queue bounds.
- `Reopen trigger`: Any independently persisted adapter retry/commitment state or unbounded failure queue requires owning-contract review.

## Context and Hypothesis

- `Reason`: EXP-0099 establishes continuation ownership inside Actors but does not independently decide whether existing adapters or ingress paths retain commitment/retry authority under backpressure.
- `Hypothesis`: Every in-scope failure either rolls back atomically, returns a typed failure to Actors, or remains in its existing bounded canonical queue without creating parallel execution authority.
- `Materiality`: Duplicate external effects or adapter-owned retry state can violate committed-prefix durability and exactly-once Task effects.

## Baseline and Candidates

The sole candidate is current EXP-0095 C1 composition. New commitment registries, phases or scheduler semantics are excluded.

## Controls

- `Controlled variables`: Current runtime/pallet source, configured bounds, transactional wrappers and typed failure taxonomy.
- `Changed variables`: None; this is an existing-path audit.
- `Confounders`: A provider's bounded transport queue is not Actor Continuation; an external failure code is not retry authority; successful ingress does not prove rollback.

## Benchmark Class, Workloads, and Criteria

- `Class`: Source/test ownership and rollback audit.
- `Workload`: DEX/Router market rejection, XCM/message delivery failure, observation fanout pressure, funding/resource admission failure, Ready/Waiting/Wakeup capacity and adapter-local bounded errors.
- `Metrics`: Pre/post state root or balances, typed failure, Actor cursor/attempt state, queue cardinality/bounds, retry pointer count and external effect count.
- `Acceptance`: Every category has an exact code owner and falsifier proving no partial/duplicate commitment and no independent retry authority.
- `Rejection`: Untracked external success before Actor rollback, duplicate queue/reference, adapter retry store, unbounded pending state or silent semantics change.

Source inspection finds no adapter-owned cursor, retry counter or Actor commitment registry. Bounded transport/fanout queues retain only their own delivery work; EXP-0099's Actor Run remains the sole process retry authority.

## Derived Metrics

Six existing categories map to canonical transactional or bounded-queue owners and zero independent Actor retry stores. The canonical route executes eight runtime and three package falsifiers under one source-identity guard.

## Statistical / Variance Notes

Deterministic rollback/ownership audit; provider liveness, latency and timing distributions are outside scope.

## Result

Current source/test ownership and the passing consolidated route support atomic effects and one Actor retry authority in every declared category.

## Interpretation

Transport and fanout queues own delivery continuation only, not Actor process continuation. Typed adapter failure becomes input to the one Actor Run transition; it does not authorize a parallel retry.

## Decision

Accepted. Existing backpressure paths fail atomically or retain work in their bounded owning queue, while Actor Run remains the sole process retry authority.

## Rejected Alternatives and Tradeoffs

- `Success-only tests`: Rejected because they cannot falsify partial commitment.
- `Transport queue as Actor retry`: Rejected unless current source proves shared authority, which would violate the governing contract.
- `New registry`: Excluded unless an existing path cannot satisfy atomicity with current owners.

## Validity

Establishes current source/test ownership and consolidated execution evidence by category. Does not establish provider liveness, untested future adapters or release acceptance.

## Follow-Up / Next Gradient

Proceed to G8 residual convergence and explicit production-constraint disposition.

## Architecture Impact

None; audit existing paths before considering new state or phases.
