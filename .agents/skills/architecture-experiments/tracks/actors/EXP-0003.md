## Decision Question

Which conforming Contract body geometry—one Step cell, two-Step chunk, four-Step chunk, or compact Step header plus external payload—best minimizes current-Step ProofSize and lifecycle Weight without making short Contracts pay for unused ceiling capacity?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` → `Hot/Cold Physical Contract`, `Complete Projection`, and `Active Execution State Geometry`.
- `Preserved invariants`: One semantic ordered Contract; exact bounded reconstruction; activation without cold body reads; execution loads only the current Step representation; stale/missing/overlapping fragments fail closed; atomic create/update/close; no mutable semantic mirror.
- `Reopen trigger`: Specification reopens only for demonstrated semantic defect or infeasibility beyond the relevant physical candidates. A losing candidate is rejected without changing semantics.

## Context and Hypothesis

- `Current architecture`: One `ActorContracts[actor_id]` value stores authored header fields and the complete bounded Step vector. Activation, scheduling, execution, lifecycle, and projection share that monolithic value.
- `Reason`: The 32-Step target and no-ceiling-tax contract require evidence that current-Step reads and short-Contract state do not inherit maximum body geometry.
- `Hypothesis`: One bounded fragmented representation can materially reduce current-Step ProofSize while retaining dispatchable maximum lifecycle operations and exact projection.
- `Materiality`: ProofSize, reads/writes, encoded state bytes, loaded-fragment count, and correctness postconditions are exact: any delta is material. A generated RefTime delta is material when its absolute relative delta exceeds `max(2%, 3 × pooled relative model standard error)` for the matched branch. A runtime-Wasm byte delta above 1% is material. Selection seeks the highest measured current-Step and lifecycle performance among candidates that preserve every hard invariant and production envelope; no arbitrary improvement quota may reject a real Pareto improvement.

## Benchmark Class, Workloads, and Criteria

- `Benchmark class`: FRAME lifecycle/current-Step benchmarks, retained-state encoding, matching production Wasm, and exact reconstruction/fault tests.
- `Workloads`: Short 1-Step, representative compact/mixed Contracts, maximum 8-Step baseline, and comparative 16/32-Step geometry where candidate construction permits.
- `Metrics`: Component-wise RefTime and ProofSize; database reads/writes; encoded persistent bytes; current-Step proof/read set; create/update/close/activate/projection Weight; Wasm size; exact semantic equivalence.
- `Statistical method`: Identical 50-step/20-repeat generated benchmarks across isolated candidate trees; retain model coefficient standard errors and remove no samples. Treat RefTime as equivalent only within `max(2%, 3 × pooled relative model standard error)`. Exact dimensions have no noise band.
- `Acceptance criteria`: Exact semantic and reconstruction parity; no cold unreached-body proof in matched one-Step execution; every maximum lifecycle call fits its production dispatch envelope component-wise; no unbounded scan; and selection from the conforming nondominated set by the release bottleneck. If no dimension is binding, prefer lower current-Step ProofSize, then lifecycle RefTime, persistent bytes, Wasm size, and implementation simplicity. A tradeoff is accepted only when its sacrificed dimension stays inside a predeclared bound and the gain improves the declared release target.
- `Rejection criteria`: Any semantic divergence, unbounded scan, stale fragment authority, non-dispatchable maximum lifecycle path, or undeclared component-wise regression.

## Result

C1 is component-wise worse than B0 at the current 1..=8 profile across every measured decision branch and retained-state footprint. No candidate decision is made at Measured status; causal interpretation and candidate pruning follow separately.

## Interpretation

- `C1 current profile`: C1 is strictly dominated by B0 at 1..=8 Steps. It adds a header read, one write per Step for lifecycle mutation, one read per Step for reconstruction, and 14.46×/21.79× retained bytes at one/eight Steps.
- `No Ceiling Tax`: B0 remains semantically unsuitable for the 32-Step target because its one monolithic maximum proof grows with the global body ceiling. C1 proves that naive fragmentation is not an acceptable cure; repeating body authority per Step converts ceiling tax into read, write, reconstruction, and persistent-state tax.
- `C2/C3`: Pure tail chunks can amortize lifecycle writes and authority bytes, but they retain the second current-path read and increase the loaded tail fragment above C1. Because C1 already loses current load and B0 lifecycle is constant, C2/C3 are not earned as the next candidate before a design removes the one-Step extra read.
- `C4`: External payload separation is a Step-shape question. It cannot repair C1's duplicated body authority or header-plus-cell read by itself and remains deferred to EXP-0004.
- `C5 gradient`: Inline exactly Step 0 in the hot header as its unique body owner, with lazy authority-bound tail fragments only when `step_count > 1`. A one-Step Actor then needs one storage read and no tail record, while later cursors retain lazy loading. This directly targets the 100 one-Step throughput objective and no-ceiling-tax invariant.

## Decision

Reject C1 as a production geometry for the current profile. Do not build C2/C3 merely to soften a design whose one-Step path is already dominated. Preserve B0 temporarily, remove C1 instrumentation after its successor is prepared, and route one earned C5 A/B candidate to a successor Experiment Record before implementation selection.

## Rejected Alternatives and Tradeoffs

| Candidate or shortcut | Decision | Evidence-backed reason |
| --- | --- | --- |
| C1 one-cell body | Rejected for production | Loses all measured branches and state footprint at 1..=8 Steps. |
| Build C2/C3 immediately | Rejected as next move | Fewer tail records cannot remove the extra header+fragment read for Step 0. |
| Keep B0 as 32-Step production geometry | Rejected as final design | Monolithic maximum proof violates the accepted no-ceiling-tax physical contract. |
| Move payloads first | Deferred to EXP-0004 | Payload shape does not resolve duplicated body authority or the extra Step-0 read. |

## Validity

- `Establishes`: C1's component-wise regression at 1..=8 Steps, rejection of naive per-Step fragmentation, and the earned inline-Step-0 successor gradient.
- `Does not establish`: C5 performance, tail fragment geometry, 16/32-Step dispatchability, Step-payload shape, or production acceptance.
- `Invalidation triggers`: Contract semantics, candidate family, workload geometry, benchmark method, runtime limits, Weight owners, toolchain, or Wasm builder changes.

## Follow-Up / Next Gradient

- Open one successor record for C5: hot header with uniquely owned inline Step 0 and lazy tail fragments.
- Freeze B0/C5 one-Step, later-cursor, lifecycle, reconstruction, and footprint controls before measuring; add a chunked tail only if measured tail lifecycle pressure earns it.
- Remove every C1 `Exp0003*` store/function and temporary profile after the successor harness can preserve the B0 baseline independently. Project build, tests, CI, release validation, and runtime behavior must not depend on this Skill or its private experiment lifecycle.
