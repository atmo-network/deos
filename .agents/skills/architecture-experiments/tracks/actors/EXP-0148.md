## Decision Question

Does retained `address_event_trigger_occurrence()` physically bound a legal maximum-Step User Actor with maximum source/asset filter whitelists, signed funding and balance-watch header for one matched source notification?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` §4.2 AddressEvent readiness and §7.7 Trigger fee ownership; `AGENTS.md` Actor Fee Boundaries.
- `Invariant`: One useful `pending_signal: false -> true` occurrence owns its Actor-specific matching/collection/placement; source publication and later Pipeline/Action effects have independent owners, and a latched duplicate does not charge again.
- `Reopen trigger`: The admitted filter/header bound, source notification path or Trigger fee boundary changes.

## Context and Hypothesis

- `Current architecture`: The retained AddressEvent benchmark uses `SourceFilter::Any`, `AssetFilter::Any` and one short Step. Runtime `lib.rs::trigger_weight_for_family` also uses this generated owner to compute the User useful-readiness Trigger fee. `notify_address_event` is the Actor-specific matched source path; source publication remains separate.
- `Reason`: EXP-0147 showed a large funded/watch User header can underbound another Trigger family; AddressEvent additionally admits maximum source/asset filters.
- `Hypothesis`: A fully admitted maximal filter/header Actor exceeds the retained AddressEvent unit in both independent Weight dimensions.
- `Materiality`: Underpricing either physical source notification or its economic useful-readiness fee risks incomplete admission/collection before coordinated release binding.

## Statistical / Variance Notes

RefTime base and three reads rise on the same Wasm; ProofSize excess is independent. The fixture varies several bounded fields, so it finds a legal counterexample rather than a marginal cost per field. It does not establish a universal maximum or fee vector identity.

### Benchmark Evidence Disposition

- `Benchmark Evidence Status`: Qualified selected source/fee-owner counterexample, not adopted coefficient.
- `Reassessment Trigger`: Source notification, filter bounds, header encoding, fee collection, benchmark source/Wasm or production Weight identity changes.
- `Compared Observation IDs`: Selected and matched output SHA-256 values under Environment.
- `Noise / Stability Evidence`: Same-Wasm RefTime base/read and deterministic ProofSize excess; no universal noise bound.
- `Current Authority`: Retained AddressEvent short-header generated owner underbounds one legal maximum-header User notification in complete RefTime and ProofSize.

## Result

Selected maximum-filter User AddressEvent measures `615,592,000 / 19,100 + 23 reads/6 writes`, versus retained `275,388,000 / 8,463 + 20 reads/6 writes`. Source publication, later Pipeline and Task effects remain outside this measured Actor-specific owner.

## Interpretation

The useful-readiness Trigger fee and Actor-specific notification Weight share this owner, while the ingress publisher pays its own source work. Rebinding just this generated owner without coordinating complete source selectors, production Wasm and cost vectors would be premature; no multiplication over unrelated Task/Trigger classes is needed to classify this selected underbound.

## Decision

Reject retained `address_event_trigger_occurrence()` as a complete physical bound for W1. Defer production coefficient and fee-vector rebinding until Detector/Placement closure.

## Validity

- `Establishes`: One ordinarily admitted User matched notification underbounds the retained source/fee owner in both dimensions.
- `Does not establish`: General maximum over every Actor class/mutability, filter, source or placement; production fee adequacy after regeneration; full-block resource headroom.
- `Known limitations`: One User Mutable Idle source/asset match, no previously latched cycle or different AssetKind-specific adapter branch.
- `Invalidation triggers`: Source/Weight or admitted-filter topology changes and invalidates the exact witness.
- `Residual qualitative insight`: Long admitted filter and header state can amplify an Actor-specific source fee/Weight without changing the publisher's own responsibility.
