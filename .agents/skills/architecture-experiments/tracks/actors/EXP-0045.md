### Pre-fission EXP-0029 lines 319–344

Let `S` be the admitted Step count, `L` the number of authored amount positions, `O` distinct typed Opening surfaces, `F` admission-time tracked funding assets, `A` current accumulator entries and `R` Run funding-snapshot entries. Let `p_i` count canonical timed-predicate occurrences in Step `i`, with Opening subset `o_i`. Counts describe one current Contract, not an arbitrary product of storage capacities.

| Current Task family | Amount positions per Step | Opening identity | LastFunding identity |
| --- | --- | --- | --- |
| AddLiquidity | 2 | PreservableAsset for each leg | Each leg asset |
| Transfer, SplitTransfer, Burn, SwapIn, RemoveLiquidity, Stake, DonateLiquidity | 1 | PreservableAsset of the resolved amount | Same asset; LP asset for RemoveLiquidity |
| Mint, SwapOut | 1 | TargetAsset | Target asset |
| Unstake | 1 | StakingShares of the position asset | Host receipt asset at admission |
| StopCycle | 0 | None | None |

`InputLimit`, SwapOut absolute input ceiling, minimum output values and SplitTransfer leg count add no amount positions. `Fixed`, `PercentageOfCurrent` and `AllAvailable` allocate neither Opening nor LastFunding entries. One amount position cannot select both frozen-source families. Same asset under different Opening variants remains a different surface; same typed surface deduplicates. Funding deduplicates by receipt/direct asset identity independently, so aliasing can lower a count but cannot increase it beyond authored positions.

| Domain | Source-derived necessary constraint | Qualification / executable owner |
| --- | --- | --- |
| Amount state | `O + F ≤ L ≤ 2S`; `A ≤ F`, `R ≤ F` | `execution.rs::opening_surfaces`, `lib.rs::derive_funding_tracked_assets`; certified ingress changes values and occupied subsets, never the tracked set |
| Concurrent funding | `A + R ≤ 2F`, with overlapping asset identities permitted | Opening snapshots and clears accumulation; later ingress accumulates for the next cycle; `suspended_cycle_freezes_its_funding_snapshot_and_preserves_new_accumulation` |
| Host storage | `S ≤ MaxContractSteps`, `F ≤ MaxFundingTrackedAssets` | Mock caps 12/10, reference caps 12/40; neither the 40-entry storage encoding nor a Weight parameter proves a reachable 40-source Contract |
| Lifecycle | Every non-no-op replacement rederives tracking, prunes accumulation and cancels the old Run | `update_contract_prunes_stale_funding_accumulators`; `prepare_reachable_update` first creates a real Run, refills nonempty accumulation, then replaces through the public call |
| Snapshot values | Accumulation and Run funding values are positive; Opening balances may be zero | Funding is certified ingress history; Opening is a balance observation. Payload commitment proves integrity of the encoded value, not its admission reachability |

For the reference 12/24/48 host, `O = 24` forces `F = A = R = 0`, while 48 Opening predicate results can coexist with those 24 amount surfaces. Thus 24/48/40 is storage-only and unreachable under the current Task algebra. The mock independent-asset two-leg constructor has `O + F = 24`, so its legal funding-boundary allocations are `O ≥ 14`; `reachable_update_allocation_boundaries_match_authored_contract` covers 14/10, 19/5 and 24/0 through admission, certified funding, Opening, refill and replacement, plus rejection of 13/11 before Actor publication. These are family/host witnesses, not a proof that every tuple satisfying the necessary inequalities is economically or resource-admissible.
