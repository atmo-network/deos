## Decision Question

Does the currently generated *successful* placed-pair Weight contain the actual late-fee rollback-plus-scalar work invoked under the same pair reservation, in both RefTime and ProofSize, on a matched benchmark Wasm? A selected result can falsify the bound but cannot establish a universal branch maximum.

## Governing Specification

- `Exact section`: `docs/actors-resource-policy.specification.en.md` §4 (maximum-before-mutation, actual Weight and rollback); `template/pallets/actors/docs/specification.en.md` ObservationCrossing useful Trigger fee and atomicity.
- `Invariant`: A genuine `InsufficientFee` during a multi-User batch may roll the batch back and retry scalar progress; already committed prefixes of other tasks are not compensated. Each useful Trigger fee is collected once; failed transactional work still consumes physical resources and cannot borrow Shared Economic.
- `Reopen trigger`: If the charged pair's safe maximum cannot include the complete bounded fallback without breaking minimum-family one-third Control, reopen the physical selection, not semantic rollback or Control ownership.

## Context and Hypothesis

- `Current architecture`: `service_crossing_transitions_resuming` admits `crossing_placed_pair_unit()` plus fault reserve, then calls `do_crossing_placed_batch_or_single_unit(2)` and settles only the selected pair branch. The generated pair and maximum batch benchmarks execute direct success without the outer fallback. The package test now places the underfunded User second, proves the pair was selected and that the funded first member's collection attempt rolls back before scalar retry; one sink fee commits.
- `Reason`: An independently live failure path may contain two attempted fee/authority traversals inside one branch reservation. RefTime and ProofSize cannot be inferred by subtracting or summing independently generated success outputs as a substitute for the exact atomic branch.
- `Hypothesis`: A same-Wasm late-fee fallback estimate exceeds the retained pair projection in at least one dimension. The selected result tests, but cannot exhaust, this hypothesis over other headers or later batch failures.
- `Materiality`: A concrete selected underbound triggers a complete branch selector; non-falsification retains the gate for other live failure orders, maximum headers, batch sizes, deadline competition and branch maxima.

## Result

Both benchmark extrinsics executed sequentially on the same compressed benchmark Wasm. The late-fee diagnostic calls the exact batch-or-single function with its second User depleted to the configured minimum after creation; the first User latches, the second does not. Its estimate is `8,903,539,000 / 162,782` including current RocksDB RefTime, below the retained pair owner `12,577,613,000 / 162,782` by `3,674,074,000 / 0`. The matched direct pair estimate is `12,455,528,000 / 162,782`. Production Weight and Wasm files were not changed.

## Interpretation

Two attempted collections do not imply the estimated ProofSize doubles: the generated estimate stays `162,782` for both. The diagnostic base RefTime increases but its writes fall from 86 to 49, so the runtime DB schedule dominates the complete charged estimate. These are selected two-User ordinary-header profiles, not domination over a larger cohort, maximum-header User, fee collector rejection, per-stop classification or full Prepass. Neither separate-generated subtraction nor an apparent identical proof estimate supplies a universal physical bound.

## Decision

Inconclusive for production selector closure; research result. The selected late-fee pair fallback does not falsify the retained pair owner, so stop this two-User fixture rather than sweep underfunded positions or repeat direct successes. Keep a complete failure-selector upper and competing mandatory/Service admission open; do not rebind production Weight/Wasm.
