## Decision Question

Does the selected current-state process/residence design compose without a known supported-domain safety or resource contradiction, and what exact implementation evidence must close each remaining hazard without claiming correctness for unbounded future host behavior?

## Governing Specification

- `Exact section`: `BACKLOG.md` N5.3; `template/pallets/actors/docs/specification.en.md` §2.3; the Current Hazard Closure Routes in `experiments.md`; EXP-0120–EXP-0133.
- `Invariant`: A selector may authorize execution only for the same current generation and validated effect domain; every wake, round, transfer, lifecycle and cleanup interleaving preserves one durable obligation or terminal authority, with custody independent and every refusal paid.
- `Reopen trigger`: One supported reference or independent-host path permits selector/executor domain divergence, stale-generation effect, lost wake, duplicate/skipped round turn, duplicate/absent residence, custody mutation, unowned refusal, unsupported event-only Park or reachable legacy authority.

## Context and Hypothesis

- `Current architecture`: Separate records selected the stable process, residence policy, carrier, round, dependency acknowledgment, transfer, lifecycle, cleanup, collateral, old-path cut and resource owners. Their pairwise decisions have not yet been composed against the complete current hazard ledger.
- `Reason`: Locally sound mechanisms can fail at boundaries: a callback can mutate selector inputs, a wake can race acknowledgment, a ring transfer can recapture a turn, cleanup can cross generations, and a host can promise notifications for a mutation domain it does not control.
- `Hypothesis`: Composition is sound when all authority is generation-bound, selector and executor share one typed domain, callback-visible state is revalidated before commit, acknowledgments cover only fixed revisions, residence changes linearize transactionally, rounds use immutable B markers, and incomplete host mutation domains retain deterministic timed review.
- `Materiality`: Freeze the exact supported-domain implications, hazards, refused cases and evidence gates. Runtime implementation, model checking, generated coefficients, integration tests and compile-time legacy absence remain N3–N5/N7 work.

## Measurements

### Core Implication Rules

```text
execute(g, d) => process.generation = g
             && process.status = Serving
             && selector_domain(d) = executor_domain(d)
             && current inputs are revalidated after callback-visible boundaries

ack(source, r) => evaluation covered r
               && every revision > r remains durably Pending or traversable

commit transfer(S, D) => D staged and affordable
                      && Process.residence linearizes once
                      && exact S release and cursor repair commit atomically
```

No callback return is itself authority to commit stale state. Effect settlement reports what executed; Control decides whether current state may consume that result. Transaction rollback restores the pre-transition residence and obligation, not custody already finalized by an independent ledger owner.

## Result

The selected mechanisms have no identified design-level contradiction when composed under the matrix. Every known applicable hazard retains an explicit invariant, obligation-preserving refusal and finite implementation falsifier. This is not runtime closure: all executable gates remain open until the selected architecture exists, generated owners bind it and adversarial suites pass.

## Interpretation

Soundness is conditional on declared host capabilities, not on optimism about callbacks or notifications. The generic pallet can promise event-only wake completeness only for a mutation domain the host proves closed. Else it must retain bounded timed review or reject that capability. Likewise, atomic storage rollback cannot undo an independently finalized ledger effect; scheduling must treat custody as final and make notification failure a paid local outcome.

## Decision

Accept Candidate A as the N5.3 design closure. Bind selector and executor to one typed current-generation domain; revalidate callback-visible authority; preserve revisions newer than the covered acknowledgment; linearize residence once; keep block B immutable; preserve custody across scheduling refusal; require presecured mandatory capacity; admit event-only Park only for certified closed host domains and otherwise retain timed review or reject support. N5.3 implementation closure remains open until every named executable gate passes with generated owners and no legacy authority.

## Rejected Alternatives and Tradeoffs

| Candidate | Decision | Evidence-backed reason |
| --- | --- | --- |
| Check once before callback | Rejected | Callback-visible state or generation can change before commit |
| Generation-blind stale cleanup | Rejected | Can delete or wake replacement state |
| Acknowledge latest observed revision after evaluation | Rejected | Can consume an occurrence not covered by the evaluated snapshot |
| Source-first residence movement | Rejected | Capacity failure can erase the only obligation |
| Mutable round length or served-prefix reset | Rejected | Allows duplicate, skipped, donated or recaptured turns |
| Roll back transfer when notification fails | Rejected | Conflates independent custody finality with scheduler capacity |
| Universal notification-only parking | Rejected | Generic hosts cannot prove every balance/spendability mutation route |
| Borrow ordinary capacity for mandatory cleanup | Rejected | Saturation can deadlock revocation and debt reduction |
| Keep old queue as exceptional fallback | Rejected | Reintroduces a second unpriced liveness authority |

The tradeoff is explicit timed-review cost for incomplete sources, stronger adapter contracts and a larger adversarial test matrix. These costs preserve generic-host honesty and make safety claims finite and falsifiable.
