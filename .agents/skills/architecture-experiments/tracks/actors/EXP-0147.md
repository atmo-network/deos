## Decision Question

Does the retained `observation_change_trigger_occurrence()` Weight used to price one useful-readiness Trigger dominate a selected ordinarily admitted maximum-Step, maximum signed-funding/watch User header, independently of its complete fanout page's actual execution Weight?

## Governing Specification

- `Exact section`: `template/pallets/actors/docs/specification.en.md` §7.7 Trigger fee and §4.2 ObservationChange fanout; `AGENTS.md` Actor Fee Boundaries and Trigger Latching.
- `Invariant`: Charge only one `false -> true` useful Trigger transition for its Actor-specific owner; fanout physically executes it inside the page and must not add a separate occurrence Weight. Trigger fee sufficiency and page admission are distinct resource decisions.
- `Reopen trigger`: Fee owner equation or header admission/encoding changes, or a future separately executed Trigger path replaces canonical page work.

## Context and Hypothesis

- `Current architecture`: `lib.rs::trigger_weight_for_family` selects generated `observation_change_trigger_occurrence()` for User fee pricing inside `reactions.rs::process_observation_change_occurrence`. The retained benchmark has a short one-Step header. Ordinary fanout calls the same process through `signal_observation_subscriber_ordinary`; the direct `signal_observation_subscriber` wrapper used here invokes the same body, but its only ordinary production caller is an unreachable stored `Terminal` branch (EXP-0146).
- `Reason`: EXP-0143 found a legal full page of maximum User headers far above the retained ordinary page Weight. That does not itself quantify the separate per-useful-readiness fee owner.
- `Hypothesis`: One maximum funded/watch header loads more state than the retained Trigger fee coefficient covers in both resource dimensions.
- `Materiality`: Underpricing this owner undercharges each useful-readiness transition even if page admission is fixed; multiplying its diagnostic Weight onto the already complete page would instead double-charge execution.

## Result

A maximum signed-funding/watch User header costs `537,647,000 / 23,481 + 23 reads/7 writes` for one canonical ObservationChange occurrence versus retained fee owner `217,559,000 / 9,068 + 20 reads/7 writes`. The two excess dimensions remain selected, not universal maxima.

## Interpretation

The physical execution of each useful occurrence is inside the fanout page of EXP-0143; this separate measurement calibrates the Trigger fee and cost-vector identity for one Actor, not a second page charge. Trigger fee collection is one per `false -> true` latch, and retry/failure does not create a second paid activation. Do not refresh runtime vectors against stale generated Weight/Wasm just to clear assurance.

## Decision

Reject retained short-header `observation_change_trigger_occurrence` as a physical upper bound for W1. Defer fee owner, page, family admission, production Wasm and exact cost vectors to coordinated generation after all four Weight-owner groups close.

| Add the selected Trigger Weight 64 times to measured fanout page | Rejected | Actor-specific Trigger work is already physically executed within the page; that is double counting. |
| Treat direct signal wrapper as an independently scheduled live source | Rejected | EXP-0146 proves its ordinary caller is only the non-live stored terminal branch; the underlying process remains live inside ordinary fanout. |

## Validity

- `Establishes`: One ordinarily admitted maximum-header User latching transition underbounds retained fee owner in both dimensions.
- `Does not establish`: Universal header maximum, every Trigger family, production fee vector, complete page admission or a separate physical charge.
- `Known limitations`: One selected User/Idle header and dense subscriber topology; no System exemption, Immutable, latched coalescence or full temporal/predicate cross-product.
- `Invalidation triggers`: Changed fee collection or placement semantics, changed header bounds or source/Wasms invalidating this comparison.
- `Residual qualitative insight`: A page can be substantially undercharged physically while its nested per-Actor economic Trigger fee is independently undercalibrated; correcting either does not license duplicate Weight accounting.
