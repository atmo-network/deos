## Decision Question

What is the smallest monotone registration and acknowledgment protocol that prevents one current-generation activation check from losing a dependency update before, during, or after negative evaluation, subscription replacement, shared-feed traversal, callback execution, acknowledgment, or transaction rollback?

## Governing Specification

- `Exact section`: `BACKLOG.md` lost-wakeup invariant and N3.7; `template/pallets/actors/docs/specification.en.md` §2.3 current-state residence.
- `Invariant`: Park may acknowledge only exact dependency revisions covered by one committed current evaluation; every later or concurrent relevant mutation remains represented by source revision inequality, an unadvanced dirty cursor, or one generation-bound Pending obligation.
- `Reopen trigger`: A supported callback or mutation can make a parked condition applicable without changing a watched nonwrapping revision, invalidating a timed deadline, or leaving durable Pending work.

## Context and Hypothesis

- `Current architecture`: EXP-0121 selects one generation-bound Pending check, EXP-0123 selects exact revisions or timed review, EXP-0125 selects generation-bound reverse handles, and EXP-0126 selects immutable block rounds. Exact registration, traversal, and acknowledgment interleavings remain open.
- `Reason`: Clearing a dirty flag or replacing subscriptions after evaluation can erase an update that occurred against the old registration or during bounded shared traversal.
- `Hypothesis`: Give every event-complete dependency key one checked nonwrapping revision and serialize negative check, destination registration, revision validation, certificate acknowledgment, and old-registration removal in one transaction. Shared invalidation traverses one fixed target revision and advances only after stale proof or durable obligation transfer; newer revisions remain as a later target.
- `Materiality`: Freeze one exact causal protocol and its finite interleaving falsifiers. Concrete capacity reservation belongs to N3.8 and encoded widths/Weight belong to N5.2.

## Measurements

### Selected State

| Owner | State | Rule |
| --- | --- | --- |
| Dependency key | `revision`, `scan_target`, `scan_cursor`, `exhausted` | Every relevant mutation checked-increments `revision`; an active traversal keeps its fixed target while a newer revision remains distinguishable; exhaustion is sticky and never compares equal |
| Reverse registration | exact key → bounded generation/plan-bound subscriber pages | A handle identifies the exact registration generation; replacement cannot mutate an old handle into authority for a new generation or plan |
| Actor process | Park Certificate acknowledged key revisions, plan revision, generation, optional review deadline | Park is valid only when all committed registrations and acknowledged revisions match the evaluation snapshots |
| Actor residence | one Pending/Live/Sleep/Park owner | Source progress may advance only after stale proof or destination ownership is durably secured |

### Negative Check and Subscription Replacement

One transaction performs this order:

1. Resolve exact Actor generation and accepted plan revision. Capture current revisions for the complete conservative dependency set and evaluate the current plan from authoritative state.
2. If applicable, do not acknowledge negative evidence; atomically secure Pending/Live according to residence policy.
3. If false, install or validate every new exact registration and required timed-review deadline while old registrations remain valid.
4. Re-read generation, plan revision, every watched source revision, and all time boundaries after registration and all synchronous callbacks. If any differs, commit or retain one Pending obligation instead of Park; the mismatched revisions are not acknowledged.
5. Only when all values still match, write the Park Certificate with exactly the captured revisions, commit Park, then remove obsolete old registrations in the same transaction.
6. Any error or callback failure rolls back certificate, registration, residence, and acknowledgment together. No source or traversal cursor may observe success from a rolled-back transfer.

The protocol does not require an unbounded retry loop. One mismatch coalesces to Pending; the later current check evaluates the newest state. If old and new sets overlap, exact generation-bound handles make registration idempotent. Plan/generation replacement directly revokes the old certificate and cannot inherit its acknowledgments.

### Source Mutation and Shared Traversal

A relevant event-complete source mutation checked-increments `revision = R`. If no traversal is active, it sets `scan_target = R` and initializes the bounded subscriber-page cursor. If one is active for `T < R`, it leaves that target/cursor intact and retains `revision = R`; after T completes, `revision > T` initializes the next traversal from the then-current subscriber topology. Repeated updates coalesce to the greatest current revision, not one event per update.

For each exact subscriber reference encountered under target T:

```text
load exact registration + generation + plan
→ stale/removed/not subscribed to T: prove no authority and advance
→ current and already Pending/Live/busy: coalesce durably and advance
→ current Park/Sleep requiring check: secure generation-bound Pending first
→ only after committed stale proof or destination authority: advance cursor
```

A destination-full or resource refusal leaves the source cursor on that subscriber and leaves `scan_target` unchanged. N3.8 owns how destination capacity is reserved, but it may not weaken this retention rule. Completion of target T clears only T after the final page; if `revision > T`, a new traversal is initialized rather than clearing the source dirty state.

Topology changes are monotone against the same rule. Removal/replacement invalidates the exact old handle and directly creates/coalesces Pending for the affected current generation before releasing any obligation. A newly added subscriber evaluates current state during registration and acknowledges the then-current revision transactionally; it does not depend on whether a traversal cursor has already passed its page. Therefore behind-cursor insertion cannot be skipped, and deleted old references need only stale proof.

### Interleaving Matrix

| Interleaving | Required committed result |
| --- | --- |
| Update before snapshot | Evaluation reads the new revision/current state and may acknowledge it only after validation |
| Update after snapshot but before/during registration or evaluation callback | Final validation differs; Park is forbidden and Pending remains |
| Update after final validation/ack commit | Source revision exceeds certificate acknowledgment and traversal/Pending discovers it |
| Update during partial traversal | Current target/cursor remains; newer revision becomes the next coalesced target |
| Subscriber added behind cursor | Registration transaction evaluates and acknowledges current revision or leaves Pending; old traversal position is irrelevant |
| Subscriber removed/replaced ahead or behind cursor | Exact old handle becomes stale; current generation receives direct Pending when required; traversal may advance only after that proof/transfer |
| Nested callback mutates a watched source | Callback revision write shares the transaction overlay and is seen by final validation; callback failure rolls back both sides |
| Transaction rolls back after destination write | Registration, certificate, destination and source progress all roll back; source remains dirty/unadvanced |
| Old generation reference arrives | Exact generation mismatch proves stale; it cannot wake or acknowledge the replacement |
| Timed fallback becomes due during check | Final boundary validation forbids indefinite Park; Sleep/Pending retains the due review |

### Revision Exhaustion

Revision increment uses checked arithmetic. On failure the source enters sticky `exhausted` recovery authority in the same transaction; it never wraps and no certificate may treat equality as freshness. Existing traversal/cursor remains retained, all event-only Park certificates for that key are invalid until bounded recovery completes, and new checks must remain Pending or use an already-authorized deterministic review deadline. A runtime upgrade/fresh-genesis recovery may widen/reset the domain only under an explicit bounded sweep proving every affected registration has been invalidated. N3.8 owns capacity-safe realization of that sweep; ordinary execution fails closed.

## Result

Candidate A leaves no clear-dirty gap. Before commit, final validation catches every watched mutation represented in the transaction overlay; after commit, revision inequality and retained dirty traversal represent it. Shared traversal never overwrites an older target with a newer one, and cursor progress is conditional on stale proof or a committed destination obligation. Registration changes do not rely on cursor position.

## Interpretation

The acknowledgment unit is a revision-covered negative evaluation, not a notification and not a cleared boolean. Serial FRAME execution and transactional rollback are sufficient when every relevant callback writes the authoritative revision before returning. A fixed traversal target separates “members owed for T” from “a newer source state exists”; generation-bound direct registration closes add/remove races without snapshotting subscriber history.

## Decision

Accept Candidate A as a research result and sole N3.7 causal protocol: checked nonwrapping source revisions; transactional evaluate/install/revalidate/acknowledge/remove-old ordering; revision-fixed paged traversal whose cursor advances only after stale proof or durable transfer; and sticky fail-closed exhaustion. Stop after the finite W1–W3 interleaving matrix. N3.8 must realize destination admission and rollback atomically rather than invent another acknowledgment channel.

## Rejected Alternatives and Tradeoffs

| Candidate | Decision | Evidence-backed reason |
| --- | --- | --- |
| Clear dirty before or after evaluation without revision compare | Rejected | An update in the clear/check gap can disappear |
| Remove old subscriptions before installing new | Rejected | Replacement creates a window with no invalidation owner |
| Overwrite active traversal target with latest revision | Rejected | Cursor position for the old topology/revision becomes ambiguous and may skip promised members |
| Restart traversal from page zero on every update | Rejected | A hot source can prevent bounded completion indefinitely |
| Advance cursor when Pending destination is full | Rejected | Source acknowledgment would outlive the only durable obligation |
| Wrapping revision counter | Rejected | Equality can misclassify a newer state as acknowledged |
| Preserve one event per source mutation | Rejected | Current-state semantics need one latest obligation, not history-proportional storage |
| Treat callback execution as outside the acknowledgment transaction | Rejected | Partial callback success can expose state not covered by the certificate |

The accepted tradeoff is one source revision write per relevant event-complete mutation, a final bounded revision reread, and potentially multiple coalesced traversals when updates continue during a scan. This cost buys causal closure; N5.2 must establish its resource viability.

## Validity

- `Establishes`: Exact check/register/validate/ack ordering, subscription replacement rule, fixed-target traversal, cursor advancement condition, callback/rollback behavior, generation isolation, timed-boundary validation, and nonwrapping exhaustion semantics.
- `Does not establish`: Concrete storage layout/width, destination-capacity reservation, host balance notification completeness, production Weight, throughput, or runtime implementation correctness.
- `Known limitations`: Only host-declared event-complete keys may use event-only Park; generic balance/spendability retains EXP-0123 timed review.
- `Invalidation triggers`: A supported mutation bypasses revision ownership, implementation advances before durable transfer, callback effects escape rollback, or fixed-target traversal cannot fit bounded state.
- `Residual qualitative insight`: Never clear work; acknowledge only an exact observation while preserving every newer revision.
