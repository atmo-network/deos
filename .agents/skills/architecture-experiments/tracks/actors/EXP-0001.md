## Decision Question

Does the current architecture sustain the 0.7.24 target of 100 completed one-Step Actor cycles per block while retaining bounded, uniform, starvation-free service as active population rises to 10,000?

## Governing Specification

- `Target`: `BACKLOG.md` → Quantitative Release Contract and S13 Reactive Transfer 10k profile.
- `Preserved invariants`: `template/pallets/actors/docs/specification.en.md` requires User/System class-neutral strict FIFO, temporal readiness, cutoff, bounded work, and Weight-metered execution.
- `Reopen trigger`: Any proposed speedup that changes FIFO, deterministic service, causal timing, atomicity, or economic effect semantics is a semantic proposal, not a candidate optimization.

## Context and Hypothesis

- `Current architecture`: Active Actors hold hot scheduler state. Cadence-1 obligations enter bounded wakeup buckets, materialize into one monotonic paged FIFO, and execute through `on_initialize` plus `on_idle`. Queue service loads canonical Actor state, validates the live ticket and same-block guard, reserves branch Weight, consumes the paged head transactionally, executes one cycle, and schedules next work. Runtime configuration sets `MaxExecutionsPerBlock = 1,000`, queue page size `64`, and queue capacity `10,000`; Weight remains the primary admission bound.
- `Workload`: Mutable System Actors, each with one cadence-1 Step whose task is `StopCycle`, no precondition, persistent contract, and 10,000 native units. Genesis System Actors are removed. Every synthetic block runs Actors `on_initialize` then `on_idle(Weight::MAX)`.
- `Hypothesis`: The current physical scheduler can reach at least 100 completed cycles/block with stable service in this cheaper-than-Transfer one-Step profile.
- `Materiality`: The release target is 100 completed cycles/block. Stability requires zero failed Steps, no starvation, and cycle-count spread at most 4.

## Statistical / Variance Notes

- Five native wall-clock samples were retained without outlier removal. CV ranges from 1.26% to 3.14%.
- Cycle counts were identical across runs, while host timing remains diagnostic because CPU scaling and unrelated host load were not pinned.
- The occupancy profile is deterministic behavioral evidence, not a production timing sample.

## Result

The current baseline completes about 41 cycles/block at 48–100 Actors, 39.60 at 1,000, and 32.24 at 10,000. The 10,000-Actor rate is 67.76% below the 100 cycles/block release target. Service remained starvation-free over 418 blocks and substantially inside the allowed fairness spread, but the queue and wakeup frontier approached full population occupancy. Native wall-clock variability was low across five samples, while mean host cost rose from 3.84 to 10.01 ms/block.

## Interpretation

- `Measurement`: The deterministic cycle counter falsifies the target hypothesis even for a no-effect StopCycle workload; the more expensive reactive Transfer target cannot be inferred to perform better.
- `Stability`: Relative actor service is uniform at 10,000 population (spread 1), and measured cycle counts are exactly repeatable. This is strong behavioral evidence for bounded fairness, not production timing evidence.
- `Scaling`: Throughput loses about 21.4% from the 48-Actor rate to the 10,000-Actor rate while queue/wakeup occupancy becomes dense. Population-sensitive control/materialization and queue pressure are plausible contributors.
- `Binding dimension`: Not established. This native profile combines wakeup, materialization, queue, canonical-state, execution, and rescheduling work and does not decompose RefTime, ProofSize, reads, or writes.
- `Pareto class`: Not applicable; no alternative architecture was measured.

## Decision

Reject the hypothesis that the current physical baseline already meets 100 completed cycles/block. Preserve this tree as the exact pre-optimization baseline. Do not change semantics or select a candidate from this experiment alone.

## Validity

- `Establishes`: DEOS 0.7.23 native deterministic throughput and fairness for cadence-1 System Actors executing one StopCycle Step under the recorded horizons.
- `Does not establish`: Reactive detection throughput, Transfer/economic effect throughput, production-Wasm capacity, six-second block safety, User contention, RefTime/ProofSize attribution, or database behavior.
- `Invalidation triggers`: Scheduler/wakeup/FIFO/hot-state layout, Weight implementation, runtime limits, Step semantics, workload harness, compiler, or benchmark methodology changes.
- `Residual insight`: Preserve exact cycle-rate and occupancy geometry as the comparison point even after numeric authority becomes stale.

- `Eliminated hypotheses`: Current baseline already meets target; fairness imbalance is the primary observed failure; the count ceiling predicts throughput.
