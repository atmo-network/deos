## Context and Hypothesis

This Leaf owns the complete Run-state mutation primitive used by composed Running and Suspended fallbacks. The production Step core writes exactly one successor: Running progress, Suspended retry, or Idle completion/failure. The later placement selector separately publishes Queue, Waiting, or Unsignaled authority. Direct `scheduler_inner_*` profiles may already include both operations; only unmatched phase/outcome/placement cells may use a separately measured composition.

The initial hypothesis was that the existing `run_progress`, `run_suspend`, and `run_complete` fixture family represented that composable mutation boundary. Exact generated storage traces falsified it. The fixtures call benchmark-only `write_run_state` from a retained Ready primary: progress and suspension also maintain a Block wakeup reference, while completion consumes Ready and publishes Unsignaled. Production committed-Step execution instead mutates `ActorRunStateStore` in the core and publishes the successor only afterward through `schedule_next_work_with_authority`. The measured values remain useful admitted-payload and overlap classifiers, but are not production Run coefficients and cannot be repaired by subtraction.

## Benchmark Class, Workloads, and Criteria

Acceptance requires a call-path matrix and same-Wasm measurements showing that exactly one owner covers each committed successor and destination handoff without reusing any `write_run_state` cross-boundary work.

| Successor class | Reachable destination classes after consumed Ready source | Required ownership |
| --- | --- | --- |
| Continued | Queue normally; Waiting on Ready-capacity fallback | Direct inclusive profile where matched; otherwise one exact complete consumed-source successor profile |
| Suspended | Waiting normally; Queue for an exact next-block retry inside the snapshotted cutoff | Direct inclusive profile where matched; otherwise one exact complete consumed-source successor profile |
| Completed or Failed | Unsignaled with no deferred authority; Queue/Waiting for a retained signal or terminal deadline | Direct inclusive/terminal owner where matched; otherwise one exact complete consumed-source successor profile |

The smallest falsifier is one legal branch where selected accounting omits or duplicates Run head/payload, primary publication, Waiting reference/heap work or applicable hold reconciliation. A fixture that begins from a retained primary after production already consumed it is itself a boundary falsifier.

## Result

The successor partition and admitted classifier are frozen. Dense Running-capable geometry is admitted through `S=3` and rejected independently at every `S=4..12`, while an ordinary low-capture `S=12` Contract reaches real Running authority. Exact traces falsify the categorical body's claimed composability. Corrected complete-path measurements establish Continued→Wakeup, both first-retry Suspended→Queue/Wakeup and terminal Completed/Failed→Unsignaled successors from consumed Ready authority. The low-capture Continued→Wakeup profile component-wise contains the measured dense alternative under the pinned DB schedule, closing the finite Run successor envelope.

## Interpretation
