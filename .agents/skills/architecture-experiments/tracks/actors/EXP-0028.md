## Decision Question

Does every production Actor Control phase have exactly one sound Weight owner, with no omission and no double charge?

## Governing Specification

- `Owners`: `template/pallets/actors/docs/specification.en.md` (sole ownership, lifecycle/Trigger/Pipeline/Action semantics, placement and scheduler); `docs/actors-resource-policy.specification.en.md` (component-wise admission/actual settlement, equal-thirds block policy); `docs/actors-performance-assurance.specification.en.md` (evidence and target).
- `Frozen physical input`: [EXP-0025](./EXP-0025.md) C1 Architecture Freeze. No change to FIFO, ticket chronology, Q1, causal floor, primary/reference ontology, source/successor atomicity or sole execution owner.
- `Semantic oracle`: A0 SHA-256 `8746e423168309975e509be91e4eb06fdf0eb0b43369d75f1ee62202a4341678` remains frozen; use only for relevant semantic equivalence, never as a Weight oracle.
- `Scope`:

- Own Trigger/Pipeline/Action control ownership, Action fee-collection Control cost, invocation events and User state-hold work.
- Own source consumption, successor publication, cleanup, lifecycle terminal work, Waiting placement/removal and independent Cadenced rearm phase boundaries.
- Distinguish semantically required User/System differences, actual versus maximum control settlement and no-double-charge.
- Keep four separate columns: semantic owner, physical storage owner, Weight owner and monetary fee owner. A semantic operation may touch several stores but has one complete charging boundary; storage ownership alone does not establish Weight coverage.

- `Evidence class`: Call-path ownership audit, legal native witnesses and production-Wasm FRAME branch evidence.

| Action attempt | Opening/Running/Suspended; success/skip/permanent/Temporary; StopCycle | Collection Control versus effect Weight and monetary fee |
| Source/successor | Ready consume, Unsignaled/Ready/Waiting destination, capacity fallback | One physical publication owner and correct actual selector |
| Temporal/lifecycle | Cadenced rearm, reference replacement, terminal/close/cancel, cleanup | No omitted or double-counted heap, state-hold or lifecycle work |

Every production call path maps to one charged owner; reservations dominate valid actuals component-wise; cross-phase shared work is included exactly once.
- `Rejection criteria`: Any uncovered branch, double charge, mismatched actual selector or collection-funded base undercount; classification by Task name alone is insufficient.
